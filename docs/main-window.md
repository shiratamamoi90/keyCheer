# 要件: メインウィンドウの開閉(キャラクター未作成時の自動表示 + トレイからの開閉)

キャラクターが未作成のとき、起動時にメインウィンドウ(将来キャラ作成 UI を載せる場所)を自動表示する。
キャラクター作成済み、または自動表示をユーザーがスキップ済みのときは自動表示しない。
トレイから手動でも開閉(トグル)できる。ウィンドウを閉じても常駐は継続する(プロセスは終了しない)。

前半の要件は「いつ表示/非表示になるか」というライフサイクル(論点 0018)、後半の要件は
メインウィンドウの画面の分け方と各画面でできること(論点 0033)。
フォームの入力と保存は `docs/character-creation.md`、生成は `docs/pool-generation.md`、
使用中のキャラクターの切り替えは `docs/character-selection.md` が正本。画面の見た目・レイアウトは仕様化しない。

`hasCharacter` の判定・`onboarding.skipMainWindowAutoShow` のデータ契約は `docs/data-model.md` 参照。
下の `hasCharacter(character)` は、論点 0032 以降「`characters` が 1 件以上」を指す。

### S0018_01 キャラクター未作成なら起動時にメインウィンドウを表示する

- GIVEN `hasCharacter(character) === false` かつ `onboarding.skipMainWindowAutoShow === false`
- WHEN アプリを起動する
- THEN メインウィンドウが自動的に表示される

### S0018_02 キャラクター作成済みなら起動時にメインウィンドウを表示しない

- GIVEN `hasCharacter(character) === true`
- WHEN アプリを起動する
- THEN メインウィンドウは生成されるが非表示のまま(トレイ操作でのみ表示される)

### S0018_03 スキップ済みなら未作成でも起動時に表示しない

- GIVEN `hasCharacter(character) === false` かつ `onboarding.skipMainWindowAutoShow === true`
- WHEN アプリを起動する
- THEN メインウィンドウは生成されるが自動表示しない(トレイからは引き続き開ける)

### S0018_04 トレイクリックで表示/非表示をトグルする

- GIVEN メインウィンドウが非表示状態
- WHEN トレイの「KeyCheer を開く」をクリックする
- THEN メインウィンドウが表示され、フォーカスされる
- GIVEN メインウィンドウが表示中に同操作を行う
- WHEN トレイをクリックする
- THEN 非表示になる(hide。ダイアログは経由しない)

### S0018_05 作成済みなら閉じてもダイアログを出さない

- GIVEN `hasCharacter(character) === true` の状態でメインウィンドウが表示中
- WHEN 閉じるボタン(×)を押す
- THEN 確認ダイアログを出さず、即座に hide する(`app.quit()` は呼ばれない)

### S0018_06 未作成のまま閉じるとダイアログが出る

- GIVEN `hasCharacter(character) === false` の状態でメインウィンドウが表示中
- WHEN 閉じるボタン(×)を押す
- THEN 「次回から自動表示しない」チェックボックス付きの確認ダイアログを表示する
  (`close` イベントの既定動作を止めてから非同期で確認する)

### S0018_07 ダイアログの選択でスキップフラグが決まる

- GIVEN 上記ダイアログが表示されている
- WHEN チェックボックスを**チェックせず** OK を選ぶ
- THEN ウィンドウは hide され、`onboarding.skipMainWindowAutoShow` は変更しない
- GIVEN 上記ダイアログが表示されている
- WHEN チェックボックスを**チェックして** OK を選ぶ
- THEN ウィンドウは hide され、`onboarding.skipMainWindowAutoShow` を `true` として永続化する

### S0018_08 スキップ済みでもトレイからは開ける

- GIVEN `onboarding.skipMainWindowAutoShow === true` かつ `hasCharacter(character) === false`
- WHEN トレイの「KeyCheer を開く」をクリックする
- THEN メインウィンドウが表示される(スキップは自動表示のみを抑制し、手動オープンには影響しない)

### S0018_09 重複表示の防止 [境界]

- GIVEN メインウィンドウの表示要求(起動時自動表示・トレイクリック)が短時間に重複する
- WHEN 2 回目以降の表示要求が発生する
- THEN 新しいウィンドウを二重生成せず、既存の 1 つを表示・フォーカスするだけに留める

### S0018_10 メインウィンドウの読み込みに失敗した場合 [異常系]

- GIVEN メインウィンドウ用 HTML の読み込みに失敗する
- WHEN 起動時の自動表示 or トレイクリックが発生する
- THEN アプリは落ちず、発動経路(キー押下 → ポップアップ)は影響を受けない。
  main 側にエラーログを残すのみとする

### S0018_11 メインウィンドウは発動経路と独立している [不変条件]

- GIVEN メインウィンドウの表示/非表示状態(任意)
- WHEN キー押下がトリガー条件を満たす
- THEN メインウィンドウの状態に関係なくポップアップが発動する(相互に依存しない)

### S0018_12 メインウィンドウの renderer は providers を import しない [不変条件]

- GIVEN メインウィンドウ用 preload / renderer のソース
- WHEN import を検査する
- THEN `src/agent/*`・`src/core/providers/*` を import しない(ESLint no-restricted-imports で機械的に検査)

## 要件: メインウィンドウの画面(論点 0033)

メインウィンドウを「キャラクター」「切り替え」「設定」の 3 つの画面に分け、タブでいつでも行き来できる。
キャラクター画面は保存と生成をまとめた画面で、キャラクターの保存・編集・削除と生成を行う(論点 0061)。

> S0033_01 / S0033_09 / S0050_02 は論点 0061 で欠番。
「プールのある」は、そのキャラクターの `pool.json` を読み込めることを指す(`docs/data-model.md`)。

### S0061_01 3 つの画面をタブでいつでも切り替えられる

- GIVEN メインウィンドウが表示中(どの画面を開いていても、生成中でも)
- WHEN キャラクター・切り替え・設定のいずれかのタブを選ぶ
- THEN その画面に切り替わる。保存の画面・生成の画面というタブは**無い**
### S0033_02 キャラクターが 0 件ならキャラクター画面を最初に出す

- GIVEN `characters` が空
- WHEN メインウィンドウを非表示から表示にする(起動時の自動表示・トレイ)
- THEN キャラクター画面を出す

### S0033_03 プールのあるキャラクターがあれば切り替え画面を最初に出す

- GIVEN プールのあるキャラクターが 1 件以上
- WHEN メインウィンドウを非表示から表示にする
- THEN 切り替え画面を出す

### S0033_04 保存済みでもプールのあるものが無ければキャラクター画面を最初に出す [境界]

- GIVEN `characters` が 1 件以上で、プールのあるキャラクターが 0 件
- WHEN メインウィンドウを非表示から表示にする
- THEN キャラクター画面を出す

### S0033_05 表示中のウィンドウは開いている画面を変えない [否定]

- GIVEN メインウィンドウが表示中で、利用者が設定画面を開いている
- WHEN 起動時の自動表示やトレイからの表示要求が重なる(S0018_09)、または生成が完了する
- THEN 開いている画面は**変わらない**(最初の画面を決めるのは非表示から表示にしたときだけ)

### S0033_06 生成中にほかの画面へ移っても生成は続く [否定]

- GIVEN キャラクター C の生成が実行中で、キャラクター画面を開いている
- WHEN 別の画面へ移る、またはキャラクター画面へ戻る
- THEN C の生成は中断も再開始も**されない**。キャラクター画面に戻ると、その時点の進捗を出す

### S0033_07 生成中はほかの画面でもキャラクタータブに「生成中」と示す

- GIVEN 生成が実行中
- WHEN 切り替え・設定のいずれかの画面を開いている
- THEN キャラクタータブに生成中であることを示す。生成が終わる(完了・中断・失敗)と示すのをやめる

### S0033_08 進捗と中断はキャラクター画面だけに出す [否定]

- GIVEN 生成が実行中
- WHEN 切り替え・設定のいずれかの画面を開いている
- THEN 進捗の詳細と中断の操作はその画面に**出さない**(中断はキャラクター画面から行う。S0020_06)

### S0061_02 保存済みで入力が保存した内容と同じなら生成ボタンを押せる

- GIVEN キャラクター画面で保存済みのキャラクター C を選んでいて、入力(名前・性格・話者)が保存した内容と同じ。生成は実行中でない
- WHEN 入力の枠の生成ボタンを押す
- THEN C の生成を始める(作り直しになるときは S0038_07 の確認を先に出す)

### S0061_03 新規の入力では生成ボタンを押せない [否定]

- GIVEN キャラクター画面で「新しく作る」を選んでいる(保存していない入力がある、または空)
- WHEN 画面を見る
- THEN 生成ボタンは押せない形で出し、生成は**始まらない**。先に保存するよう示す

### S0061_04 保存した内容から書き換えている間は生成ボタンを押せない [否定]

- GIVEN キャラクター画面で保存済みの C を選び、名前・性格・話者のどれかを書き換えて、まだ保存していない
- WHEN 画面を見る
- THEN 生成ボタンは押せない形で出し、生成は**始まらない**(書き換える前の内容で生成しない)。保存すると押せるようになる

### S0061_05 生成の進捗と結果を入力の枠の下に出す

- GIVEN キャラクター画面で C の生成を始めた
- WHEN 生成が進む / 完了する / 失敗する / 中断する
- THEN 入力の枠の下に、進捗と中断の操作を出す。終わったら結果を出す:完了なら成功の旨と画像の結果(作れなかった画像があればその理由)と C の 3 枚(S0050_01 と同じ出し方)、失敗なら理由、中断ならその旨

### S0061_06 進捗と結果には生成しているキャラクターの名前を示す [境界]

- GIVEN C の生成が実行中、または C の生成の結果を出している
- WHEN キャラクター画面の一覧で別のキャラクター D を選ぶ
- THEN 入力の枠は D の内容になり、進捗と結果は C のものであると名前で分かるように示す。D の生成が始まったようには**見せない**
### S0033_10 切り替え画面にプールの無いキャラクターを出さない [否定]

- GIVEN プールのあるキャラクター D と、プールの無いキャラクター E がある
- WHEN 切り替え画面を開く
- THEN D は一覧に出し、E は**出さない**。使用中のキャラクターがあれば、それと分かるように示す

### S0033_11 生成中で前回のプールがあるものは選べない形で出す [境界]

- GIVEN キャラクター C の生成が実行中で、C に前回のプールがある
- WHEN 切り替え画面を開く
- THEN C を一覧に出すが選べない形にし、生成中である旨を示す(S0032_13)。C が使用中ならそれも示す

### S0033_12 プールのあるキャラクターが無ければ切り替え画面でそう示す [境界]

- GIVEN プールのあるキャラクターが 0 件
- WHEN 切り替え画面を開く
- THEN 一覧は空で、生成が済んだキャラクターが無い旨を示す。クラッシュしない

### S0050_01 切り替え画面で選んだキャラクターの 3 枚を大きく出す

- GIVEN プールのあるキャラクター C に、待機画像・`regular`・`milestone` の画像が保存されている
- WHEN 切り替え画面の一覧で C を選ぶ
- THEN 一覧の横に C の 3 枚を並べて出し、どれがどの画像か分かるように示す。透明な所が分かる下地に載せる

### S0050_03 欠けた画像は欠けていると分かるように示す [境界]

- GIVEN C の `regular` の画像が欠けている(待機画像はある)
- WHEN 3 枚を出す
- THEN `regular` の枠に画像が無いことを示す。待機画像で**代えない**(キャラの窓の代わり S0036_20 とは別)

### S0050_04 画像を出しても保存データを変えない [否定]

- GIVEN キャラクター・使用中のキャラクター・画像・統計が保存されている
- WHEN 切り替え画面で一覧のキャラクターを選んで 3 枚を見る
- THEN 選んだだけでは使用中のキャラクターは変わらず(使用中にする操作は今のまま)、保存データは**変化しない**

### S0050_05 画像プロバイダーを選ぶ操作を出さない [否定]

- GIVEN キャラクター画面
- WHEN 画面を開く
- THEN 画像を含め、生成に使うプロバイダーを選ぶ操作は**出さない**(生成はローカルだけ。論点 0054)

### S0050_06 3 枚を出している所に「画像だけ作り直す」を出す

- GIVEN C の 3 枚を出している(切り替え画面で選んだ、またはキャラクター画面で生成が終わった)。画像の重みが置き場にある
- WHEN 画面を見る
- THEN 「画像だけ作り直す」の操作を出す。始めると `docs/pool-generation.md` S0050_07 の作り直しをし、進捗を示し、終わったら 3 枚の表示を新しくする

### S0050_07 画像の重みが無いか、生成中なら画像だけ作り直せない [境界]

- GIVEN 画像の重みが置き場に無い、またはどれかのキャラクターの生成か画像だけの作り直しが実行中
- WHEN 3 枚を出している画面を見る
- THEN 「画像だけ作り直す」を使えない形で出し、理由(重みが無い / 実行中)を示す

### S0038_07 作り直しになるときは、生成を始める前に確認する

- GIVEN キャラクター C に読み込めるプールがあり、生成を開始すると作り直しになる(`docs/pool-generation.md` S0038_02 / S0038_03 / S0038_06)
- WHEN キャラクター画面で C の生成を開始する
- THEN 生成を始める前に、プール・wav・画像を作り直す旨の確認を出す。作り直すを選んだときだけ生成を始める

### S0038_08 確認で取りやめたら何も変えない [否定]

- GIVEN S0038_07 の確認が出ている
- WHEN 取りやめる
- THEN 生成を始めない。C のプール・wav・画像・`generatedBy`・`activeCharacterId` は**変化しない**

### S0038_09 再開と初めての生成では確認を出さない [否定]

- GIVEN C の生成を開始すると再開になる(S0038_01 / S0038_04)、または C に読み込めるプールが無い(S0038_05)
- WHEN キャラクター画面で C の生成を開始する
- THEN 確認を**出さず**に生成を始める(再開では何も消えないため)

### S0033_13 設定画面で生成後に自動で使用中にするかを変える

- GIVEN `generation.shouldActivateOnComplete` が `true`
- WHEN 設定画面で「生成が完了したら使用中にする」を外して保存する
- THEN `generation.shouldActivateOnComplete` を `false` として永続化する。次の生成の完了から効く(S0032_20)

### S0036_29 設定画面で常時表示を切り替える

- GIVEN `popup.shouldAlwaysShow = true` でキャラの窓が出ている
- WHEN 設定画面で「キャラを常に表示する」を外して保存する
- THEN `popup.shouldAlwaysShow` を `false` として永続化し、再起動しなくてもキャラの窓を消す(以降は S0036_24)。
  付け直したら再起動しなくても窓を出す

### S0053_08 設定画面でセリフを出すかを切り替える

- GIVEN `popup.shouldShowMessage = true`
- WHEN 設定画面で「セリフを表示する」を外して保存する
- THEN `popup.shouldShowMessage` を `false` として永続化し、再起動しなくても次の応援からセリフを出さない(S0053_04)。
  `popup` のほかの設定(`shouldAlwaysShow`・`customPosition`)は変化しない。付け直したら次の応援から出す

### S0053_09 セリフを出すかの不正な値は保存しない [不変条件]

- GIVEN renderer から `shouldShowMessage` に真偽値でない値を指定したリクエストが届く
- WHEN main が受け取る
- THEN 保存せず、エラーを返す。窓の表示も変えない(S0033_15 と同じ扱い)

### S0057_01 テーマが system なら OS の設定に合わせる

- GIVEN `ui.theme = "system"`、OS の設定がダーク
- WHEN メインウィンドウを表示する
- THEN メインウィンドウはダークの見た目で表示される。OS の設定がライトならライトの見た目

### S0057_02 OS の設定が変わったら開いているメインウィンドウにすぐ反映する

- GIVEN `ui.theme = "system"`、メインウィンドウが表示中
- WHEN OS の設定をライトからダークに変える
- THEN 再起動せず、表示中のメインウィンドウがダークの見た目に変わる

### S0057_03 設定画面でテーマを選ぶとすぐ反映する

- GIVEN `ui.theme = "system"`、OS の設定がライト
- WHEN 設定画面でテーマを「ダーク」にして保存する
- THEN `ui.theme` を `"dark"` として永続化し、再起動せずにメインウィンドウがダークの見た目に変わる

### S0057_04 light / dark を選んでいれば OS の設定に従わない [境界]

- GIVEN `ui.theme = "light"`、メインウィンドウが表示中
- WHEN OS の設定をダークに変える
- THEN メインウィンドウはライトのまま変わらない

### S0057_05 テーマはキャラの窓と確認ダイアログを変えない [否定]

- GIVEN キャラの窓が出ている
- WHEN `ui.theme` を `"dark"` に変える
- THEN キャラの窓(絵・セリフの吹き出し)の見た目は**変化しない**。作り直しの確認ダイアログ(S0038_07)は OS の設定に従い、`ui.theme` では変わらない

### S0057_06 テーマの不正な値は保存しない [不変条件]

- GIVEN renderer から `ui.theme` に `"system"` / `"light"` / `"dark"` 以外の値を指定したリクエストが届く
- WHEN main が受け取る
- THEN 保存せず、エラーを返す。メインウィンドウの見た目も変えない(S0033_15 と同じ扱い)

### S0057_07 テーマの変更は他の設定と保存データを変えない [否定]

- GIVEN 保存済みのキャラクター・トリガー設定・`popup` の設定・統計
- WHEN 設定画面でテーマを変えて保存する
- THEN `ui.theme` 以外は**変化しない**

### S0070_01 設定画面に応援の回数・秒数・節目を出す

- GIVEN 保存値 `triggers = { regular: 30, activeThresholdSec: 90, milestoneInterval: 500, isMilestoneEnabled: true }`
- WHEN 設定画面を開く
- THEN 応援の欄に、通常の応援の回数 30・止まった扱いにするまでの秒数 90・節目の回数 500・節目の応援を出す(入)が出る。
  設定が保存されていなければ既定値(50・60・250・入)が出る(S0015_01)

### S0070_02 確定した値をすぐ保存する

- GIVEN 設定画面で通常の応援の回数が 50
- WHEN 回数の欄に 80 を入れて確定する(欄から離れる、または Enter)
- THEN `triggers.regular = 80` を保存し、次の打鍵から 80 回ごとに応援する(保存ボタンは無い)

### S0070_03 確定する前の入力は保存しない [否定]

- GIVEN 設定画面で通常の応援の回数が 50
- WHEN 回数の欄に「1」と打ち、まだ確定していない
- THEN 保存は起きず、`triggers.regular` は 50 のまま

### S0070_04 範囲より小さい値・大きい値は端の値にする [境界]

- GIVEN 設定画面で `regular = 50`・`milestoneInterval = 250`
- WHEN 秒数の欄に 1、または 9999 を入れて確定する
- THEN 秒数の欄は 5(または 600)になり、その値を保存する。回数の欄・節目の欄も同じ(回数 1〜`節目 - 1`、節目 `回数 + 1`〜100000)

### S0070_05 小数は切り捨てて整数にする [境界]

- GIVEN 設定画面
- WHEN 回数の欄に 80.7 を入れて確定する
- THEN 回数の欄は 80 になり、その値を保存する

### S0070_06 空や数でない入力は保存されている値に戻す [異常系]

- GIVEN 設定画面で通常の応援の回数が 50
- WHEN 回数の欄を空にして(または数でない入力で)確定する
- THEN 回数の欄は 50 に戻り、保存は起きない

### S0070_07 回数を節目以上に、節目を回数以下にできない [否定]

- GIVEN 設定画面で `regular = 50`・`milestoneInterval = 250`
- WHEN 回数の欄に 300 を入れて確定する(または節目の欄に 40 を入れて確定する)
- THEN 回数の欄は 249(または節目の欄は 51)になる。**節目が回数以下の値は保存されない**。節目の応援を出さない間も同じ

### S0070_08 節目の応援を出さない間は節目の回数を変えられない [境界]

- GIVEN 設定画面で節目の応援を出す(入)、節目の回数 250
- WHEN 「節目の応援を出す」を切る
- THEN `triggers.isMilestoneEnabled = false` を保存し、節目の回数の欄は押せない形になる。`milestoneInterval` は 250 のまま保存されている

### S0070_09 応援の欄の変更は他の設定と保存データを変えない [否定]

- GIVEN 保存済みのキャラクター・使用中のキャラクター・`popup` の設定・テーマ・`generation` の設定・統計
- WHEN 設定画面で応援の欄の値を変えて保存する
- THEN `triggers` 以外は**変化しない**

### S0033_14 設定の変更は他の保存データを変えない [否定]

- GIVEN 保存済みのキャラクター・使用中のキャラクター・トリガー設定・統計
- WHEN 設定画面で `generation.shouldActivateOnComplete` を変えて保存する
- THEN `characters`・`activeCharacterId`・トリガー設定・統計は**変化しない**(実行中の生成にも触れない)

### S0033_15 renderer からの設定の変更は main 側で検証する [不変条件]

- GIVEN renderer から `generation.shouldActivateOnComplete` に真偽値でない値を指定したリクエストが届く
- WHEN main が受け取る
- THEN 保存せず、エラーを返す(`security-rules.md`「入力と信頼境界」)

## 不変条件

- 常駐アプリ:メインウィンドウを閉じても `app.quit()` しない。
- 発動経路(キー押下 → ポップアップ)とメインウィンドウのライフサイクルは独立。
- `hasCharacter` はメモリ上の設定オブジェクトから決定的に計算する純粋関数(I/O を持たない)。
- `onboarding.skipMainWindowAutoShow` は自動表示のみを抑制する。トレイからの手動オープンには影響しない。
- 画面(タブ)の切り替えは表示だけを変え、保存データ・生成・使用中のキャラクターに触れない。
