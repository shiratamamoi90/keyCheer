# 要件: メインウィンドウの開閉(キャラクター未作成時の自動表示 + トレイからの開閉)

キャラクターが未作成のとき、起動時にメインウィンドウ(将来キャラ作成 UI を載せる場所)を自動表示する。
キャラクター作成済み、または自動表示をユーザーがスキップ済みのときは自動表示しない。
トレイから手動でも開閉(トグル)できる。ウィンドウを閉じても常駐は継続する(プロセスは終了しない)。

前半の要件は「いつ表示/非表示になるか」というライフサイクル(論点 0018)、後半の要件は
メインウィンドウの画面の分け方と各画面でできること(論点 0033)。
フォームの入力と保存は `docs/character-creation.md`、生成は `docs/pool-generation.md`、
使用中のキャラクターの切り替えは `docs/character-selection.md` が正本。画面の見た目・レイアウトは仕様化しない。

`hasCharacter` の判定・`onboarding.skipMainWindowAutoShow` のデータ契約は `docs/data-model.md` 参照。
下の `hasCharacter(character)` は、論点 0032 以降「`characters` が 1 件以上」を指す。

### S0018_01 キャラクター未作成なら起動時にメインウィンドウを表示する

- GIVEN `hasCharacter(character) === false` かつ `onboarding.skipMainWindowAutoShow === false`
- WHEN アプリを起動する
- THEN メインウィンドウが自動的に表示される

### S0018_02 キャラクター作成済みなら起動時にメインウィンドウを表示しない

- GIVEN `hasCharacter(character) === true`
- WHEN アプリを起動する
- THEN メインウィンドウは生成されるが非表示のまま(トレイ操作でのみ表示される)

### S0018_03 スキップ済みなら未作成でも起動時に表示しない

- GIVEN `hasCharacter(character) === false` かつ `onboarding.skipMainWindowAutoShow === true`
- WHEN アプリを起動する
- THEN メインウィンドウは生成されるが自動表示しない(トレイからは引き続き開ける)

### S0018_04 トレイクリックで表示/非表示をトグルする

- GIVEN メインウィンドウが非表示状態
- WHEN トレイの「KeyCheer を開く」をクリックする
- THEN メインウィンドウが表示され、フォーカスされる
- GIVEN メインウィンドウが表示中に同操作を行う
- WHEN トレイをクリックする
- THEN 非表示になる(hide。ダイアログは経由しない)

### S0018_05 作成済みなら閉じてもダイアログを出さない

- GIVEN `hasCharacter(character) === true` の状態でメインウィンドウが表示中
- WHEN 閉じるボタン(×)を押す
- THEN 確認ダイアログを出さず、即座に hide する(`app.quit()` は呼ばれない)

### S0018_06 未作成のまま閉じるとダイアログが出る

- GIVEN `hasCharacter(character) === false` の状態でメインウィンドウが表示中
- WHEN 閉じるボタン(×)を押す
- THEN 「次回から自動表示しない」チェックボックス付きの確認ダイアログを表示する
  (`close` イベントの既定動作を止めてから非同期で確認する)

### S0018_07 ダイアログの選択でスキップフラグが決まる

- GIVEN 上記ダイアログが表示されている
- WHEN チェックボックスを**チェックせず** OK を選ぶ
- THEN ウィンドウは hide され、`onboarding.skipMainWindowAutoShow` は変更しない
- GIVEN 上記ダイアログが表示されている
- WHEN チェックボックスを**チェックして** OK を選ぶ
- THEN ウィンドウは hide され、`onboarding.skipMainWindowAutoShow` を `true` として永続化する

### S0018_08 スキップ済みでもトレイからは開ける

- GIVEN `onboarding.skipMainWindowAutoShow === true` かつ `hasCharacter(character) === false`
- WHEN トレイの「KeyCheer を開く」をクリックする
- THEN メインウィンドウが表示される(スキップは自動表示のみを抑制し、手動オープンには影響しない)

### S0018_09 重複表示の防止 [境界]

- GIVEN メインウィンドウの表示要求(起動時自動表示・トレイクリック)が短時間に重複する
- WHEN 2 回目以降の表示要求が発生する
- THEN 新しいウィンドウを二重生成せず、既存の 1 つを表示・フォーカスするだけに留める

### S0018_10 メインウィンドウの読み込みに失敗した場合 [異常系]

- GIVEN メインウィンドウ用 HTML の読み込みに失敗する
- WHEN 起動時の自動表示 or トレイクリックが発生する
- THEN アプリは落ちず、発動経路(キー押下 → ポップアップ)は影響を受けない。
  main 側にエラーログを残すのみとする

### S0018_11 メインウィンドウは発動経路と独立している [不変条件]

- GIVEN メインウィンドウの表示/非表示状態(任意)
- WHEN キー押下がトリガー条件を満たす
- THEN メインウィンドウの状態に関係なくポップアップが発動する(相互に依存しない)

### S0018_12 メインウィンドウの renderer は providers を import しない [不変条件]

- GIVEN メインウィンドウ用 preload / renderer のソース
- WHEN import を検査する
- THEN `src/agent/*`・`src/core/providers/*` を import しない(ESLint no-restricted-imports で機械的に検査)

## 要件: メインウィンドウの画面(論点 0033)

メインウィンドウを「保存」「生成」「切り替え」「設定」の 4 つの画面に分け、タブでいつでも行き来できる。
「プールのある」は、そのキャラクターの `pool.json` を読み込めることを指す(`docs/data-model.md`)。

### S0033_01 4 つの画面をタブでいつでも切り替えられる

- GIVEN メインウィンドウが表示中(どの画面を開いていても、生成中でも)
- WHEN 保存・生成・切り替え・設定のいずれかのタブを選ぶ
- THEN その画面に切り替わる

### S0033_02 キャラクターが 0 件なら保存画面を最初に出す

- GIVEN `characters` が空
- WHEN メインウィンドウを非表示から表示にする(起動時の自動表示・トレイ)
- THEN 保存画面を出す

### S0033_03 プールのあるキャラクターがあれば切り替え画面を最初に出す

- GIVEN プールのあるキャラクターが 1 件以上
- WHEN メインウィンドウを非表示から表示にする
- THEN 切り替え画面を出す

### S0033_04 保存済みでもプールのあるものが無ければ生成画面を最初に出す [境界]

- GIVEN `characters` が 1 件以上で、プールのあるキャラクターが 0 件
- WHEN メインウィンドウを非表示から表示にする
- THEN 生成画面を出す

### S0033_05 表示中のウィンドウは開いている画面を変えない [否定]

- GIVEN メインウィンドウが表示中で、利用者が設定画面を開いている
- WHEN 起動時の自動表示やトレイからの表示要求が重なる(S0018_09)、または生成が完了する
- THEN 開いている画面は**変わらない**(最初の画面を決めるのは非表示から表示にしたときだけ)

### S0033_06 生成中にほかの画面へ移っても生成は続く [否定]

- GIVEN キャラクター C の生成が実行中で、生成画面を開いている
- WHEN 別の画面へ移る、または生成画面へ戻る
- THEN C の生成は中断も再開始も**されない**。生成画面に戻ると、その時点の進捗を出す

### S0033_07 生成中はほかの画面でも生成タブに「生成中」と示す

- GIVEN 生成が実行中
- WHEN 保存・切り替え・設定のいずれかの画面を開いている
- THEN 生成タブに生成中であることを示す。生成が終わる(完了・中断・失敗)と示すのをやめる

### S0033_08 進捗と中断は生成画面だけに出す [否定]

- GIVEN 生成が実行中
- WHEN 保存・切り替え・設定のいずれかの画面を開いている
- THEN 進捗の詳細と中断の操作はその画面に**出さない**(中断は生成画面から行う。S0020_06)

### S0033_09 生成画面で選べるのは保存済みのキャラクターだけ [否定]

- GIVEN 保存画面に未保存の入力がある
- WHEN 生成画面で生成するキャラクターを選ぶ
- THEN 選べるのは `characters` にあるキャラクターだけで、未保存の入力は候補に**含まれない**

### S0033_10 切り替え画面にプールの無いキャラクターを出さない [否定]

- GIVEN プールのあるキャラクター D と、プールの無いキャラクター E がある
- WHEN 切り替え画面を開く
- THEN D は一覧に出し、E は**出さない**。使用中のキャラクターがあれば、それと分かるように示す

### S0033_11 生成中で前回のプールがあるものは選べない形で出す [境界]

- GIVEN キャラクター C の生成が実行中で、C に前回のプールがある
- WHEN 切り替え画面を開く
- THEN C を一覧に出すが選べない形にし、生成中である旨を示す(S0032_13)。C が使用中ならそれも示す

### S0033_12 プールのあるキャラクターが無ければ切り替え画面でそう示す [境界]

- GIVEN プールのあるキャラクターが 0 件
- WHEN 切り替え画面を開く
- THEN 一覧は空で、生成が済んだキャラクターが無い旨を示す。クラッシュしない

### S0033_13 設定画面で生成後に自動で使用中にするかを変える

- GIVEN `generation.shouldActivateOnComplete` が `true`
- WHEN 設定画面で「生成が完了したら使用中にする」を外して保存する
- THEN `generation.shouldActivateOnComplete` を `false` として永続化する。次の生成の完了から効く(S0032_20)

### S0033_14 設定の変更は他の保存データを変えない [否定]

- GIVEN 保存済みのキャラクター・使用中のキャラクター・トリガー設定・統計
- WHEN 設定画面で `generation.shouldActivateOnComplete` を変えて保存する
- THEN `characters`・`activeCharacterId`・トリガー設定・統計は**変化しない**(実行中の生成にも触れない)

### S0033_15 renderer からの設定の変更は main 側で検証する [不変条件]

- GIVEN renderer から `generation.shouldActivateOnComplete` に真偽値でない値を指定したリクエストが届く
- WHEN main が受け取る
- THEN 保存せず、エラーを返す(`security-rules.md`「入力と信頼境界」)

## 不変条件

- 常駐アプリ:メインウィンドウを閉じても `app.quit()` しない。
- 発動経路(キー押下 → ポップアップ)とメインウィンドウのライフサイクルは独立。
- `hasCharacter` はメモリ上の設定オブジェクトから決定的に計算する純粋関数(I/O を持たない)。
- `onboarding.skipMainWindowAutoShow` は自動表示のみを抑制する。トレイからの手動オープンには影響しない。
- 画面(タブ)の切り替えは表示だけを変え、保存データ・生成・使用中のキャラクターに触れない。
