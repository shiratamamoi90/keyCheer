# アーキテクチャ:分離軸 × 実装手段

この設計は2つの直交する軸でできている。規模が変わっても **Core は書き換えず、行・列・セル単位で足し引きする**だけで拡張できる。

## 分離軸(縦):規模に応じたレイヤー

| レイヤー  | いつ使うか             | 内容                                                    |
| --------- | ---------------------- | ------------------------------------------------------- |
| **Core**  | 常時(個人開発から)     | 二系統原則、基本 skill、format+test フック              |
| **Scale** | 規模が上がったら足す   | ADR、危険操作veto、CI連携、sub-agent 並列化             |
| **Adapt** | プロジェクト種別で差替 | 「正」の定義、ドメイン別 skill、baselines/migrations 等 |

## 実装手段(横):担保の強さ

| 手段     | 置き場                        | 強制力         | 役割                 |
| -------- | ----------------------------- | -------------- | -------------------- |
| **方針** | CLAUDE.md / .claude/rules/    | なし(影響のみ) | 守ってほしいこと     |
| **実行** | .claude/skills/               | コマンドで呼ぶ | 繰り返す工程の自動化 |
| **強制** | .claude/settings.json (hooks) | あり(機械実行) | 絶対に守らせること   |

> 重要:CLAUDE.md はハードポリシーではない。絶対則は可能な限り hooks か skill の停止条件で担保する。「守ってほしい」は方針列、「守らせる」は強制列。

## マトリクス

|           | 方針                   | 実行                                               | 強制                         |
| --------- | ---------------------- | -------------------------------------------------- | ---------------------------- |
| **Core**  | 二系統原則・Don't      | /new-change, /new-experiment, /validate, /run-loop | format on edit, test on stop |
| **Scale** | チーム規約・ロール     | /eval, /onboarding                                 | 危険操作veto, 時間予算, CI   |
| **Adapt** | 「正」の定義・不変条件 | ドメイン別コマンド                                 | ドメイン別検査               |

各セルは独立。1セルの変更が他に波及しない。

## 二系統の対応表

|              | 仕様ループ(決定的)             | 探索ループ(非決定的)                              |
| ------------ | ------------------------------ | ------------------------------------------------- |
| 単位フォルダ | changes/NNNN-xxx/              | experiments/NNNN-xxx/                             |
| 中身         | proposal / spec / tasks / diff | hypothesis / config / result                      |
| 完了先       | specs/ に反映しアーカイブ      | result を残しアーカイブ                           |
| テスト       | 全シナリオを縛る(主役)         | 強さは縛らない。クラッシュ/予算のみ決定的にテスト |
| 対応コード   | src/engine(安定・決定的)       | src/agent, src/eval(探索)                         |

## 依存方向(不変条件)

```
src/engine  ← src/agent  ← src/eval
(決定的・安定)   (探索)       (評価)
```

矢印の向きにのみ依存してよい。engine は agent / eval を知らない。これを崩すとテスト容易性と再現性が同時に壊れる。

### KeyCheer での割り当て

| 層     | KeyCheer での中身                                                              | Electron 上の居場所                      |
| ------ | ------------------------------------------------------------------------------ | ---------------------------------------- |
| engine | カウント / アクティブ時間(60秒) / KPM / 速度ゾーン / トリガー判定 / データ契約 | 純粋ロジック(main/renderer 両方から利用) |
| agent  | Ollama 応援メッセージ生成、sd.cpp キャラ画像生成、プリキャッシュ               | main プロセスの I/O アダプタ             |
| eval   | 応援文言の品質・多様性・レイテンシの計測                                       | スクリプト(`npm run eval`)               |

UI(React レンダラ)・キーフック・トレイ・IPC は engine を**使う側**。engine はこれらに依存しない。

## 種別ごとの Adapt(差し替え表)

| 種別                            | 「正」                      | 仕様ループ       | 探索ループ    | 固有物                             |
| ------------------------------- | --------------------------- | ---------------- | ------------- | ---------------------------------- |
| Web/業務アプリ                  | 要件定義                    | 主役             | ほぼ無し      | migrations/                        |
| CLI/ツール                      | コマンド仕様                | 主役             | 無し          | fixtures/                          |
| ライブラリ                      | 公開API契約                 | 主役             | 無し          | 後方互換テスト                     |
| MLコンペ                        | 評価指標+ルール             | engine部のみ     | 主役          | baselines/, eval/                  |
| 研究/PoC                        | 検証仮説                    | 補助             | 主役          | data versioning                    |
| **★ KeyCheer(デスクトップ+AI)** | **要件 + プライバシー方針** | **主役(engine)** | **AI 部のみ** | **baselines/(定型文), 同梱モデル** |

KeyCheer は「Web/業務アプリ」に近い(決定的コアが主役)が、応援文言・画像という AI 機能を持つため
探索ループを一部併用する **ハイブリッド**。種別が変わったら Adapt 行だけ差し替える。Core/Scale は不変。
