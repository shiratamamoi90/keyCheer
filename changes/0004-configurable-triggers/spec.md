# 要件: トリガー条件の設定可能化

通常応援の間隔・マイルストーン・アクティブ判定の秒数は **設定値** として保持し、ユーザーが UI から変更できる。既定値は安全側で固定する。値域はバリデーションし、不正値は拒否してエラー表示する。設定変更は再起動なしで即時反映される。

設定スキーマ:

```jsonc
{
  "triggers": {
    "regular": 50, // 既定 50。1 ≦ N ≦ 10000
    "milestones": [1000, 5000, 10000, 50000, 100000], // 既定値は維持。各値 1 以上・昇順・重複なし、最大 20 個、空配列許容(milestone OFF)
    "activeThresholdSec": 60, // 既定 60。5 ≦ s ≦ 600(10 分)
  },
}
```

- **KPM 算出窓(60 秒)は本設定とは独立**(`speed-zone.md` 参照)。`activeThresholdSec` を変更しても KPM 窓は影響を受けない。

## シナリオ: 既定値(新規インストール)

- GIVEN 設定 JSON が存在しない
- WHEN 起動して設定を読み込む
- THEN `triggers.regular = 50` / `triggers.milestones = [1000, 5000, 10000, 50000, 100000]` / `triggers.activeThresholdSec = 60` が既定として読み込まれる

## シナリオ: 通常応援間隔の変更

- GIVEN `triggers.regular = 50`、累計カウントが 29
- WHEN ユーザーが UI で 30 に変更し保存、その後キーを 1 回押す
- THEN カウントが 30 になり、種別 `regular` の応援が発動する(再起動不要)

## シナリオ: マイルストーンの変更

- GIVEN マイルストーン `[1000, 5000, 10000, 50000, 100000]`
- WHEN ユーザーが `[100, 500, 1000]` に変更し保存
- THEN 設定が永続化され、カウント 100/500/1000 で `milestone` 種別の応援が発動する(他の数値では発動しない)

## シナリオ: アクティブ判定秒数の変更

- GIVEN `triggers.activeThresholdSec = 60`
- WHEN ユーザーが 120 に変更し保存
- THEN 最後の押下から 120 秒以内を `isActive=true` と判定する。**KPM 窓(直近 60 秒)は影響を受けない**(KPM は引き続き「分」の値を保つ)

## シナリオ: 不正値(通常応援間隔)[境界・異常系]

- GIVEN ユーザーが通常応援間隔に `0` / 負数 / 非整数 / 上限超 を入力
- WHEN 設定保存を試みる
- THEN 保存は拒否され、エラー表示。既存の有効値は変更されない

## シナリオ: 不正値(マイルストーン)[境界・異常系]

- GIVEN マイルストーンに以下のいずれか:`0` 以下を含む / 重複 / 降順 / 非整数 / 最大個数超
- WHEN バリデーション
- THEN 拒否されエラー表示

## シナリオ: 不正値(アクティブ秒数)[境界・異常系]

- GIVEN アクティブ秒数に `0` / 負数 / 5 未満 / 600 超 が入力される
- WHEN バリデーション
- THEN 拒否されエラー表示

## シナリオ: 設定 JSON 直接編集への防御 [不変条件]

- GIVEN ユーザーが `electron-store` の JSON を直接編集し不正値を書き込んだ状態でアプリ起動
- WHEN 起動時バリデーション
- THEN 不正キーは既定値に置換され、エラーログを出して起動を継続する(クラッシュしない)

## シナリオ: 旧 JSON の補完 [境界]

- GIVEN 旧バージョンの設定 JSON に `triggers.activeThresholdSec` キーがない
- WHEN 起動時に読み込む
- THEN 欠損キーは既定値 60 で補完される(他の既存キーは保持)

## シナリオ: 既存 `triggers.regular = 100` を 50 にリセット [マイグレーション]

- GIVEN アップデート前に保存された `triggers.regular = 100`(現行既定値)
- WHEN アップデート後に起動
- THEN `triggers.regular` は **50 にリセット**され、初回起動時に「既定値が 50 に変更されました」とユーザーに通知する(以降ユーザーが明示的に再変更した値は尊重される)

## シナリオ: マイルストーン空配列の許容

- GIVEN ユーザーがマイルストーンを `[]` に設定
- WHEN 保存
- THEN 保存を許容する。`milestone` 種別の応援は発動しなくなり、`regular` のみが動く(milestone OFF として有効な設定)

## シナリオ: 変更の即時反映

- GIVEN 起動中に設定を保存
- WHEN 直後にキーを押す
- THEN 再起動なく新しい設定値で発動判定される(engine 側はキャッシュを保持しない / 設定変更通知で更新する)

## シナリオ: 速度ゾーン閾値は本変更の対象外 [境界]

- GIVEN ユーザーが UI を開く
- WHEN トリガー設定画面を表示
- THEN 通常間隔・マイルストーン・アクティブ秒数のみが編集対象。速度ゾーン閾値(slow/normal/fast = 100/250)は本画面に出ない

## 不変条件

- 設定値が何であっても、応援発動経路の外部依存ゼロ(`providers` 不参照)は維持。
- engine 側のバリデーションは **純粋関数** で、UI 側のチェックに依存しない(設定 JSON 直接編集にも耐える)。
- engine は `electron-store` を直接 import しない。設定は引数で受け取る。
- プライバシー方針(キー種類のみカウント・統計・発動経路の永久ローカル)は維持。
