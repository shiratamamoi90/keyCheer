# 提案 0002: 応援はアプリ単体で完結 — AI/TTS はキャラ作成時のみ使用

## なぜ

現状の設計は応援発動のたびに Ollama でメッセージ生成 + VOICEVOX で音声合成する。これは:

- 応援にレイテンシが乗る(プリキャッシュで吸収する複雑なロジックが必要)
- Ollama/VOICEVOX の常駐が前提になり、未起動時のフォールバック分岐が増える
- 「すべてオフラインで完結」というコンセプトに対し、毎回 localhost にアクセスする実装上の引っかかりが残る

応援の発動は「キャラを作ったあとずっと続く日常体験」。一方キャラ作成は「ユーザーが意識して一度だけやる準備フェーズ」。**重い処理は準備フェーズに寄せ、日常体験はゼロ依存で動く**方が自然。

## 方針

キャラ作成時に Ollama でメッセージプール(約 480 文)を一括生成し、VOICEVOX で全文を事前合成して wav 保存する。応援発動時はプールから対応シナリオの文を選び、対応 wav を再生するだけ。アプリ実行中は localhost サーバーすら不要。

## 影響範囲

- ADDED:
  - キャラ作成フロー(性格・口調生成 → メッセージプール一括生成 → 音声事前合成 → 保存)
  - メッセージプールのデータ契約(`{zone × type × timeOfDay}` の 24 シナリオ × 約 20 文)
  - 発動時のプール選択 & wav 再生ロジック(LLM/TTS 呼び出しなし)
  - プール枯渇/欠損時のフォールバック契約
- MODIFIED:
  - `specs/integrations.md`: Ollama / VOICEVOX の用途を「キャラ作成時のみ」に明示。応援発動からの依存を削除
  - `specs/cheer-trigger.md`: 「ゾーン別バケットからの取り出し」を「プールからの取り出し + wav 再生」に変更
  - `specs/data-model.md`: `character` に messagePool / voicePool への参照(または保存ディレクトリ規約)を追加
  - CLAUDE.md: 冒頭の説明(「Ollama が応援メッセージを生成し、VOICEVOX が読み上げる」)とプライバシー方針(「localhost のみ」→「キャラ作成時のみ localhost、応援時はゼロ依存」)
- REMOVED:
  - 応援発動経路からの Ollama/VOICEVOX 呼び出し
  - 「速度ゾーン別プリキャッシュの非同期補充」ロジック(プールは初期化時に決まる固定資産になる)

## 種別判定

**決定的**(同じキャラ・同じ発動条件・同じシード → 同じプール選択・同じ wav 再生)。仕様ループで進める。
※ LLM が**どんな文言を生成するか**・VOICEVOX 音声の自然さ・480 文の生成時間体感は非決定的 → experiments/ で測る(既存 0001-cheer-prompt-tone をプール一括生成の文脈に拡張)。本 change では「プール構造を満たす」「発動時に正しい wav が再生される」「枯渇/欠損時にフォールバックする」までを決定的に縛る。

## 要確認

- メッセージ内の動的数値(例: 「500 回」)の扱い: プールには汎用文を入れ実行時に差し込むか、milestone だけテンプレート補間か
- 480 文 × wav の総ディスク使用量(数十 MB〜100 MB 級)と保存場所(ユーザーデータディレクトリ配下のどこか)
- キャラ再生成時の差分更新方針(全廃棄 & 再生成 / 差分のみ再生成)
- 同一文の連続再生を避けるシャッフル方針(LRU / セッション内除外)
- 480 文一括生成中の UX(進捗表示、キャンセル、中断後の再開可否)
- マイルストーン回数が設定によって変わるとき、プール側に持つべき情報(例: 1000 / 5000 共通の汎用文 + `{milestone}` 差し込み)
