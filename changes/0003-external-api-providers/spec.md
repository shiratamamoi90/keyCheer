# 要件: 生成プロバイダー抽象とプライバシー境界

キャラ作成時のテキスト/音声/画像生成は、ローカルまたは外部 API を**プロバイダー**として差し替え可能にする。応援発動・キーカウント・統計は外部送信しない。外部送信はユーザーが明示選択した場合のみ発生する。

## シナリオ: プロバイダー設定の保存

- GIVEN ユーザーがキャラ設定で `text=openai`, `voice=local-voicevox`, `image=local-sdcpp` を選択
- WHEN 設定を保存する
- THEN 設定 JSON に `providers: { text: "openai", voice: "local-voicevox", image: "local-sdcpp" }` が記録される

## シナリオ: API キーは平文 JSON に出ない [不変条件]

- GIVEN ユーザーが OpenAI の API キーを入力
- WHEN 設定を保存する
- THEN キーは OS セキュアストレージ(safeStorage)に保存され、`electron-store` の JSON には**現れない**(プレースホルダ参照のみ)

## シナリオ: ローカル選択時は外部送信が発生しない [不変条件]

- GIVEN `providers` 3つすべてがローカル(`local-ollama` / `local-voicevox` / `local-sdcpp`)
- WHEN キャラを作成・プール生成・音声合成・画像生成を実行
- THEN localhost 以外への HTTP リクエストは**一切発生しない**(ネットワーク監視で 0 件)

## シナリオ: 外部選択時は同意ダイアログを経る

- GIVEN ユーザーがテキストを `openai` に切り替えた直後
- WHEN 初回のキャラ生成を試行する
- THEN 外部送信される情報(性格説明、プロンプト等)を明示するダイアログが出て、同意するまで送信は発生しない

## シナリオ: 同意済みプロバイダーへの再送信

- GIVEN ユーザーが過去に `openai` テキストへの送信に同意済み
- WHEN 同じプロバイダーで再度生成
- THEN 同意ダイアログは出ず、直接送信される(同意は当該プロバイダー単位で記録)

## シナリオ: プロバイダー切り替えで同意リセット

- GIVEN `openai` で同意済み、ユーザーが `anthropic` に切り替え
- WHEN `anthropic` で初回生成
- THEN 同意ダイアログが再度出る(同意は当該プロバイダー単位)

## シナリオ: 外部生成失敗時は自動でローカルに切り替えない [異常系]

- GIVEN テキスト `openai` 選択、ネットワーク断 or API エラー
- WHEN プール生成中に失敗する
- THEN 自動でローカルにフォールバックせず、エラーを表示してユーザーに再試行/プロバイダー変更を促す
  - 理由: 意図しない外部選択や、品質基準を満たさないローカル出力での自動保存を防ぐ

## シナリオ: APIキー未設定で外部プロバイダーを選んだ場合 [異常系]

- GIVEN `text=openai` 選択、API キー未設定
- WHEN 生成を試行する
- THEN 生成は実行されず、キー入力を促すダイアログが出る(外部送信は発生しない)

## シナリオ: 応援発動経路から外部 API を呼ばない [不変条件]

- GIVEN キャラ作成済み(プロバイダーが何であれ)
- WHEN 応援が発動する
- THEN 0002 と同じく **localhost 含めて一切のサーバー通信を行わない**。プロバイダー設定は応援経路で参照されない

## シナリオ: キー入力・統計は外部送信しない [不変条件]

- GIVEN いかなるプロバイダー設定でも
- WHEN キー押下・KPM 算出・統計更新・cheerHistory への記録が起きる
- THEN これらのデータが外部に送られることはない(設定で許可するオプションも提供しない)

## シナリオ: 生成元プロバイダーの記録

- GIVEN プール・音声・画像の生成が完了
- WHEN `character` を保存する
- THEN そのキャラがどのプロバイダーで作られたかが `character.generatedBy: { text, voice, image }` に記録される(再生成時の参照用)

## シナリオ: プロバイダー一覧の契約 [境界]

- GIVEN プロバイダー識別子
- WHEN バリデーション
- THEN 既定セットに含まれる識別子のみ受理する
  - text: `"local-ollama" | "openai" | "anthropic"`
  - voice: `"local-voicevox" | "openai-tts" | "elevenlabs"`
  - image: `"local-sdcpp" | "openai-dalle" | "stability-ai"`
  - ※ MVP に含める最終セットは tasks.md で確定([要確認])

## シナリオ: 同意ダイアログ未通過でのキー漏出防止 [境界]

- GIVEN 外部プロバイダー選択、同意ダイアログ表示中にアプリ強制終了 → 再起動
- WHEN 起動後に同じプロバイダーで生成を試行
- THEN 同意フラグは保存されておらず、ダイアログから再開する

## 不変条件

- 「キー入力内容を保存・送信しない」「キーカウント・KPM・統計は外部送信しない」「応援発動経路は外部依存ゼロ」は本変更でも維持する。
- API キーは平文 JSON に書かない。
- 「外部送信される情報の中身」は同意ダイアログでユーザーに必ず提示する。
- 各プロバイダーの**出力品質・レイテンシ**は仕様化しない(→ experiments/ で比較評価)。
