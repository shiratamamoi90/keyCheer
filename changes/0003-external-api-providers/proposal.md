# 提案 0003: キャラ生成の外部API対応(テキスト/音声/画像)とプライバシー方針の改定

## なぜ

ローカル LLM(Ollama)・ローカル TTS(VOICEVOX)・ローカル画像生成(sd.cpp)はオフライン性とコストゼロが利点だが、**生成物の品質や表現幅は外部 API(OpenAI / Anthropic / ElevenLabs / DALL-E 等)に劣る**。「自分のキャラ」を作る体験を重視するユーザーには、品質を優先して外部 API を選びたいニーズがある。

応援の発動経路は 0002 で外部依存ゼロになっているため、**キャラ作成時の生成手段だけ**外部 API を選べるようにすれば、応援フェーズのオフライン性・プライバシーは維持できる。

## 方針

- **生成手段の抽象化**: テキスト/音声/画像の生成インターフェースを切り、ローカル(Ollama / VOICEVOX / sd.cpp)と外部API実装を**プロバイダー**として差し替え可能にする
- **対応プロバイダー(MVP 想定)**:
  - テキスト: Ollama(local) / OpenAI / Anthropic Claude
  - 音声: VOICEVOX(local) / OpenAI TTS / ElevenLabs
  - 画像: sd.cpp(local) / OpenAI DALL-E / Stability AI
  - 最終的にどれを MVP に含めるかは tasks で確定
- **プライバシー方針改定**:
  - 旧: 「ネットワーク通信は localhost のみ」
  - 新: 「**キーカウント・応援発動・統計は永久に外部送信しない**(従来通り)。**キャラ作成時に限り、ユーザーが UI で外部プロバイダーを明示選択した場合のみ**、入力した性格説明やプロンプトを当該プロバイダーへ送信する。」
- **API キー保存**: OS のセキュアストレージ(Windows Credential Manager / Electron `safeStorage`)に保存。平文 JSON には書かない
- **デフォルトはローカル**: 何も設定しなくてもローカル一式で完結する状態を維持
- **生成失敗時のフォールバック**: 外部 API 失敗時は **自動でローカルにフォールバックしない**(意図しない外部選択を防ぐ)。ユーザーにエラーを示し再試行/プロバイダー変更を促す

## 影響範囲

- ADDED:
  - `src/agent/providers/` 配下にプロバイダー抽象とローカル/外部実装
  - API キー管理(safeStorage 経由)
  - キャラ設定画面に「プロバイダー選択 UI」(テキスト/音声/画像それぞれ)
  - 外部送信前の同意ダイアログ(初回 + プロバイダー変更時)
  - 設定スキーマに `providers: { text, voice, image }` 追加
- MODIFIED:
  - **CLAUDE.md のプライバシー方針**(改定が主目的の一つ)
  - 0002 で計画したプール生成・音声合成・画像生成パスをプロバイダー経由に
  - `specs/integrations.md`: ローカル一式の契約 + プロバイダー抽象の契約
  - `specs/data-model.md`: 設定に `providers` 追加、`character` に「生成元プロバイダー記録」追加
- 変えない:
  - 応援発動の決定的契約(0002)。プールから選んで wav 再生する経路には**一切外部 API を呼ばない**
  - キーカウント・統計の永久ローカル方針

## 種別判定

**決定的**(設定済みプロバイダーと入力 → 同じ呼び出しが起き、同じシード・同じプロバイダー応答なら同じ結果)。仕様ループで進める。
※ 各プロバイダーの**出力品質**(画像のうまさ・音声の自然さ・セリフのらしさ)・レイテンシは非決定的 → experiments/ で比較評価する(実装後)。本 change で縛るのは:

- 「ローカル選択時は外部送信が一切発生しない」
- 「外部選択時、同意なしに送信されることはない」
- 「API キーが平文 JSON に出ない」
- プロバイダー失敗時の挙動契約
- 設定スキーマの妥当性

## 要確認

- MVP に含めるプロバイダーの最終セット(各 1〜2 個ずつでよいか)
- 同意ダイアログの粒度(プロバイダーごと / 生成ごと / 1 回だけ)
- 外部選択時の概算コスト表示(生成前に「約 ¥XXX」を示すか)
- 生成失敗時の挙動: 「自動フォールバックしない」を本当に守るか、ユーザー設定でローカルへの fallback を許可するか
- プロキシ・社用ネット環境での通信失敗ハンドリング
- 利用規約上の責任表示(各 API プロバイダーの ToS への同意誘導)
- 監査ログ(「いつ何が外部送信されたか」を統計に残すか)
