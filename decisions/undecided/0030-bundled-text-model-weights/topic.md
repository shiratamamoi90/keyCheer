# 論点 0030: 利用者の機械にテキストモデルをどう入れるか(初回セットアップの取得物と、モデル定義の正本)

- **種別: 決定的**
- **状態: 未決定**
- **反映先: —**(初回セットアップは未実装。決まったら論点 0010 に「論点 0030 で置き換えた」と追記する)

## 何を決めるか

論点 0010 は「`gemma2:2b` を初回セットアップでアプリが取得する」と決めている。論点 0027 で
`sarashina2.2-3b-instruct` に変えたので、**利用者の機械に何を・どこから取得させるか**を決め直す。

0027 は開発機で公式の重みを Ollama に取り込んで量子化した。利用者の機械で同じことをさせると、
約 6.7 GB を取得したうえで量子化の計算が要る。

## 案

| | 案A: 量子化済み GGUF を自分たちでホストする | 案B: 利用者の機械で取り込む | 案C: コミュニティの GGUF を取得させる |
|---|---|---|---|
| 取得量 | 約 2.1 GB(Q4_K_M) | 約 6.7 GB(BF16) | 約 2.1 GB |
| 利用者の機械の負荷 | 小 | 量子化の計算(CPU で時間がかかる) | 小 |
| 出所 | 自分たちで変換した GGUF(sha256 で固定) | 公式の重み | 第三者(0027 で却下) |
| 必要なもの | ホスト先(MIT なので再配布できる) | 無し | 無し |
| ライセンス表記 | MIT の LICENSE を同梱 | 同左 | 同左 |

## 人間の方針(2026-10-25)

**Gemma は使わない。削除する方針。** 論点 0027 で Sarashina に替えたあと、gemma2:2b を残して
選べるようにはしない。

方針から決まること:初回セットアップで gemma2:2b は取得しない(0010 の取得物から外す)。
Gemma の利用規約の同梱義務(0010)も無くなる。

## 併せて決める:モデル定義の正本(開発機と利用者の機械で共有する)

人間の指摘(2026-10-25):**モデルのインストールは開発機だけでなく利用者の機械も考える。**

モデルを入れるのに要る値は、今は開発機の `scripts/import-sarashina.sh` にしか無く、モデル名だけが
アプリの既定値(`DEFAULT_SYSTEM_CONFIG.ollamaModel`)と 2 箇所に直書きされている。利用者の機械で
入れる仕組み(初回セットアップ)を作ると、同じ値が 3 箇所目に出る(@.claude/rules/impl-rules.md
「共通化」— 3 箇所目は設計が要求している合図)。

| 値 | 開発機(0029) | 利用者の機械(本論点) | アプリの生成(0028) |
|---|---|---|---|
| Ollama 上のモデル名 | 使う | 使う | 使う(既定値) |
| チャットテンプレート・stop | 使う | 使う(案A でも案B でも Modelfile が要る) | 使わない |
| 取得元とハッシュ | 公式の重み(safetensors) | 案A なら量子化済み GGUF / 案B なら公式の重み | 使わない |
| 量子化の形式 | 使う | 案B なら使う | 使わない |

| | 案M1: モデル定義をデータファイル 1 つにまとめる | 案M2: 各所に直書きのまま |
|---|---|---|
| 置き方 | 例:モデル名・テンプレート・stop・取得元・ハッシュを持つ JSON を 1 つ置き、開発用スクリプト・初回セットアップ・既定値がそこから読む | 今のまま。コメントで「一致させる」と書く |
| 片方だけ直す事故 | 起きない | 起きうる(モデル名がずれると生成が「モデルが無い」で失敗する) |
| 依存方向 | 既定値は core にある。core はファイル I/O をしないので、JSON を import(ビルド時に取り込む)できるかの確認が要る | 影響なし |
| シェルスクリプトから読む | `node -e` で読む(jq は依存に足さない) | — |

あわせて、利用者の機械でも開発機と同じ GGUF になることを確かめられる:0029 の取り込みは
2 回とも同じ層 `sha256:60e33bab…6b959` を出した(再現できる)。案A でホストする GGUF はこの
sha256 で固定でき、開発機で作ったものと同じであることを照合できる。
