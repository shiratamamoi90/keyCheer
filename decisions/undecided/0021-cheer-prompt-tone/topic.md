# 論点 0021: 応援プロンプトに速度ゾーンを含めるか

- **種別: 非決定的**
- **状態: 未決定**
- **反映先: —**(決めた値は config へ。要件には及ばない)

## 何を決めるか

キャラ作成時の一括生成で、プロンプトに速度ゾーン(slow / normal / fast)と当日アクティブ時間を
明示的に含めるかどうか。含めた方が状況に合った文言になるはずだが、**良し悪しは指標でしか測れない**
ため、決定的な要件としては書かない(@.claude/rules/experiment-rules.md)。

## 案

| | 案A: zone_aware(ゾーンを渡す) | 案B: zone_blind(渡さない = 現行) |
|---|---|---|
| 状況適合度 | 上がるはず(仮説) | 現行水準 |
| 生成レイテンシ | プロンプトが伸びる分わずかに増える | 現行水準 |
| プール構造への影響 | 無し(バケットは元からゾーン別) | 無し |

## 測り方

- 評価データ: 代表的な状況サンプル 30 件(count / type / timeOfDay / kpm / zone の組み合わせ)
- モデル: gemma2:2b(固定)、temperature 0.8 固定、seed 42 固定、依存は `package-lock.json` で固定
- 試行: 各サンプル 5 生成 = 150 メッセージ
- 指標: 状況適合度(人手 1〜5 スコアの平均)/ 多様性(同一サンプル内のユニーク率)/
  1メッセージあたり生成レイテンシ(ms)/ 契約違反率(30文字超過・空・複数文)
- 比較基準(baseline): `src/core/baseline/messages.ts` の同梱定型文と、ゾーンを渡さない現行プロンプト。
  baseline は固定し、改良したいときは別名で追加する(@.claude/rules/experiment-rules.md「規律」)。
- 計測コマンド: `npm run eval`

## 中止条件

- 一括生成の総時間がキャラ作成の待ち時間として許容できない水準を超えたら中止し、現行プロンプトに戻す。
- 契約違反率が baseline より悪化したら中止(品質以前の問題)。
