# 論点 0029: 開発用ランタイムで Sarashina をどう用意するか

- **種別: 決定的**
- **状態: 未決定**
- **反映先: —**(開発機の手順。`package.json` の `services:model` と `DEVELOPMENT.md` を直す。要件には及ばない)

## 何を決めるか

今の `npm run services:model` は `ollama pull gemma2:2b` を実行する。論点 0027 で採ったモデルは
Ollama の公式ライブラリに無く、**公式の重みを取得して `ollama create` で取り込む**必要がある
(手順は 0027 の「GGUF の出所の調査」で実機確認済み)。この手順を開発機でどう再現できる形にするか。

## 案

| | 案A: npm スクリプト + シェルスクリプト | 案B: 手順を DEVELOPMENT.md に書くだけ |
|---|---|---|
| やること | `scripts/` に取得(コミット固定 + sha256 照合)→ コンテナへコピー → Modelfile で `ollama create` を置き、`services:model` から呼ぶ | 人が手で同じ手順を打つ |
| 再現性 | 高い(ハッシュとテンプレートがスクリプトに固定される) | 打ち間違いの余地がある |
| 量 | 中(約 6.7 GB の取得、コンテナの中に curl が無いのでホスト側で取得) | 小 |

## 人間の方針(2026-10-25)

**Gemma は使わない。削除する方針。** 論点 0027 で Sarashina に替えたあと、gemma2:2b を残して
選べるようにはしない。

方針から決まること:`services:model` は gemma2:2b を取得しない。開発機の Ollama のボリュームに
残っている `gemma2:2b` も消す(`ollama rm gemma2:2b`)。論点 0021 / 0026 の baseline の比較にも使わない
(両論点は Sarashina で測る。論点 0027 の決定)。
