# 論点 0050: 画像プロバイダーの選択と、作った画像の確認を画面に出す

- **種別: 決定的**
- **状態: 未決定**
- **反映先: `docs/main-window.md`**(見込み。決まるまで `docs/` は書き換えない)

## 何を決めるか

2026-11-13 の整合の確認で、画像まわりが画面にほとんど出ていないことが分かった。人間の指示:**決めた内容は UI・UX にも反映する。画像も。**
要件が既にあるもの(画像が作れなかったときの表示・生成ボタンの文言)は直した。ここでは、要件が無いものを決める。

1. **画像プロバイダーの選択。** 生成画面の「生成に使うプロバイダー」には、応援メッセージと音声の 2 つしか無い。
   画像(`local-sdcpp` / `openai-dalle` / `stability-ai`)は設定の値(`providers.image`)はあるが、画面から変えられない。
2. **作った画像の確認。** 生成が終わっても、メインウィンドウでは 3 枚の画像を見られない。キャラの窓に待機画像が出るだけで、
   `regular`・`milestone` の画像は応援が出るまで見えない。背景の抜けそこないに気づけず、作り直すかの判断ができない。
3. **画像だけの作り直し。** 抜けそこないを見つけても、今は文言・音声ごと作り直すしかない(論点 0039 で「欠けた画像だけを補う操作は設けない」と
   決めている。見直すかどうか)。

## 案

### 1. 画像プロバイダーの選択

| | 案A:生成画面に 3 つ目の選択を足す | 案B:出さない(今のまま。既定の `local-sdcpp` 固定) |
| --- | --- | --- |
| 外部の画像を使えるか | 使える(同意ダイアログと API キーは既存の仕組みに乗る) | 画面からは使えない |
| 注意 | `openai-dalle` は 512x768 を受け付けない(既知)。外部は新しい作り方ではない(背景が透明にならない) | — |

### 2. 作った画像の確認

| | 案A:生成画面に、選んだキャラクターの 3 枚を並べて出す | 案B:切り替え画面の一覧に待機画像を小さく出す | 案C:出さない |
| --- | --- | --- | --- |
| 抜けそこないに気づけるか | 3 枚とも分かる | 待機画像だけ | 応援が出るまで分からない |
| 画面の変更 | 生成画面に画像の欄。透明が分かる下地(市松など)が要る | 一覧の項目 | 無し |

A と B は両立する。

### 3. 画像だけの作り直し

| | 案A:生成画面に「画像だけ作り直す」を足す | 案B:設けない(論点 0039 のまま) |
| --- | --- | --- |
| 抜けそこないへの手 | 画像の 3〜4 分だけで試し直せる | 文言・音声ごと作り直す(十数分) |
| 影響 | 論点 0039 を置き換える。シードが固定なので、同じ画像タグなら同じ絵になる(作り直すたびにシードを変えるかも決める必要がある) | — |

## `[要確認]`

- 1・2・3 それぞれ、どの案にするか。
- 2 の案A にするなら、画像を画面に渡す経路(専用スキームは既にキャラの窓で使っている)は作り方の話なので要件には書かない。

## 現在の考え

エージェントの考え(判断は人間):1 は案A、2 は案A + 案B、3 は案A(作り直すたびにシードを変える)。
背景の抜けそこないを「ひとまず受け入れる」と決めた(論点 0045)ので、気づけることと、安く試し直せることが要る。

**待っているもの**:上の `[要確認]` への人間の判断。
