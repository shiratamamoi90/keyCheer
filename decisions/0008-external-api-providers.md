# ADR 0008: キャラ生成に外部 API プロバイダーを採用、プライバシー方針を再定義(2026-05)

## 文脈

ローカル一式(Ollama / VOICEVOX / sd.cpp)は「オフライン・プライバシー優先」の利点が大きい一方、表現の幅や品質では外部 API(OpenAI / Anthropic / ElevenLabs / DALL-E 等)に劣る。
0002 で**応援発動は外部依存ゼロ**になっているため、キャラ作成時の生成手段だけ選べるようにすれば、日常体験のプライバシーと表現品質を両立できる。

## 決定

- **生成手段の抽象化**: テキスト・音声・画像を 3 種のプロバイダーインターフェースに切り、ローカル/外部実装を差し替え可能にする。
- **対応プロバイダー(MVP 想定)**:
  - テキスト: `local-ollama` / `openai` / `anthropic`
  - 音声: `local-voicevox` / `openai-tts` / `elevenlabs`
  - 画像: `local-sdcpp` / `openai-dalle` / `stability-ai`
  - 最終セットは tasks 段階で確定。
- **デフォルトはローカル**。何も設定しなければアプリは完全オフラインで動く。
- **API キー保存**: OS セキュアストレージ(Electron `safeStorage` 経由、Windows Credential Manager)。設定 JSON には平文を出さない。
- **プライバシー方針の再定義**(旧 → 新):
  - 旧: 「ネットワーク通信は **localhost のみ**」
  - 新: 「**キーカウント・KPM・統計・応援発動は永久に外部送信しない**(従来通り)。**キャラ作成時に限り**、ユーザーが UI で外部プロバイダーを**明示選択**し、**送信内容を提示する同意ダイアログ**を通過した場合のみ、入力された性格説明・プロンプトを当該プロバイダーへ送信する。」
- **生成失敗時の自動フォールバック禁止**: 外部 API 失敗時はエラーを表示し、ユーザーに再試行/プロバイダー変更を促す(ローカルへ自動退避させない)。
- **応援発動経路は本変更でも外部 API を呼ばない**(0002 の不変条件を維持)。

## 結果

- 利点:
  - 「自分の好きなキャラを作る」体験で表現品質が大きく上がる。
  - 応援フェーズ・統計のプライバシーは従来通り守られる(コードレベルでも、応援経路と生成経路を分離することで担保しやすい)。
  - プロバイダー差し替え可能な抽象は将来の選択肢追加(新 LLM・新 TTS)を低コストにする。
- 欠点 / トレードオフ:
  - 「localhost のみ」という強い不変条件を緩める判断であり、プライバシー方針の説明責任が増える(同意ダイアログ・送信内容の明示・ドキュメント)。
  - 実装複雑度が上がる(抽象、キーボックス、同意フロー、UI)。
  - 外部 API 利用は従量課金。ユーザー負担。
  - プロバイダーごとの ToS への同意誘導が必要。

## 比較した選択肢

- **外部 API は一切採用しない**: 完全オフラインは保てるが、品質改善の余地を捨てる。
- **失敗時にローカル自動フォールバック許容**: 操作は楽だが、外部選択の意図を曖昧にしユーザー期待を裏切る恐れ。
- **API キーを電子メモ程度の暗号化で JSON に保存**: 実装は楽だが、マスターキー漏洩で全鍵漏出。OS キーチェーン採用で却下。
- **生成も応援も全部外部 API 化**: 応援フェーズの常時通信が発生し、KeyCheer のコンセプトに反する。

## 関連 ADR への影響

- **ADR 0002 (Ollama)**: 撤回しない。`local-ollama` として既定値かつ選択肢の一つになる。
- **ADR 0003 (VOICEVOX)**: 撤回しない。`local-voicevox` として既定値かつ選択肢の一つになる。
- **ADR 0005 (sd.cpp + LCM)**: 撤回しない。`local-sdcpp` として既定値かつ選択肢の一つになる。
- **ADR 0006 (速度ゾーン応援)**: 影響なし。
- **ADR 0007 (オフライン応援プール)**: 維持。プール生成・音声合成・画像生成の**手段**だけプロバイダーに置き換わる。応援発動経路には何も影響しない。

## 未確定事項 [要確認]

- MVP に含めるプロバイダーの最終セット(各 1〜2 個ずつでよいか)。
- 同意ダイアログの粒度(プロバイダーごと / 生成ごと / 1 回だけ)。
- 概算コスト表示の有無と表現(「約 ¥XXX」)。
- プロバイダーの ToS への同意誘導フロー。
- 監査ログ(「いつ何が外部送信されたか」)を統計に残すか。
- プロキシ・社用ネット環境での通信失敗ハンドリング。
