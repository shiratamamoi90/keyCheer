# 論点 0082: 使用中のキャラクターが無いときは応援を出さない

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/cheer-trigger.md`**(ほかに `docs/character-selection.md`・`docs/pool-generation.md`・`docs/character-creation.md`・`docs/popup.md`・`docs/data-model.md`・`docs/glossary.md`・`docs/overview.md` の文言)

## 何を決めるか

人間の報告(2026-11-27):「キャラクターを作成していない、選択していない時でもセリフが画面に表示される。キャラクター選択時のみに修正」。

今の決まりでは、使用中のキャラクターが無いとき(`activeCharacterId` が未設定 / 指す先が `characters` に無い)も
baseline 定型文で応援し、セリフを画面に出す(`docs/character-selection.md` S0032_15、`docs/data-model.md`「使用中のキャラクター」)。
音声は無く、画像も無いので、文字だけが出る。これを「使用中のキャラクターがあるときだけ応援を出す」に変えるかを決める。

あわせて、**使用中のキャラクターはあるがプールがまだ無い**(生成前・生成の途中・失敗)ときの扱いも決める。
今は定型文で応援し、待機画像があれば待機画像を出す(`docs/popup.md` S0036_22)。

## 案

| | 案A:使用中が無ければ出さない。プールが無くても使用中があれば定型文で出す | 案B:使用中にプールがあるときだけ出す |
|---|---|---|
| 作っていない・選んでいないとき | 出さない | 出さない |
| 使用中はあるがプールが無いとき | 定型文で出す(今どおり。待機画像があれば出す) | 出さない |
| 報告との対応 | 「選択時のみ」をそのまま写す | 「選択していて生成も済んだときのみ」に広げて読む |
| 変える範囲 | S0032_15 の前半だけ | S0032_15 と S0036_22 |

どちらの案でも変えないもの:キーの数え方と累計(`stats.totalKeyCount`)は今までどおり進める。
50 回ごと・節目の判定も今までどおり進み、出さないのは応援の表示と通知だけ(使用中を選んだ後、続きの回数から出る)。

## 現在の考え

エージェントは案Aを推した(選んだ直後にも反応があり、選べたことが分かる)。人間は案Bを選んだ(2026-11-27)。

## 決定

**案B。使用中のキャラクターにプールがあるときだけ応援を出す**(人間の決定 2026-11-27)。

1. 使用中のキャラクターが無い(`activeCharacterId` が未設定 / 指す先が `characters` に無い)とき、
   使用中のキャラクターにプールが無い(生成前・生成の途中で 1 文も無い・生成の失敗・中身が空で破棄した)ときは、
   応援を出さない(ポップアップへ通知せず、セリフも音声も出さない)。
2. キーは今までどおり数え、累計(`stats.totalKeyCount`)も進める。50 回ごと・節目の判定に使う回数も進むので、
   プールのあるキャラクターを使用中にしたら、続きの回数から応援が出る。出さなかった応援を後からまとめて出さない。
3. プールがあれば、バケットが欠けているときの同梱 baseline 定型文への退避(S0013_09)は今までどおり。
   baseline 定型文は「バケットが欠けたときの補い」としてだけ残る。
4. 常時表示の待機画像は今までどおり(使用中のキャラクターに待機画像があれば、プールが無くても出す)。出さないのはセリフの応援だけ。
5. S0013_11 にあった「キャラ作成を促す通知」は実装されていなかった。応援を出さないので、この通知も設けない。

シナリオ:`docs/cheer-trigger.md` S0082_01〜02 を足し、S0013_11・S0020_09・S0032_15 は ID を保って文言を直す
(使用中のキャラクターが無いときの扱いという主題は残るため)。S0032_07・S0020_03・S0019_09・S0036_21・S0036_22 も文言だけ直す。

## 理由

- 人間の報告「キャラクターを作成していない、選択していない時でもセリフが画面に表示される」。キャラクターの絵も声も無い文字だけの応援は、
  このアプリの応援として望まれていない。
- 生成前のキャラクターで定型文を出すと、そのキャラクターの言葉ではない文が、そのキャラクターの応援として出る。
  生成が済むまで出さないほうが、出る文がいつもそのキャラクターのものになる。
- 判定は「プールがあるか」1 つで済む(使用中が無ければプールも無い)。core の `onKeyPress` が受け取るプールの有無だけで決まり、決定的。

## 却下した案

- 案A(使用中のキャラクターがあればプールが無くても定型文で出す)— 人間が案Bを選んだ。
  生成前のキャラクターに、そのキャラクターのものではない定型文を言わせることになる。
- 出さなかった応援を、プールができたときにまとめて出す — 打鍵の今の様子と関係のない応援になる。報告にも無い。

## 決まらなかったこと(次の論点へ)

- なし。
