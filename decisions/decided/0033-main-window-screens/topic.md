# 論点 0033: メインウィンドウを「保存」「生成」「切り替え」の 3 画面に分ける

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/main-window.md`・`docs/character-selection.md`・`docs/popup.md`**

## 何を決めるか

人間の方針(2026-10-31):メインウィンドウを次の 3 画面に分ける。

1. **保存画面** — 設定(名前・性格・話者)を入力して保存する
2. **生成画面** — 保存した設定から 1 つ選び、メッセージと音声を生成する
3. **切り替え画面** — 生成済みの設定から 1 つ選び、応援ポップアップに使うメッセージと音声を切り替える

いまは 1 画面にフォームと生成ボタン・進捗が同居している(論点 0019 / 0020)。
**前提は論点 0032**(複数保存・アクティブの切り替え)。0032 が決まってから決める。

見た目・レイアウトは仕様化しない(デザイン判断。`docs/character-creation.md` と同じ)。
ここで決めるのは**画面の間の遷移と、各画面で何ができて何ができないか**。

## 案

| | 案A: タブ(3 画面を常に切り替えられる) | 案B: 順に進む(保存 → 生成 → 切り替え) |
|---|---|---|
| 生成済みの設定を切り替えるだけの利用 | 直接切り替え画面を開ける | 毎回たどる必要がある |
| 初回の迷いにくさ | 何から始めるかを示す工夫が要る | 迷わない |
| 実装 | 画面ごとに独立 | 遷移の状態を持つ |

## 決めるべき細目

1. **起動時・トレイから開いたときに最初に出す画面。** 設定が 0 件なら保存画面、生成済みがあれば切り替え画面、など。
2. **生成中に他の画面へ移れるか。** 移れるなら進捗はどこに出すか。生成中の中断(S0020_06)はどの画面から行うか。
3. **各画面で選べないもの [否定]。** 生成画面で未保存の入力は選べない / 切り替え画面にはプールが無い設定を出さない
   (または選べない形で出す)、など。
4. **未作成のまま閉じたときのダイアログ**(S0018_06)の判定は 0032 の `hasCharacter` に従う。

## 決定

案A(タブ)。メインウィンドウを **「保存」「生成」「切り替え」「設定」の 4 タブ**にし、いつでも行き来できる。

1. **最初に出す画面は状態で決める**(起動時の自動表示・トレイから非表示 → 表示にしたとき)。
   キャラクターが 0 件なら保存、プールのあるキャラクターが 1 件以上なら切り替え、
   保存済みでもプールのあるものが無ければ生成。
2. **生成中もほかの画面へ移れる。** 移っても生成は続く。進捗の表示と中断(S0020_06)は生成画面だけで行い、
   ほかの画面では生成タブに「生成中」とだけ示す。
3. **各画面で選べないもの。** 生成画面で選べるのは保存済みのキャラクターだけ(保存画面の未保存の入力は選べない)。
   切り替え画面にはプールの無いキャラクターを出さない。生成中で前回のプールがあるものは、選べない形で出す。
4. **設定タブ**に、論点 0032 の「生成が完了したら自動で使用中にする」(`generation.shouldActivateOnComplete`)を置く。
5. 未作成のまま閉じたときのダイアログ(S0018_06)は、論点 0032 の `hasCharacter`(1 件以上)に従う。

## 理由

- 一番多い利用は「生成済みの設定を選び直すだけ」。タブなら切り替え画面を直接開ける(案B は毎回たどる)。
- 初回の迷いは、最初に出す画面を状態で決めることで補う(0 件なら保存画面から始まる)。
- 生成は数分かかるので、待つ間に別の設定を保存・切り替えできるほうがよい。中断を生成画面に絞るのは、
  どの生成を止めるのかが進捗と同じ場所で分かるようにするため(生成は同時に 1 件 = 論点 0032)。
- 設定を 4 つ目のタブにするのは、トリガー設定など今後の設定項目を同じ場所に足せるため。
- 切り替え画面は「使えるものから選ぶ」画面なので、使えない(プールの無い)ものは並べない。
  生成中のものだけ選べない形で出すのは、前回のプールで使用中のまま再生成している場合に、一覧から消えると
  使用中が見えなくなるため。

## 却下した案

- **案B(保存 → 生成 → 切り替えの順に進む)** — 選び直すだけの利用で毎回回り道になる。
- **最初の画面を前回開いていた画面にする** — 状態が変わっても(全部削除した等)前回の画面が出て、
  何から始めるかが分からなくなる。保存する状態も 1 つ増える。
- **いつも保存画面から始める** — 一番多い「選び直すだけ」で毎回タブを移る手間が出る。
- **生成中は生成画面に留める** — 数分間ほかの操作ができない。S0032_14(生成中でも他へ切り替えられる)を
  画面で殺してしまう。
- **設定を生成画面のチェックボックスにする** — 今後の設定項目の置き場がまた要る。
- **切り替え画面にすべてのキャラクターを選べない形で出す** — 10 件のうち使えるものが埋もれる。
  未生成のものは生成画面で見える。

## 決まらなかったこと(次の論点へ)

- タブを移ったときに、保存画面の書きかけの入力を残すか。見た目と使い勝手の判断なので仕様化しない
  (実装で決め、困ったら論点を開く)。
- 設定タブに足すほかの項目(トリガー設定・ポップアップの表示時間)は、`work/` のトリガー設定 UI と
  設定 UI の作業で扱う。ここでは置き場だけ決めた。
