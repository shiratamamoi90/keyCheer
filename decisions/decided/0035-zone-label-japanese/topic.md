# 論点 0035: ゾーンの行を、英語のゾーン名を使わずに書く

- **種別: 非決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`**(システムプロンプトのテンプレートと S0035_01〜03)

## 何を決めるか

論点 0021 で、システムプロンプトのゾーンの行(「速度ゾーンでテンション調整: slow=寄り添う / normal=標準 /
fast=勢いを煽る」)は残すと決めた。テンションの差を作っているため。
一方で、この行の英語のゾーン名 `slow` / `normal` / `fast` が、9.7% のバケットで応援文に漏れている
(`-slow--` だけの文など。層 3 を通っても残り、プールに入りうる)。

行を消すと漏れは 0 になったが、テンションの差も消えた(論点 0021 の `result.md`)。
**ゾーン名を英語のラベルで書かず、日本語の文で伝えれば、漏れを消しつつ差を保てるか**を測って決める。

## 案

| | baseline: zone_line(現行) | variant: zone_sentence |
|---|---|---|
| ゾーンの行 | 「速度ゾーンでテンション調整: slow=寄り添う / normal=標準 / fast=勢いを煽る」(3 ゾーンを英語名で並べる) | そのバケットのゾーンだけを日本語の 1 文で書く(下) |
| バケットキー `{slow_regular_morning}` 等 | 渡す | 渡す(同じ) |
| 仮説 | — | 英語のラベルが無いので漏れが消える。そのバケットの調子だけを書くので、テンションの差は保たれる |

variant の文(ゾーンの行と同じ位置に置き換える):

- slow:「いまは打つのがゆっくりなときです。寄り添うように応援してください。」
- normal:「いまはふつうの速さで打っているときです。いつもの調子で応援してください。」
- fast:「いまは速く打っているときです。勢いを煽るように応援してください。」

測らなかった別案:3 ゾーンを並べたまま名前だけ日本語にする(「ゆっくり=寄り添う / ふつう=標準 / 速い=勢いを煽る」)。
バケットキーは英語の `slow` のままなので、モデルがキーと日本語の名前を結び付けられるかが別の不確かさになる。
zone_sentence で足りなければ測る。

## 測り方

- 振る変数:ゾーンの行の書き方だけ(`axis: prompt`。案は `src/eval/promptVariant.ts`)。
- 評価データ・モデル・試行・シードは論点 0021 と同じ:24 バケット × 評価用キャラクター 3 種 × 5 回 = 各案 360 バケット、
  sarashina2.2-3b-instruct(Ollama、q4_K_M)、temperature は Ollama 既定、seed 42(試行 i は seed + i)、構造化出力あり、
  ランタイムは compose.yaml の ollama(digest 固定、CPU)、依存は `package-lock.json`。
- 主指標:**ゾーン名の漏れ**(層 3 の後の文に `slow` / `normal` / `fast` が大文字小文字を問わず含まれる文の率と、
  それを含むバケットの率)。生記録から数える。
- 副指標:**ゾーンの差**(論点 0021 と同じ数え方。1 文あたりの「!」の数、勢いの語・寄り添う語を含む文の率を
  ゾーン別に)。あわせて見本を並べ、人間が判断する。
- 自動指標:30 字超過率・失敗バケット率・件数充足率・日本語の文の率・書式混入率・平均レイテンシ(論点 0026 と同じ集計)。
- 計測コマンド:`npm run eval -- decisions/undecided/0035-zone-label-japanese`

## 中止条件

- variant でもゾーン名の漏れが baseline と同程度に残るなら、この書き方は捨てる(上の別案に進むか、現行のまま)。
- variant の契約違反(30 字超過率・失敗バケット率)が baseline より明らかに悪化したら、現行に戻す。

## 決定

zone_sentence を採る。システムプロンプトのゾーンの行を、そのシナリオの速度ゾーンだけを日本語で書いた 1 文に置き換える
(文言は `docs/integrations.md`)。

## 理由

- ラベルの写し(`-slow--` 形)が 0 件になり、ゾーン名を含むバケットは 9.7% → 3.1%(`result.md`)。
  残りは英語の文の中の `slowly` / `fastest` で、プロンプトの写しではない。
- ゾーンの差は現行より強くなった(「!」の数 slow 0.20 → fast 1.11、現行 0.40 → 0.77)。論点 0021 で行を残した理由
  (テンションの差)を損なわない。
- 悪化(30 字超過 2.8 → 4.8%、失敗 0.8 → 1.1%、日本語の文の率 90.7 → 88.7%、+0.7 秒/バケット)は小さく、
  30 字超過は層 3 が切り詰める。中止条件の「明らかな悪化」には当たらないと人間が判断した(2026-10-31)。

## 却下した案

- zone_line(現行のまま)— 英語のゾーン名が 9.7% のバケットで応援文に漏れ、プールに入りうる(論点 0021・本論点の `result.md`)。
- 3 ゾーンを並べたまま名前だけ日本語にする案(測らずに保留)— zone_sentence で漏れが消え、差も強まったので測る理由が無くなった。
  シナリオキーの英語のゾーン名と日本語の名前を結び付けられるかが別の不確かさになる。

## 決まらなかったこと(次の論点へ)

- 応援文に英語の文・語が混ざる(両案とも 12〜14% の文)。今回の変数とは別の傾向。気になったら論点を開いて測る
  (今は開かない。人間の判断を待つ)。

## 現在の考え

**2026-10-31 に計測し(`result.md`)、人間の判断で zone_sentence を採った(上の「決定」)。**
zone_sentence でラベルの写し(`-slow--` 形)は消え、ゾーン名を含むバケットは 9.7% → 3.1%(残りは英語の文の中の
`slowly` / `fastest`)。ゾーンの差は現行より強くなった。契約違反はわずかに悪化(30 字超過 2.8 → 4.8%)。
アプリの `buildSystemPrompt` への反映は `docs/integrations.md` の S0035_01〜03 をもとに作業を切って行う。
