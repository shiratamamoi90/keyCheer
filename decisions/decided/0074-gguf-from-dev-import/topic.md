# 論点 0074: 配布する GGUF は、開発機の取り込みから取り出す

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `decisions/decided/0059-text-model-bundle-form/config.yaml`**(配布物の作り方。GGUF の sha256 を記す)

## 何を決めるか

論点 0059 は配布するテキストモデルを q4_K_M の GGUF 1 ファイルとし、sha256 はビルドで作った物から固定するとした。どう作るか。

## 案

| | 案A:開発機の取り込みから取り出す | 案B:llama.cpp で変換・量子化 |
| --- | --- | --- |
| 試してきた物と | 同じファイル(層 `sha256:60e33bab…6b959`) | 同じになる保証が無い |
| ビルドの道具 | 増えない | llama.cpp が要る |

## 決定

人間が選んだ(2026-11-25):**案A**。1 は人間の選択、2〜3 はエージェントが補い、人間が承認した(2026-11-25)。

1. 開発機の Ollama(compose。`npm run services:model` で取り込んだもの)のモデル `sarashina2.2-3b-instruct` の q4_K_M の層を、スクリプトでコンテナの外へコピーし、
   `sarashina2.2-3b-instruct-q4_K_M.gguf` にする。
2. 層の sha256 は論点 0030 の 2 回の取り込みが出した `60e33bab403b69d923fef2bbbaf798adf1ba47cd897dfdf815bf85f433b6b959` に固定し、取り出した物がこれと一致しなければ止める。
   この値を論点 0059 の `config.yaml` に記す(0059 決定 3)。
3. 置き先は git に入らない配布物の置き場(`release/weights/`)。

## 理由

- 計測で使ってきたモデルと全く同じファイルを配れる。ビルドの道具が増えない。

## 却下した案

- 案B — 試してきた物と同じになる保証が無く、llama.cpp を足すことになる。

## 決まらなかったこと(次の論点へ)

- なし。
