# 結果(2026-11-11 計測)

同じ実行の中で両候補を測った(`npm run eval -- decisions/decided/0041-image-base-model`)。
評価用キャラクター 3 種 × 画像の種類 3(待機・`regular`・`milestone`)× 2 試行 = 候補ごとに 18 枚、計 36 枚。
条件は `config.yaml`(512x768・4 ステップ・LCM LoRA・サンプラー lcm・CFG 1・量子化なし・CPU・seed 42 と 43)。
画像タグは先に 18 ケース分を作って保存し、両候補で同じものを使った(タグの失敗 0)。

ベースモデルは決めず、作り方を変えて測り直す(論点 0045)。以下は判断の前に書いた記述。

**立ち絵として使えるか・3 枚が同じキャラに見えるかは、人間が全ケースを見て決める。**

エージェントが見たのは 36 枚のうち 10 枚(各候補 5 枚)だけで、判断の代わりにはならない。見た範囲の事実だけを書く。

- MeinaMix V10:5 枚とも人物が描かれた。1 枚(レン・`milestone`・試行 0)は同じ人物が 2 人並んだ。
  1 枚(チア・待機・試行 0)は服に意味の無い文字が入った。
- 線と塗りは MeinaMix のほうが整って見え、Counterfeit は絵画風で崩れが大きい、という印象(10 枚の範囲)。

## モデルの差ではない問題(両候補に共通)

1. **同じキャラクターの 3 枚が、同じ人物に見えない。** 見た範囲では、同じキャラクターでも画像の種類によって髪の色・髪型・服が
   変わった(例:チアの待機と `regular`、レンの待機と `regular` と `milestone`)。論点 0036 は「同じシード + 画像タグの差し替え」で
   同じキャラにする狙いだったが、画像タグが見た目(髪・服)を含まないので、タグが変わると別人になる。
2. **画像タグが、画像モデルの書き方になっていない。** テキストモデルが返したタグは `CheerfulLeader stance` や
   `Smiling-But-With-A-Wink` のような独自の語で、キャラクターの名前がそのまま入ることもある(`Calm and Respectful Sizuku`)。
   人物を指す語(`1girl` など)や画質を指す語が無いので、人物が描かれない絵(上の Counterfeit の 1 枚)が出うる。
3. **いまの `local-sdcpp` の実装は LCM LoRA が効かない。** サンプラーと CFG を渡しておらず、プロンプトに `<lora:名前:1>` も
   足していない。計測ではこの 2 つを計測ドライバの側で補った。

1 と 2 は画像タグの出させ方(論点 0036 の案P1 と `docs/integrations.md`「画像タグの要求」)の問題で、ベースモデルを
どちらにしても残る。3 は実装の抜け。

## 計測環境で分かったこと

- 公式の Linux 向け配布物(`master-1086-465adf3`)は Ubuntu 26.04 でビルドされており GLIBC 2.43 を要求する。
  開発機(Ubuntu 24.04・GLIBC 2.39)ではそのまま動かないので、Ubuntu 26.04 のコンテナの中で動かした
  (`scripts/image-eval.Dockerfile`)。論点 0040 の決定 5(開発機に Linux 版を取る)は、そのまま起動できる前提だった。

## 再現のしかた

1. `bash scripts/fetch-image-eval.sh`(sd.cpp と重みを取得し sha256 を照合。計測用コンテナも作る。約 5.5 GB)
2. `npm run services:up`(画像タグ用の Ollama。モデルは `npm run services:model`)
3. `npm run eval -- decisions/decided/0041-image-base-model`

依存は `package-lock.json`、sd.cpp・重み・コンテナのベースは `config.yaml` のタグ・コミット・sha256・digest で固定。
