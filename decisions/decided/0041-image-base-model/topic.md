# 論点 0041: ローカル画像生成のベースモデルをどれにするか

- **種別: 非決定的**
- **状態: 決定済み**
- **反映先: —**(決めた値はモデルの取得元とハッシュで、取得物は論点 0042、置き場は論点 0040 が `docs/` に反映する)

## 何を決めるか

論点 0005 は「SD1.5 アニメ系(AnythingV5 / MeinaMix / Counterfeit V3 等から実装時に確定)+ LCM LoRA、4 ステップ」と決め、
ベースモデルの最終選定と量子化を宿題に残した。論点 0036 も、画像の品質は非決定的なので別の論点で測るとした。
ここで、`local-sdcpp` が使うベースモデルを 1 つに決める。

絵の良し悪しは指標と目視でしか測れないので、計測で決める。振る変数は**ベースモデルだけ**にする。
量子化の形式・LCM LoRA の版・ステップ数・画像タグの出させ方(論点 0036 で決定済み)は固定する。
量子化も振りたくなったら、モデルが決まったあとに別の論点にする。

## 案

候補は論点 0005 が挙げた 3 つ。配布元を確かめて 2 つに絞った(下の「確かめたこと」)。

| | Counterfeit V3.0 | MeinaMix V10 | AnythingV5 |
|---|---|---|---|
| 公式の配布元 | Hugging Face `gsdf/Counterfeit-V3.0`(コミット `d8ce63b3`) | Hugging Face `Meina/MeinaMix`(コミット `ff1db136`) | Hugging Face に作者本人のリポジトリが見当たらない(再配布だけ) |
| ライセンス | CreativeML OpenRAIL-M | CreativeML OpenRAIL-M | 再配布のものは CreativeML OpenRAIL-M |
| 使うファイルとサイズ | `Counterfeit-V3.0_fix_fp16.safetensors` 2034 MB | `Meina V10 - baked VAE.safetensors` 3363 MB | — |
| 測るか | 測る | 測る | 測らない(公式の配布元を固定できない) |

LCM LoRA は Hugging Face `latent-consistency/lcm-lora-sdv1-5`(コミット `cf2fced5`、`pytorch_lora_weights.safetensors` 128 MB、
ライセンス OpenRAIL++)に固定する。

## 確かめたこと(2026-11-11。Hugging Face の公式のリポジトリ)

- 上の表の配布元・コミット・ファイル・サイズ・ライセンスの表記。sha256 は Hugging Face が持つ値を `config.yaml` に書く。
- CreativeML OpenRAIL-M / OpenRAIL++ は、利用の制限を引き継ぐことを条件に再配布を認める形のライセンス。
  利用者には公式のリポジトリから直接取得させるので、自分たちでホストはしない。表記は論点 0043 の表示に足す。
  **ライセンスの本文はまだ読んでいない**(表記を確かめただけ)。決定の前に読む。
- **今の `local-sdcpp` の実装は、サンプラーとガイダンスの強さ(CFG)を sd.cpp に渡していない。** LCM LoRA は
  LCM 用のサンプラーと低い CFG(1.0〜2.0)を前提にするので、既定のままでは 4 ステップでまともな絵にならない見込み。
  計測ではこの 2 つを全候補で固定して渡し、決めた値は実装の定数にする(実装の変更は着手の許可を取ってから)。

## 計測の前に確かめること(決定的。計測ではない)

- **ライセンス。** 利用者の機械に取得させてよいか、自分たちでホストしてよいか(論点 0042 の取得元に効く)。
  条件を満たさない候補は測らずに外し、`却下した案` に理由を残す(モデルにも出所の審査を行う。
  @.claude/rules/security-rules.md「LLM を組み込むときの最低限」)。
- **版の固定。** 取得元・コミット・sha256 を `config.yaml` に書けること。固定できない候補は測らない。

## 測り方

- 振る変数:ベースモデルだけ。
- 評価データ:評価用キャラクター 3 種(論点 0021 以降の計測と同じプロフィール)× 画像の種類 3(待機・`regular`・`milestone`)。
  画像タグは、一度テキストプロバイダーに出させたものを保存し、**全候補で同じタグを使う**
  (タグの揺れをモデルの差に混ぜない)。
- 試行数・シード:`config.yaml`。シードは固定し、試行 i は seed + i。
- 主指標:**人間が見て立ち絵として使えるか**(候補ごとに同じキャラ・同じ種類の画像を並べて判断する)。
  あわせて、3 枚が同じキャラに見えるか(同一シード + タグ差し替えの狙い)。
- 自動指標:1 枚あたりの生成時間(CPU / 使えれば iGPU)、失敗率(タイムアウト・異常終了)、最大メモリ。
- 固定するもの:sd.cpp の版(論点 0040)、LCM LoRA の版、4 ステップ、512x768、量子化の形式、依存(`package-lock.json`)。
- 計測ドライバ:`src/eval/imageModelComparison.ts`(`axis: image_model`。人間の許可を得て追加した)。
- 計測コマンド:`npm run eval -- decisions/decided/0041-image-base-model`

## 中止条件

- CPU で 1 枚あたりの時間が、3 枚の生成を待てない長さになる候補は、その候補の計測を打ち切る
  (上限の値は baseline を測ってから決める)。
- 全候補が立ち絵として使えないと判断したら中止し、ローカル画像生成を既定から外すか(外部だけにするか)を
  別の論点で問い直す。それまでは今のまま(`local-sdcpp` は組み立てず、画像なしで生成を終える)。

## 計測の前に確認を求めていたこと(どちらも済んだ)

- 人間が全ケースを見て、どちらを採るかを決める → 下の「人間の判断」。
- CreativeML OpenRAIL-M / OpenRAIL++ の本文の確認 → 下の「ライセンスの本文を読んだ結果」。

## 人間の判断(2026-11-11)

計測の条件:baseline は Counterfeit V3.0、量子化はしない、サンプラーは lcm、CFG は 1、候補ごとに 18 枚。

## 人間の判断(2026-11-13)

36 枚を見て、**どちらのモデルも立ち絵として使えない**。ベースモデルは決めず、絵の作り方を変えて測り直す
(背景なし・キャラクター以外は透明・5 色・待機画像から派生)→ 論点 0045。

## 人間の判断(2026-11-13。論点 0045 の 2 回目の計測を見て)

**Counterfeit V3.0 を採用する。** メモリ・速さ・重みの大きさも込みで決めた(材料は論点 0045 の `result.md`
「ベースモデルを選ぶための材料」:速さは同じ、MeinaMix は重みが 1329 MB・最大メモリが 578 MB 多い)。

## ライセンスの本文を読んだ結果(2026-11-13。エージェントの読み)

読んだもの:CreativeML Open RAIL-M(2022-08-22 付。Hugging Face `CompVis/stable-diffusion-license` の `license.txt`)と
CreativeML Open RAIL++-M(2023-07-26 付。`stabilityai/stable-diffusion-xl-base-1.0` の `LICENSE.md`)。
モデルカードのライセンスの表記は、固定したコミットで Counterfeit V3.0 が `creativeml-openrail-m`、LCM LoRA が `openrail++`。

- **使うこと・アプリに組み込んで使わせることは認められている**(定義「You」に end-use application での利用が入っている。
  2 項で複製・配布・サブライセンスを無償で許諾)。商用かどうかの制限は本文に無い。
- **作った絵について、ライセンサーは権利を主張しない**(6 項)。絵とその使い方の責任は作った人にある。
- **利用の制限(別紙 A)がある**:違法な利用、未成年者を害する利用、人を害する目的の偽情報、個人を害しうる個人情報、
  中傷・嫌がらせ、差別、医療の助言、司法・法執行・入国管理のための情報 など。**KeyCheer の使い方(キャラクターの立ち絵)は当たらない。**
- **5 項は「自分の利用者にも 5 項(利用の制限)を守らせること」を求めている。** アプリが利用者にモデルを使わせるので、
  重みを取得する前に、ライセンスと利用の制限を利用者に示す必要がある(論点 0043 の表示・論点 0042 の取得前の案内に足す)。
- **配布の条件(4 項)**:モデルを第三者に配るなら、利用の制限を引き継ぐ条項を付ける・ライセンスの写しを渡す・変更したら明示する・
  著作権などの表示を残す。**KeyCheer は重みを配らない**(利用者が公式のリポジトリから直接取得する)ので、4 項の配布には当たらない読み。
  自分たちでホストする(変換・量子化した重みを配る)ことにしたら 4 項を満たす必要がある。
- **OpenRAIL-M の 7 項**:ライセンサーはライセンス違反の利用を制限でき、モデルを更新でき、利用者は「最新版を使うよう合理的に努める」。
  コミットを固定して取得する方針と向きが違う。固定は再現性と改ざんの検出のためで、作者が版を改めたら追随を検討する、という扱いにする。
  OpenRAIL++ にはこの「最新版」の文は無い。
- **残る不確かさ**:Counterfeit V3.0 は複数のモデルを混ぜて作られていて、もとのモデルの条件までは追えていない。
  リポジトリにライセンスの本文のファイルは無く、モデルカードの表記だけ。作者の Civitai の頁の条件は確かめていない。
  **これはエージェントの読みで、法的な確認ではない。配布の前に人間が原文を読んで確かめる**(論点 0043 と同じ扱い)。

## 決定

`local-sdcpp` のベースモデルは **Counterfeit V3.0** にする。LCM LoRA と合わせて使う。取得元と版は次のとおり(sha256 は `config.yaml`)。

| | 取得元(Hugging Face) | コミット | ファイル | 大きさ | ライセンス |
| --- | --- | --- | --- | --- | --- |
| ベースモデル | `gsdf/Counterfeit-V3.0` | `d8ce63b3` | `Counterfeit-V3.0_fix_fp16.safetensors` | 2034 MB | CreativeML OpenRAIL-M |
| LCM LoRA | `latent-consistency/lcm-lora-sdv1-5` | `cf2fced5` | `pytorch_lora_weights.safetensors` | 128 MB | OpenRAIL++ |

サンプラーは lcm、CFG は 1、量子化はしない(配布物のまま)。利用者には公式のリポジトリから直接取得させ、自分たちではホストしない。

**この論点の計測の条件(全身・4 ステップ・3 枚とも文字から作る)は、実際の使い方と違う。** 実際の作り方は論点 0045 が決めた
(腰から上・白の下地・待機画像から派生・7 色)。モデルの選定は、0045 の 2 回目の計測(新しい作り方での両モデルの絵・時間・メモリ)を見て人間が行った。

## 理由

- 人間の判断(2026-11-13):メモリ・速さ・重みの大きさも込みで Counterfeit V3.0。
- 速さは両モデルで同じ(新しい作り方で 3 枚 約 213 秒と約 211 秒)。MeinaMix V10 は重みが 1329 MB、最大メモリが 578 MB 多い。
  利用者が取得する量と、メモリの小さい機械での余裕は Counterfeit のほうがよい。
- 取得元・コミット・sha256 を固定できる(公式のリポジトリがある)。
- ライセンスは、使うこと・組み込んで使わせることを認めていて、KeyCheer の使い方は利用の制限に当たらない(上の読み)。
- 絵は、エージェントが見た範囲では MeinaMix のほうが線と塗りが整っていた。それでも Counterfeit を採ったのは、絵の差より
  取得する量とメモリを重く見た人間の判断。

## 却下した案

- **MeinaMix V10** — 絵は整っているが、重みが 1329 MB・最大メモリが 578 MB 多く、速さは同じ。
  半精度に変換すれば縮む可能性はあるが確かめていない(変換した重みを配るなら、自分たちでホストすることになり、ライセンスの 4 項が掛かる)。
- **AnythingV5** — 作者本人の公式のリポジトリが見当たらず(再配布だけ)、取得元を固定できない。測っていない。

## 決まらなかったこと(次の論点へ)

- **画像の重みのライセンスの表示と、取得前の案内**(決定的。論点 0047 として開いた):`docs/licenses.md` の「画像の重み」の行、
  取得を始める前に利用の制限を示すこと、`docs/model-weights.md` の取得元。
- 量子化・半精度への変換(メモリと取得する量を減らす)。必要になったら別の論点。自分たちでホストすることになる点に注意。
- `local-sdcpp` がサンプラー・CFG・LoRA を sd.cpp に渡していない実装の抜けは、論点 0046(作り方の要件)で扱う。
- 配布の前に、人間がライセンスの原文と作者の頁の条件を読んで確かめる。
