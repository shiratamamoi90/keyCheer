# 論点 0047: 画像の重みのライセンスの表示と、取得前の案内を要件に足す

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/licenses.md`**(S0047_01〜11。あわせて S0043_01 と表の「画像の重み」の行)・**`docs/model-weights.md`**(取得元の表・S0048_02 の文言)・**`docs/data-model.md`**(ライセンスへの同意の記録の項目)・**`docs/glossary.md`**(ライセンスへの同意・利用の制限)

## 何を決めるか

論点 0041 で、ローカル画像生成のベースモデルを Counterfeit V3.0(CreativeML OpenRAIL-M)+ LCM LoRA(OpenRAIL++)に決めた。
論点 0043 は、画像の重みのライセンスの表示を「論点 0041 が決まってから足す」として空けてある(`docs/licenses.md`)。
論点 0042 は重みの取得を決めたが、画像の重みの取得元と版は 0041 待ちだった。ここでその 2 つを埋める。

ライセンスの 5 項は「自分の利用者にも利用の制限を守らせること」を求めている(論点 0041「ライセンスの本文を読んだ結果」)。
アプリは重みを配らないが、利用者にモデルを使わせるので、利用の制限をいつ・どう示すかを決める必要がある。

決めること:

1. アプリ内のライセンスの表示に、画像の重み(ベースモデルと LCM LoRA)の何を示すか(名前・作者・ライセンス名・本文への参照・利用の制限)。
2. 画像の重みの取得を始める前に、ライセンスと利用の制限を示すか。示すなら、同意を求めるか、示すだけか。
3. 取得元・コミット・ファイル・sha256 を要件のどこに書くか(論点 0042 のモデル定義との関係)。
4. 作者が版を改めたときの扱い(OpenRAIL-M の 7 項「最新版を使うよう努める」と、コミットの固定との折り合い)。

## 人間の判断(2026-11-13)

1. **インストールの前に、ライセンスと利用の制限を表示して、同意を取る。**
2. 同意を求めるのは、**インストーラで画像の重みを選んだ人だけ**。選ばない人には求めない。
3. インストールのあと、アプリの設定画面から画像の重みを取得するときも、**同じ表示と同意を求める**。同意済みの人にはもう一度は求めない。

## 案(エージェントの提案。残りの細目。判断は人間)

| 細目 | 提案 |
| --- | --- |
| 示すもの(インストーラ・アプリの中の同意の画面) | ベースモデルと LCM LoRA それぞれの名前・配布元・ライセンス名、ライセンスの全文(CreativeML Open RAIL-M と Open RAIL++-M)、利用の制限(別紙 A)。通信せずに表示する(文面は同梱する) |
| インストーラで同意しないとき | 画像の重みを取得しない(選択を外した扱い)。インストールはそのまま進められる。テキストモデルの取得には影響しない |
| アプリの中で同意しないとき | 取得を始めず、通信しない。設定画面の取得の操作は残り、あとで同意すれば取得できる |
| 同意の記録 | 同意したことと日時を設定に残す。インストーラで同意した人は、アプリの中で同意済みとして扱う。外部プロバイダーへの送信の同意・監査ログとは別のものとして持つ |
| 同意の取り消し | 取り消す操作は設けない(アンインストールで記録ごと消える。論点 0048) |
| 設定画面のライセンスの表示(論点 0043) | 「画像の重み」の行を埋める:名前・配布元・ライセンス名・ライセンスの全文・利用の制限。重みを取得していない人にも表示する(S0043_05 と同じ)。S0043_01 の「画像の重みを除く」を外す |
| 取得元の書き場所 | `docs/model-weights.md` に、リポジトリ・コミット・ファイル・サイズの表を足す(論点 0041 の決定の値)。sha256 は論点 0041 の `config.yaml` を参照し、書き写さない |
| 作者が版を改めたとき | 固定した版を使い続ける。追随するかはアプリの更新のときに検討する(要件にはしない)。アプリの更新で、取得する重みかライセンスが変わったら、同意を取り直す |

## 決定

画像の重みを取得する前に、ライセンスと利用の制限を示して、ライセンスへの同意を取る。シナリオは `docs/licenses.md`(S0047_01〜11)。

1. 同意を求めるのは、画像の重みを取得しようとする人だけ。入口はインストーラ(画像の重みを選んだとき)と、アプリの設定画面(取得を始めるとき)。
2. 同意しなければ画像の重みを取得しない。インストール・テキストモデルの取得・画像なしの生成は、同意が無くてもできる。
3. 同意したことと日時と、同意した対象の版を設定に記録する。同意済みの人には求め直さない。対象の版が変わったら取り直す。取り消す操作は設けない。
4. 設定画面のライセンスの表示に、画像の重みの行を足す。取得していない人にも表示する。
5. 同意の画面も表示も通信しない(文面は同梱)。
6. 画像の重みの取得元は `docs/model-weights.md` に表で書いた。固定した版を使い続け、追随はアプリの更新のときに検討する。
7. 用語「ライセンスへの同意」「利用の制限」を用語集に足した。外部プロバイダーへの送信の「同意」とは別の語にした。

## 理由

- ライセンスの 5 項が、自分の利用者にも利用の制限を守らせることを求めている(論点 0041「ライセンスの本文を読んだ結果」)。
  示すだけでなく同意を取るのは、利用者が制限を受け入れたことを残すため(人間の判断)。
- 画像の重みを使わない人に求めないのは、関係の無い人に同意を強いないため。
- アプリの中でも求めるのは、インストーラを通らずに同意なしで取得できる道を残さないため。
- 「同意」という既存の用語は外部プロバイダーへの送信の承認を指すので、混ざらないよう別の語と別の設定項目にした。
- 対象の版を記録するのは、あとで重みやライセンスが変わったときに、前の同意を流用しないため。

## 却下した案

- インストールする全員に同意を求める — 画像を使わない人にも同意を強いる。
- アプリの中では表示だけで同意を求めない — インストーラを通らない道で、同意なしに取得できてしまう。
- 示すだけで同意を取らない(論点 0042 の「始める前にライセンスを示す」のまま)— 人間が同意を取ると判断。
- `providers.consent` に項目を足して済ませる — 送信の同意と意味が違い、監査ログとの関係もぼやける。

## 決まらなかったこと(次の論点へ)

- **ライセンスの読みはエージェントのもの。配布の前に人間が原文と作者の頁の条件を読んで確かめる。**
- 画像の重みは既に置き場にあるが、ライセンスへの同意の記録が無いとき(設定だけ消えた、など)に、生成で重みを使うかは決めていない。
- 「同意した対象の版」の値の付け方(何が変わったら版を上げるか)は実装のときに決める。変えたら同意の取り直しが起きる。
- テキストモデル(MIT)には同意を求めていない。取得元とライセンスの表示は論点 0030・0043 のまま。
