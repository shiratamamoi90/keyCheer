# 論点 0050: 画像プロバイダーの選択と、作った画像の確認を画面に出す

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/main-window.md`・`docs/pool-generation.md`・`docs/data-model.md`・`docs/glossary.md`**

## 何を決めるか

2026-11-13 の整合の確認で、画像まわりが画面にほとんど出ていないことが分かった。人間の指示:**決めた内容は UI・UX にも反映する。画像も。**
要件が既にあるもの(画像が作れなかったときの表示・生成ボタンの文言)は直した。ここでは、要件が無いものを決める。

1. **画像プロバイダーの選択。** 生成画面の「生成に使うプロバイダー」には、応援メッセージと音声の 2 つしか無い。
   画像(`local-sdcpp` / `openai-dalle` / `stability-ai`)は設定の値(`providers.image`)はあるが、画面から変えられない。
2. **作った画像の確認。** 生成が終わっても、メインウィンドウでは 3 枚の画像を見られない。キャラの窓に待機画像が出るだけで、
   `regular`・`milestone` の画像は応援が出るまで見えない。背景の抜けそこないに気づけず、作り直すかの判断ができない。
3. **画像だけの作り直し。** 抜けそこないを見つけても、今は文言・音声ごと作り直すしかない(論点 0039 で「欠けた画像だけを補う操作は設けない」と
   決めている。見直すかどうか)。

## 案

### 1. 画像プロバイダーの選択

| | 案A:生成画面に 3 つ目の選択を足す | 案B:出さない(今のまま。既定の `local-sdcpp` 固定) |
| --- | --- | --- |
| 外部の画像を使えるか | 使える(同意ダイアログと API キーは既存の仕組みに乗る) | 画面からは使えない |
| 注意 | `openai-dalle` は 512x768 を受け付けない(既知)。外部は新しい作り方ではない(背景が透明にならない) | — |

### 2. 作った画像の確認

| | 案A:生成画面に、選んだキャラクターの 3 枚を並べて出す | 案B:切り替え画面の一覧に待機画像を小さく出す | 案C:出さない |
| --- | --- | --- | --- |
| 抜けそこないに気づけるか | 3 枚とも分かる | 待機画像だけ | 応援が出るまで分からない |
| 画面の変更 | 生成画面に画像の欄。透明が分かる下地(市松など)が要る | 一覧の項目 | 無し |

A と B は両立する。

### 3. 画像だけの作り直し

| | 案A:生成画面に「画像だけ作り直す」を足す | 案B:設けない(論点 0039 のまま) |
| --- | --- | --- |
| 抜けそこないへの手 | 画像の 3〜4 分だけで試し直せる | 文言・音声ごと作り直す(十数分) |
| 影響 | 論点 0039 を置き換える。シードが固定なので、同じ画像タグなら同じ絵になる(作り直すたびにシードを変えるかも決める必要がある) | — |

## `[要確認]`

- 1・2・3 それぞれ、どの案にするか。
- 2 の案A にするなら、画像を画面に渡す経路(専用スキームは既にキャラの窓で使っている)は作り方の話なので要件には書かない。

## 現在の考え

エージェントの考え(判断は人間):1 は案A、2 は案A + 案B、3 は案A(作り直すたびにシードを変える)。
背景の抜けそこないを「ひとまず受け入れる」と決めた(論点 0045)ので、気づけることと、安く試し直せることが要る。

**人間の判断(2026-11-21)**:
- 1 は案B(出さない)。生成をローカルだけにするため(論点 0054。0054 が決まってから確定する)。
- 2 は「選択画面に 3 枚とも出して見られるようにする」。選択画面を切り替え画面と読み、案B を 3 枚に広げたものとした。
  `[要確認]` — 切り替え画面の一覧の各項目に 3 枚を並べるのか、選んだキャラクターの 3 枚を一覧の横に大きく出すのか。
  生成画面にも出すか(案A)。

**待っているもの**:2 の上の `[要確認]` と、3(画像だけの作り直し)への人間の判断。論点 0054 の決定。

## 人間の判断(2026-11-21・続き)

- 2:切り替え画面では、一覧で**選んだキャラクターの 3 枚を横に大きく**出す。生成が終わった生成画面にも 3 枚を出す。
- 3:画像だけ作り直す操作を設ける。作り直すたびにシードを変える。シードは**キャラクターごとに記録し、作り直すたびに 1 増やす**。
  画像タグは**保存して使い回す**(作り直しではシードだけを変える)。

## 決定

1. **画像プロバイダーを選ぶ操作は出さない**(案B)。生成はローカルだけ(論点 0054)。
2. **作った画像を画面で見られるようにする。** 切り替え画面で選んだキャラクターの 3 枚(待機画像・`regular`・`milestone`)を大きく並べ、
   生成が終わった生成画面にも 3 枚を出す。透明が分かる下地に載せる。欠けた画像は、欠けていると分かるように示す(待機画像で代えない)。
3. **画像だけ作り直す操作を設ける**(案A。論点 0039 を置き換える)。3 枚を出している所(切り替え画面・生成が終わった生成画面)に置く。
   - 生成で出した画像タグ 3 つとシードを、キャラクターごとに**画像の生成記録**として保存する。
   - 画像だけ作り直すときは、記録した画像タグをそのまま使い、シードを記録の値から 1 増やして 3 枚を作る。文言・wav・プロフィールは変えない。
   - 3 枚がそろったときだけ、新しい 3 枚と新しいシードに置き換える。そろわなかった(失敗・中断)ときは前の 3 枚と記録を残す。
   - 記録の無いキャラクター(この決定より前に作ったもの)は、画像タグを出させて記録してから作る。シードは既定のシードから 1 増やす。
   - 生成(全体)は今のまま、既定のシードで作り、画像タグとシードの記録を書き直す。
   - 生成中・画像だけ作り直している間は、もう一方を始められない。画像の重みが無ければ操作は使えない。

### エージェントが補ったところ(人間の判断の範囲で決めた細部。違えば直す)

- 記録の無い古いキャラクターの扱い、失敗したときに前の 3 枚を残すこと、全体の生成ではシードを既定に戻すこと、操作を置く場所。

## 理由

- 背景の抜けそこないを「ひとまず受け入れる」と決めた(論点 0045)ので、利用者が気づけることと、安く試し直せることが要る。
- 画像だけなら 3〜4 分で済む(全体の作り直しは十数分)。
- シードを記録して 1 ずつ増やせば、同じシードで同じ絵を再現でき(再現性の不変条件)、作り直すたびに別の絵になる。
- 画像タグを使い回すと、見た目の方向(髪・服など)を保ったまま絵だけを試し直せる。
- 失敗で前の 3 枚を消すと、試し直しのせいで絵が無くなる。全体の生成(S0036_13)とは違い、プロフィールが変わっていないので前の絵が混ざる心配が無い。

## 却下した案

- **画像プロバイダーを選ぶ操作を足す(1 の案A)** — 生成をローカルだけにした(論点 0054)。
- **切り替え画面の一覧の各項目に 3 枚を並べる** — 人間が「選んだキャラクターを大きく」を選んだ。
- **作り直さない(3 の案B。論点 0039 のまま)** — 抜けそこないへの手が十数分の全体の作り直ししか無い。
- **シードを乱数で決める** — 人間が記録して 1 増やすほうを選んだ。
- **画像タグを毎回出し直す** — 時間が増え、絵の方向も変わりうる。
