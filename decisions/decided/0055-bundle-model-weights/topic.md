# 論点 0055: モデルの重みもインストーラに入れる

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/model-weights.md`・`docs/licenses.md`・`docs/data-model.md`・`docs/integrations.md`・`docs/pool-generation.md`・`docs/overview.md`・`docs/glossary.md`**(あわせて `.claude/rules/stack.md`「配布形態」・`.claude/rules/security-rules.md`)

## 何を決めるか

人間の指示(2026-11-21):**ローカルの生成に要るものをすべてアプリに含める。重みもインストーラに入れる。**

ランタイム(Ollama / VOICEVOX ENGINE / sd.cpp の CPU 版)を同梱することは、論点 0034 / 0040 で決まっている。
重みは「利用者が始めたときに取得する」と決めていて(論点 0010 / 0042 / 0048)、この論点はそこを置き換える。

同梱する重み(見込み):

- テキスト:`sarashina2.2-3b-instruct` の q4_K_M(論点 0027 / 0030。約 2 GB)
- 画像:Counterfeit V3.0 fp16(約 2.0 GB)と LCM LoRA(約 0.13 GB)(論点 0041)
- 音声:VOICEVOX の音声モデル(論点 0044。話者 4 つのぶん)

置き換えの対象:

- 論点 0042:アプリの中での取得(進捗・中断・続きから・照合・空き容量)。**画像の重みのぶんは実装済み**
  (`src/agent/imageWeightsFetch.ts` ほか、S0042_02〜06・09〜13)。
- 論点 0048:インストール中の取得(未実装)。
- 論点 0047:取得の前のライセンスへの同意。インストーラでの同意(S0047_02〜04)に一本化するかが決める点になる。
- 論点 0030:テキストモデルを自分たちの Hugging Face のリポジトリでホストすること。ホストは要らなくなり、
  ビルドの時に取得して同梱する形になる(取得元・sha256 の固定は残る)。

## 案

### 1. 画像の重みを必須にするか

| | 案A:すべて必須(1 本のインストーラ) | 案B:画像の重みは選べる部品にする(既定で入れる) |
| --- | --- | --- |
| インストーラの大きさ | 約 4〜5 GB | 外せば約 2.5 GB |
| 画像なしで生成を終える経路 | 重みが無い状態が無くなる(壊れたときだけ) | 残る |

### 2. インストーラの形

**エージェントの知識では、NSIS は 1 本のインストーラにおよそ 2 GB を超えるデータを入れられない**(electron-builder の既知の制約)。
`[要確認]` — 実際に作って確かめる必要がある。

| | 案A:インストーラ本体と、重みの別ファイル(同じフォルダに置く) | 案B:アプリだけのインストーラと、重みのインストーラの 2 本 | 案C:zip で配る(インストーラにしない) |
| --- | --- | --- | --- |
| 利用者の手間 | フォルダごと受け取る | 2 回インストールする | 解凍するだけ。ライセンスへの同意・アンインストールの仕組みが無い |

### 3. いまある「アプリの中での取得」をどうするか

| | 案A:削除する | 案B:壊れたときの取り直しとして残す |
| --- | --- | --- |
| 備考 | 通信がゼロになる。重みが壊れたら入れ直す | 実装済みのものを使える。取得元と照合の仕組みが残る |

### 4. ライセンスへの同意

| | 案A:インストーラで同意を取る(S0047_02〜04) | 案B:アプリの初回起動で同意を取る |
| --- | --- | --- |
| 備考 | 重みを置く前に同意を取れる | 同意の前に重みが置かれる |

## `[要確認]`

- 1〜4 それぞれ、どの案にするか。
- NSIS で 2 GB を超えるデータを入れられるか(実際に作って確かめる)。
- ライセンス上、Counterfeit V3.0(CreativeML OpenRAIL-M)と LCM LoRA を**再配布**してよいか。
  これまでは「取得元から利用者が取得する」前提で読んでいた(論点 0041 / 0047)。再配布になると、
  ライセンスの原文と利用の制限を一緒に配る義務を確かめ直す必要がある。**配布の前に人間が原文を読んで確かめる。**
- sarashina(MIT)と VOICEVOX の音声モデルの再配布の条件(論点 0043)。

## 人間の判断(2026-11-21)

- 1:すべて必須。 2:インストーラ本体と、重みの別ファイル。 3:アプリの中の取得は削除する。 4:インストーラで同意を取る。

## 決定

1. **ローカルの生成に要る重みを、すべて配布物に入れる。** テキストモデル(sarashina2.2-3b-instruct の q4_K_M)、画像の重み
   (Counterfeit V3.0 fp16 + LCM LoRA)、VOICEVOX の音声モデル(選べる話者の分)。どれも必須で、選んで外す部品にしない。
2. **配布物はインストーラ本体と、重みの別ファイルを同じフォルダに置いたもの。** インストーラは同じフォルダの重みを、sha256 を照合して置き場にコピーする。
   置き場は今と同じ `{userData}/weights/`(画像のファイル名は論点 0040 のまま)。
3. **重みの取得(通信)はアプリにもインストーラにも無い。** アプリの中の取得(論点 0042。画像の重みの分は実装済み)は削除し、
   インストール中の取得(論点 0048)は作らない。重みが欠けた・壊れたときは、インストーラで入れ直す。
4. **画像の重みのライセンスへの同意はインストーラで取る。** 重みを置く前にライセンスと利用の制限を示し、同意しなければインストールを進めない。
   アプリの中の同意の画面と、同意の記録(`system.imageWeightsLicenseAgreement`)は持たない。ライセンスの表示(S0047_01)は残す。
5. 重みが揃わない(別ファイルが無い・照合が通らない・空き容量が足りない)ときは、インストールを完了しない。
6. 更新のインストールで、照合の通る重みはコピーし直さない。アンインストールでアプリが保存したものをすべて消す(S0048_13 / S0048_14 は残す)。

## 理由

- 人間の方針(2026-11-21):ローカルの生成に要るものをすべてアプリに含める。取得が無くなれば、インストールの後は通信ゼロになり、
  プライバシー方針の「受け取るだけの通信」も無くなる。
- 1 本のインストーラは、NSIS が約 2 GB を超えるデータを入れられないという理解があり(**未確認。実装で確かめる**)、重みは 4〜5 GB になる。
  別ファイルにすれば、この制約があってもなくても同じ形で配れる。
- 必須にしたのは「すべて含める」の指示どおりで、画像なしで終わる経路は壊れたときだけになる。
- 同意をインストーラにすると、重みを置く前に同意を取れる(ライセンスが利用者にも利用の制限を守らせることを求めている。論点 0047)。

## 却下した案

- **画像の重みを選べる部品にする** — 人間が必須を選んだ。
- **インストーラ 2 本** — 利用者の手間が増える。
- **zip で配る** — ライセンスへの同意とアンインストールの仕組みが無い。
- **アプリの中の取得を、壊れたときの取り直しとして残す** — 取得元と照合の仕組み・通信が残る。入れ直しはインストーラで足りる。
- **アプリの初回起動で同意を取る** — 同意の前に重みが置かれてしまう。
