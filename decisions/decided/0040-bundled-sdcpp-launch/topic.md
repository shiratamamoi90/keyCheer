# 論点 0040: sd.cpp の実行ファイルをビルドに同梱して、生成の画像の工程から起動する

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`**(「画像」の節の S0040_01〜05。同梱する版と出所は本論点に残す)

## 何を決めるか

論点 0036 で、キャラ画像 3 枚を生成の中で作ると決め、テスト・実装まで済んだ。ただしローカル(`local-sdcpp`)は
実行ファイルもモデル重みも置き場が無いので組み立てておらず、選んでも画像なしで生成を終える(S0036_10)。

論点 0010 は「sd.cpp の実行ファイルは同梱する」とだけ決めている。論点 0034(Ollama / VOICEVOX ENGINE の同梱と起動)は
sd.cpp を対象外にしている。そのため、sd.cpp を**どの版で・どこから取り・どこに置き・どう起動するか**を決める論点が無い。
ここで決める。

0034 と分ける理由:Ollama / VOICEVOX は HTTP で待ち受ける常駐型で、起動と停止の契機・ポートの衝突・起動待ちが論点になる。
sd.cpp は画像 1 枚ごとに起動して終わる CLI で、それらが当てはまらない。片方だけを後から覆せる。

決まっていること(変えない):

- 常駐させない。生成の画像の工程でだけ起動する(論点 0005 / 0036)。
- 引数配列で起動し、シェルを経由しない。タイムアウト・キャンセル・重複起動の排他を持つ(不変条件。S0016_29 ほか)。
- 実行ファイル・モデル・LoRA のパスは同梱物の配置で決まる内部定数で、設定 JSON に持たない(`docs/data-model.md`)。
- 応援発動経路からは起動しない(S0036_26)。

## 決めるべき細目

1. **同梱する版と出所(依存の審査。@.claude/rules/security-rules.md「依存・サプライチェーン」)。**
   stable-diffusion.cpp の Windows 向けの配布物をどの版・どこから取り、どう照合するか(論点 0029 と同じく版を固定し
   sha256 を照合する)。公式の配布物を使うか、自分たちでビルドするか。
2. **どのビルドを同梱するか。** 論点 0005 は「Vulkan で加速、ダメなら CPU」。Vulkan 版 1 つで CPU にも落ちるのか、
   Vulkan 版と CPU 版の 2 つを同梱して切り替えるのか。
3. **Vulkan が使えないときの振る舞い。** 自動で CPU に切り替えるか、失敗として画像なしで終えるか(S0036_10 と同じ扱い)。
   切り替えるなら、何をもって「使えない」と判定するか(起動の失敗 / 終了コード / 時間上限)。
   `docs/integrations.md` に残っている `[要確認]`(Vulkan iGPU → 失敗時 CPU の自動切替)をここで解く。
4. **ビルドへの入れ方と置き場。** 論点 0034 の細目 2(electron-builder の `extraResources`、取得はビルド時のスクリプト、
   リポジトリには入れない)と同じにするか。0034 は 2026-11-11 にこの形で決定済みなので、それに従う。
5. **実行ファイルはあるがモデル重みが無いとき。** 重みは選んだ人だけが取得する(論点 0036)。未取得なら今の
   「組み立てられない → 画像なしで完了」(S0036_10)のままにするか、生成を始める前に知らせるか。
   取得の仕組みそのものは論点 0042。
6. **開発機での確かめ方。** 開発機は WSL2、製品は Windows。WSL2 で sd.cpp を動かす手段を用意するか
   (論点 0023 の compose に足す / Linux 版を別に取る)、Windows 実機(論点 0025)でだけ確かめるか。
7. **1 枚あたりの時間上限。** 今の実装が持つタイムアウトの値を、CPU で 512x768・4 ステップを回す前提で見直すか。
   値そのものは計測(論点 0041)の結果を見て決める。

## 案

細目 2・3 について。

| | 案A: Vulkan 版だけ同梱し、失敗したら画像なしで終える | 案B: Vulkan 版と CPU 版を同梱し、失敗したら CPU 版で作り直す | 案C: CPU 版だけ同梱する |
|---|---|---|---|
| 同梱サイズ | 小 | 中(実行ファイル 2 つ) | 小 |
| iGPU が使える機械 | 速い | 速い | 遅い |
| Vulkan が使えない機械 | 画像が出ない | 遅いが出る | 遅いが出る |
| 決めることの数 | 少 | 多(「使えない」の判定・切り替えの回数) | 最少 |
| 論点 0005 との関係 | 「ダメなら CPU」を満たさない | 満たす | 「Vulkan で加速」を捨てる |

## 確かめたこと(2026-11-11。公式の GitHub Releases)

- 配布元は `leejet/stable-diffusion.cpp`。ライセンスは MIT(同梱時の表記は論点 0043)。
- リリースは `master-<番号>-<コミット>` の形で頻繁に出る。確認時点の最新は `master-1086-465adf3`(2026-11-10)。
- Windows 向けは CPU 版(`win-cpu-x64`、17 MB)と Vulkan 版(`win-vulkan-x64`、28 MB)が別の配布物。
- Linux 向けの CPU 版(Ubuntu x86_64、27 MB)が同じリリースにある。
- Vulkan 版が Vulkan の無い機械で CPU に落ちるか、iGPU でどれだけ速いかは確かめていない(下の判断で不要になった)。

## 現在の考え(決定前の記録)

細目 2・3 は人間の判断で決まった。残りは上の決定案のとおり承認された。

## 決定

人間が承認(2026-11-11)。

1. **CPU 版だけを同梱する。今後も CPU だけ。** Windows 向け CPU 版の実行ファイル 1 つ。Vulkan・GPU 向けの版は同梱せず、
   切り替えも持たない。論点 0005 の「Vulkan で加速、ダメなら CPU」を置き換える。
2. **版と出所。** 公式の GitHub Releases(`leejet/stable-diffusion.cpp`)の配布物を、タグを 1 つ決めて取り、
   sha256 を照合する(一致しなければ同梱しない)。タグは取得スクリプトを書く段の最新を取って固定する。
3. **入れ方。** 論点 0034 と同じ(electron-builder の `extraResources`、取得はビルド時のスクリプト、リポジトリには入れない)。
4. **実行ファイルか重みが無いとき。** 子プロセスを起動せず、今のまま画像なしで生成を完了する(S0036_10)。
   知らせ方と取得への案内は論点 0042。
5. **開発機。** 同じタグの Linux 向け CPU 版を開発機用に取る。
6. **1 枚あたりの時間上限の値は要件に書かない。** 論点 0041 の計測を見て内部定数にする。
7. アプリ終了時に、実行中の sd.cpp を止める。

## 理由

- **CPU 版だけ**:人間の方針。分岐と、開発機(WSL2・CPU 既定)で確かめられない経路を作らない。どの機械でも同じ経路で動く。
  開発用ランタイム(論点 0023)・同梱ランタイム(論点 0034)の CPU 既定とも揃う。
- **公式の配布物を固定**:自分たちでビルド環境を持たずに済む。リリースが頻繁なので、タグと sha256 で固定しないと再現できない。
- **開発機に Linux 版**:配布物が同じリリースにあり、Windows 実機へ配置しなくても画像の工程と計測を回せる。
- **重みが無いときは今のまま**:取得の仕組み(論点 0042)が未決定なので、案内先の無い表示を先に決めない。

## 却下した案

- 案A(Vulkan 版だけ)— Vulkan が使えない機械で画像が出ない。人間の方針(CPU だけ)に反する。
- 案B(Vulkan 版と CPU 版を同梱し、失敗したら CPU)— 「失敗」の判定と切り替えのシナリオが増え、Vulkan の経路は
  Windows 実機でしか確かめられない。人間の方針(CPU だけ)に反する。
- 自分たちでビルドする — Windows 向けのビルド環境を用意して保つ手間に見合う理由が無い。
- Windows 実機だけで確かめる — 確かめるたびに配置が要り、計測も Windows 側で取ることになる。
- 生成を始める前に「画像の重みが無い」と知らせる表示をここで決める — 取得の仕組みが未決定で、案内先が無い。
