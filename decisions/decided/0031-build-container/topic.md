# 論点 0031: ビルド専用コンテナへいつ・どう移すか

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: —**(開発手順であって製品の要件に及ばない。実際に移すときに `DEVELOPMENT.md`・
  `.claude/rules/stack.md`「Commands」・`package.json` の scripts を直す)

## 何を決めるか

論点 0025 で、Windows 実機確認用のビルドは**いまは案A(WSL2 のホストで npm scripts)で行い、
いずれ案B(ビルド専用コンテナ)に移す**と決めた。この論点では、移す時期(何が起きたら移すか)と、
コンテナに何を載せるかを決める。

## 案

| | 案1: Node と electron-builder だけ載せる | 案2: wine も載せて NSIS まで作る |
|---|---|---|
| 固定できるもの | Node 版・ビルド依存 | 同左 + インストーラ作成の環境 |
| 作れる成果物 | `--win --dir`(0025 と同じ) | `--dir` + NSIS インストーラ |
| 論点 0010(配布)への効き | 弱い | 強い(配布インストーラの実装に使える) |
| イメージの重さ | 軽い | 重い(wine 一式) |

## 決めるべき細目

1. **移す合図。** ホストの Node 版の違いでビルドが壊れたとき / 配布インストーラ(論点 0010)の実装に入るとき /
   別の開発機が増えたとき — のどれを合図にするか。
2. **成果物の置き場は 0025 と同じにするか**(Windows の「ドキュメント」配下の `keyCheer`、環境変数で上書き)。
   コンテナから `/mnt/c` をどうマウントするか。
3. **イメージの固定方法。** 論点 0023 と同じくタグ + digest で固定するか。

## 決定

人間が承認(2026-11-11)。

1. **移す合図は、配布インストーラ(論点 0010)の実装に入るとき。** それまでは論点 0025 の案A(WSL2 のホストで npm scripts)のまま。
2. **載せるものは案2。** Node と electron-builder に加えて wine も載せ、NSIS インストーラまで作れるようにする。
3. **成果物の置き場は論点 0025 と同じ**(Windows の「ドキュメント」配下の `keyCheer`、環境変数で上書き)。
4. **イメージはタグ + digest で固定する**(論点 0023 と同じ)。

## 理由

- 配布インストーラを作る段で初めて wine と NSIS が要る。それより前に移しても、得られるのは Node 版の固定だけ。
- 案2 にしておけば、移した時点で配布インストーラの実装にそのまま使える。
- 置き場と固定の方法を既存の決定(0025 / 0023)に揃えると、手順を二重に持たない。

## 却下した案

- 案1(Node と electron-builder だけ載せる)— インストーラを作れず、配布の段でもう一度作り直すことになる。
- ホストの Node 版の違いでビルドが壊れたときを合図にする — 壊れてから移すことになる。その場合は合図を待たずに前倒ししてよい。
- 別の開発機が増えたときを合図にする — 予定が無い。

## 決まらなかったこと(次の論点へ)

- コンテナから Windows 側の置き場をどうマウントするかは、移すときに手順として決める(要件に及ばない)。
