# 論点 0029: 開発用ランタイムで Sarashina をどう用意するか

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: —**(開発機の手順。`package.json` の `services:model` と `DEVELOPMENT.md` を直す。要件には及ばない)

## 何を決めるか

今の `npm run services:model` は `ollama pull gemma2:2b` を実行する。論点 0027 で採ったモデルは
Ollama の公式ライブラリに無く、**公式の重みを取得して `ollama create` で取り込む**必要がある
(手順は 0027 の「GGUF の出所の調査」で実機確認済み)。この手順を開発機でどう再現できる形にするか。

## 案

| | 案A: npm スクリプト + シェルスクリプト | 案B: 手順を DEVELOPMENT.md に書くだけ |
|---|---|---|
| やること | `scripts/` に取得(コミット固定 + sha256 照合)→ コンテナへコピー → Modelfile で `ollama create` を置き、`services:model` から呼ぶ | 人が手で同じ手順を打つ |
| 再現性 | 高い(ハッシュとテンプレートがスクリプトに固定される) | 打ち間違いの余地がある |
| 量 | 中(約 6.7 GB の取得、コンテナの中に curl が無いのでホスト側で取得) | 小 |

## 人間の方針(2026-10-25)

**Gemma は使わない。削除する方針。** 論点 0027 で Sarashina に替えたあと、gemma2:2b を残して
選べるようにはしない。

方針から決まること:`services:model` は gemma2:2b を取得しない。開発機の Ollama のボリュームに
残っている `gemma2:2b` も消す(`ollama rm gemma2:2b`)。論点 0021 / 0026 の baseline の比較にも使わない
(両論点は Sarashina で測る。論点 0027 の決定)。

## 確認事項(解決済み、2026-10-25)

- 取得物の置き場所 → ホストの `~/.cache/keycheer-models/`(環境変数で差し替え可能)に取得し、
  **`ollama create` が成功したら削除する**(人間の判断)。
- gemma2:2b を引き続き取得するか → 取得しない(上の「人間の方針」)。

## 現在の考え

決定済み(2026-10-25 承認)。

## 決定

**案A を採る。** `npm run services:model` から `scripts/` のシェルスクリプトを呼び、次を行う。

1. 公式の `sbintuitions/sarashina2.2-3b-instruct-v0.1` を、コミット
   `4f3626fb1b64b3e97c908e67f27b2d627ba2a999` を指定してホストの `~/.cache/keycheer-models/` に取得する
   (置き場所は環境変数で差し替え可能。コンテナに curl が無いのでホスト側で取る)。
2. 重みの sha256 を Hugging Face の LFS ハッシュと照合し、**一致しなければ取り込まずに止める**。
3. compose の ollama コンテナへコピーし、`ollama create sarashina2.2-3b-instruct --quantize q4_K_M` で
   取り込む。続けて論点 0027 の `TEMPLATE` と stop を書いた Modelfile で作り直す。
4. 取り込みが成功したら、ホストの取得物とコンテナ内のコピーを削除する。
5. gemma2:2b は取得しない。

あわせて `DEVELOPMENT.md`・`.claude/rules/stack.md`「Commands」・`compose.yaml` のコメントの
`gemma2:2b` を直す。

## 理由

- 取得元・ハッシュ・テンプレートをスクリプトに固定でき、手で打つより再現性が高い(不変条件「再現性」)。
- ハッシュが合わないときに止めるのは、出所の審査(論点 0027)を取り込みのたびに効かせるため。
- 取得物を消すのは、取り込み後は Ollama のモデル置き場に量子化済みの 2.1 GB があれば足り、
  6.7 GB を残す理由が無いため(人間の判断)。取り込み直すときは取得し直す。

## 却下した案

- **案B(DEVELOPMENT.md に手順を書くだけ)** — 打ち間違いの余地があり、ハッシュの照合を飛ばせてしまう。
- **取得物を残す案** — 取り込み直しの取得を省けるが、ディスクを 6.7 GB 使い続ける(人間の判断で不採用)。
