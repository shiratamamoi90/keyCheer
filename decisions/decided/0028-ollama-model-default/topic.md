# 論点 0028: `system.ollamaModel` の既定値を変え、保存済みの設定を移行するか

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/data-model.md`**(S0028_01〜06。system.ollamaModel の既定値と移行)

## 何を決めるか

論点 0027 でローカルのテキストモデルを `sarashina2.2-3b-instruct` に決めた。設定の既定値
(`docs/data-model.md` の `"ollamaModel": "gemma2:2b"` / `DEFAULT_SYSTEM_CONFIG`)をどう変えるか。
あわせて、すでに `gemma2:2b` を保存している利用者の設定を書き換えるか。

既定値と移行は入力(保存済みの設定)から結果が一意に決まるので決定的。

## 案

| | 案A: 既定値だけ変える | 案B: 既定値を変え、旧既定値なら移行する | 案C: 何も変えない |
|---|---|---|---|
| 新規の利用者 | sarashina | sarashina | gemma2:2b |
| `gemma2:2b` を保存済みの利用者 | gemma2:2b のまま | sarashina に書き換える | gemma2:2b のまま |
| 利用者が自分で選んだモデル | 変えない | 変えない(旧既定値と一致するときだけ移す) | 変えない |
| 前例 | — | トリガー設定の `migrateLegacyDefaults`(旧既定値だけを移す) | — |

案B の弱点:利用者が**意図して** `gemma2:2b` を選んだのか、既定値のまま放置したのかを区別できない
(トリガー設定の移行と同じ制約)。

## 人間の方針(2026-10-25)

**Gemma は使わない。削除する方針。** 論点 0027 で Sarashina に替えたあと、gemma2:2b を残して
選べるようにはしない。

方針から決まること:

- 案C(何も変えない)は取れない。
- 案B の弱点(意図して gemma2:2b を選んだ人と区別できない)は問題にならない。gemma2:2b は
  サポートしないので、**保存値が `gemma2:2b` なら無条件で移す**。それ以外の値(利用者が自分で
  入れた別のモデル)は変えない。
- 案A(既定値だけ変える)は、保存済みの利用者が使えないモデルを指したまま残るので取れない。

## 確認事項(解決済み、2026-10-25)

- **Ollama 上のモデル名** → `sarashina2.2-3b-instruct`(人間の判断:論点 0027 で取り込んだ名前のまま)。
  論点 0029 / 0030 で取り込む側もこの名前を付ける。
- **移行の時期** → 待たない。開発機にはモデルが入っている(確認済み)。配布物はまだ無いので、
  保存済みの設定を持つ利用者の機械は存在しない。モデルが入っていない機械で生成した場合は、
  既存の「Ollama 未起動・モデル不在」と同じく、エラーを出してキャラ作成を完了させない
  (S0016_18。クラッシュしない・別プロバイダーへ切り替えない)。gemma2:2b を pull していない
  今の状態と同じ扱いで、新しい失敗の形は生まない。

## 現在の考え

決定済み(2026-10-25 承認)。

## 決定

**案B を採る。**

1. `system.ollamaModel` の既定値を `"sarashina2.2-3b-instruct"` にする(Ollama 上の名前。論点 0027 で取り込んだ名前のまま)。
2. 保存値が `"gemma2:2b"` のときだけ、読み込み時に無条件で既定値へ移し、保存し直す。
3. それ以外の保存値(利用者が入れた別のモデル)は変えない。移行済みの値も書き換えない。
4. 移行先のモデルが Ollama に無いときは既存の失敗の扱い(S0016_18)に従い、`gemma2:2b` へは戻さない。

反映先:`docs/data-model.md` S0028_01〜06(と設定データの JSON 例の既定値)。

## 理由

- Gemma は使わず削除する方針(人間の判断、2026-10-25)なので、`gemma2:2b` を指したまま残すと
  使えないモデルを指す設定が残る。意図して選んだ人と区別できなくても問題にならない。
- 旧既定値だけを読み込み時に移すのは、トリガー設定の移行(S0015_02)と同じ形で、利用者が自分で
  入れた値を壊さないため。
- 移行の時期を初回セットアップ(論点 0030)まで待たないのは、配布物がまだ無く、保存済みの設定を持つ
  利用者の機械が存在しないため。モデルが無い機械での失敗の形は、今と変わらない。

## 却下した案

- **案A(既定値だけ変える)** — `gemma2:2b` を保存済みの設定が、使えないモデルを指したまま残る。
- **案C(何も変えない)** — Gemma を使わない方針と矛盾する。
- **移行を論点 0030 の後に遅らせる案** — 保存済みの設定を持つ利用者がまだいないので、待つ理由が無い。

## 決まらなかったこと(次の論点へ)

- 移行したことを利用者に通知するか(トリガー設定の S0015_02 は通知する)。配布前は対象の利用者が
  いないので急がない。設定 UI(未実装)の論点と合わせて決める。
