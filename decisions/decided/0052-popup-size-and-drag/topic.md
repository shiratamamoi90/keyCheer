# 論点 0052: キャラの窓 — 絵を半分の大きさにし、絵をつかんで動かせるようにする

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/popup.md`**(S0052_01〜08。あわせて S0017_06・S0036_25 の文言)・**`docs/data-model.md`**(設定項目 popup.customPosition)

## 何を決めるか

Windows 実機で画像の表示を確かめた人間の指摘(2026-11-13):

1. セリフを表示すること(実機では、応援のときに絵は替わるがセリフが出なかった)。
2. キャラの絵をもう少し小さくすること。
3. キャラの窓の場所を動かせるようにすること。

3 は、今の不変条件「クリックも透過する」(S0017_06 / S0036_25)と両立のしかたを決める必要がある。

## 案

| | 案A:絵をつかんでドラッグ | 案B:移動モードの間だけ動かせる |
| --- | --- | --- |
| 動かし方 | 絵の上でだけマウスを受け取り、そのままドラッグ | トレイのメニューで切り替えた間だけドラッグ |
| クリックの透過 | 絵の外は今までどおり通す。**絵の真下のものはクリックできなくなる** | ふだんは窓全体が通す |
| 手数 | 思い立ったときにすぐ動かせる | 切り替えが要る |

大きさは 75% / 60% / 50% を示した。

## 決定

人間の判断(2026-11-13)。

1. **セリフは、絵のすぐ上に出す。** 絵を小さくしても、動かしても出す。窓が画面からはみ出さないようにする。
2. **キャラの絵は半分の大きさ(横 128 × 縦 192 に収める)で描く。** 保存する画像の大きさ(256x384。S0036_15)は変えない。
3. **案A。絵をつかんでドラッグで動かす。** ポインタが絵の上にある間だけ窓がマウスを受け取り、絵の外はクリックを通す。
   フォーカスは奪わない。
4. **動かした位置を覚え、次の起動でもその位置に出す。** 覚えた位置が画面の外になっていたら、既定の位置(画面の右下)に出す。

## 理由

- 絵の真下がクリックできなくなることより、すぐ動かせることを人間が選んだ。邪魔なら動かせばよい。絵を半分にしたので、ふさぐ範囲も小さい。
- 位置を覚えないと、起動のたびに動かし直すことになる。
- 画面の外の位置をそのまま使うと、モニターの構成を変えたあとにキャラが見えなくなる。

## 却下した案

- 案B(移動モード)— 切り替えの手数がかかる。人間が案A を選んだ。
- 75% / 60% の大きさ — 人間が 50% を選んだ。
- `-webkit-app-region: drag` で動かす — フォーカスを受けない窓・クリックを通す窓との組み合わせが不確かなので、
  ポインタの動きを main に伝えて窓を動かす形にする(作り方の話。コードが正本)。

## 決まらなかったこと(次の論点へ)

- **Windows 実機でセリフが出なかった原因は特定できていない。** 開発機の Electron では、同じ画面でセリフが描かれることを確かめた。
  窓を小さくして置き直したあとも出なければ、実機での調査が要る。
- 絵の大きさを設定で変えられるようにするか(今は固定)。
- 表示時間(`popup.duration`)・位置の初期値(`popup.position`)の設定は、まだ画面から変えられない(作業 0002 の範囲)。
