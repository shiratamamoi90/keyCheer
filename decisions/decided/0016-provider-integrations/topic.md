# 論点 0016: 生成プロバイダーの契約と外部送信の扱い

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`**

## 何を決めるか

テキスト / 音声 / 画像の生成手段を差し替え可能にする契約と、外部 API を使う場合の同意・失敗時の扱い。
ローカル実装(論点 0002 / 0003 / 0005)と外部 API(論点 0008)を1つのインターフェースに載せる。

## 案(採らなかったものは却下理由付きで残す)

| | 案A: プロバイダー抽象で差し替える | 案B: ローカル実装に固定する |
|---|---|---|
| 生成物の品質 | 利用者が選べる | ローカルの上限に縛られる |
| プライバシー | 明示同意が要る(設計で担保) | 送信が起こり得ない |
| 実装量 | 契約 + 実装ごとのアダプタ | 少ない |

## 決定

- 生成の呼び出しは**キャラ作成時のみ**。応援発動経路からは呼ばない(論点 0007)。
- 種別ごとに9件(ローカル1 + 外部2)を実装する:テキスト `local-ollama` / `openai` / `anthropic`、
  音声 `local-voicevox` / `openai-tts` / `elevenlabs`、画像 `local-sdcpp` / `openai-dalle` / `stability-ai`。
- **既定はローカル一式**。外部プロバイダーは UI での明示選択 + 同意ダイアログ通過が条件。
- **外部 API 失敗時に自動でローカルへフォールバックしない**(意図しない外部選択・意図しない送信を防ぐ)。
  利用者にエラーを示し、再試行かプロバイダー変更を促す。
- ローカルランタイム未起動は**クラッシュさせず**、キャラ作成を完了させない形で失敗させる。
- 外部送信は監査ログに記録する。API キーは `safeStorage` から読む。

## 理由

品質を優先したい利用者の要求と、プライバシー方針(発動経路は永久に外部送信しない)は、
**送信が起こる場面をキャラ作成時に閉じる**ことで両立できる。
自動フォールバックを禁じるのは、「ローカルのつもりが外部に出ていた / 外部のつもりがローカルだった」を
どちらも起こさないため。

## 却下した案

- 失敗時の自動フォールバック — 送信の有無が利用者から見えなくなるため却下。
- 外部 API を一切許さない — 生成物の品質を理由に見送り(論点 0008)。

## 決まらなかったこと(次の論点へ)

- 生成元プロバイダーの永続化(`character.generatedBy`)の UI 表示は未着手。
