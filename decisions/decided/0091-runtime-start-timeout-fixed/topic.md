# 論点 0091: 同梱ランタイムの起動を待つ上限を、測らずに 120 秒で確定する

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: —**(値は要件に書かない — 論点 0034 決定 5。コードの定数 `RUNTIME_START_TIMEOUT_MS` だけ)

## 何を決めるか

論点 0034 の決定 5 は「起動待ちには時間上限を置く。値は要件に書かず、実装時に CPU で応答し始めるまでを実測して内部定数にする」。
実装では測らずに **120 秒**を仮の値として置いた(`src/main/index.ts` の `RUNTIME_START_TIMEOUT_MS`)。測るか、この値で確定するかを決める。

## 案

| | 案A:測らずに 120 秒で確定する | 案B:Windows の CPU で起動時間を測って決める |
|---|---|---|
| 測るもの | なし | Ollama・VOICEVOX ENGINE が応答し始めるまでの秒数(数回) |
| 手間 | なし | 実機で測るスクリプトを用意し、実行してもらう |
| 今の実機 | 生成まで問題なく動いている(2026-11-27 の確認) | — |

## 現在の考え

エージェントは案Bを推した。人間は測らずに確定することを選んだ(2026-11-27)。

## 決定

**案A。起動を待つ上限は 120 秒で確定する**(人間の決定 2026-11-27)。論点 0034 の決定 5 のうち「実測して」の部分を置き換える(上限を置き、値を要件に書かないことは変えない)。

## 理由

- 人間の判断。実機で生成まで問題なく動いており(2026-11-27)、120 秒で足りないことは起きていない。
- 遅い機械で足りなくなったら、そのときに新しい論点で変える。

## 却下した案

- 案B(実機で測って決める)— 人間が採らなかった。
