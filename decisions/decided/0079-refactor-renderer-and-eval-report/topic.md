# 論点 0079: 画面の書き方をそろえ、計測の報告 HTML をやめる(リファクタリング)

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: —**(振る舞いを変えない作り方の決定。要件は変わらない)

## 何を決めるか

人間の指示(2026-11-25):「リファクタリングをする。共通化や他のファイルに html や css が散らばっているや、ハードコーディングなどファイルやコード量を削減できないか」。
人間が選んだもの:popup の CSS を Tailwind へ / 画面を JSX で書き直す / 名前・接続先の直書きを 1 か所に(論点 0077 / 0078)/ 計測の報告は削除でいい。

## 決定

人間が選んだ(2026-11-25)。2〜3 の細部はエージェントが補い、人間が承認した(2026-11-25)。

1. キャラの窓(`popup.html`)に直書きの CSS を、メインウィンドウと同じ Tailwind の仕組み(`npm run build:css`)に寄せる。HTML に CSS を書かない。
2. 画面は JSX で書く。tsc の変換(`jsx: react`。今と同じく React は窓の読み込みで渡す)を使い、バンドラは足さない。メインウィンドウは画面ごと(キャラクター・切り替え・設定)と共通の部品のファイルに分ける。見た目と振る舞いは変えない。
3. 計測(`src/eval/`)が書き出す報告の HTML(画像を並べて見るページ)をやめる。数値は今までどおり論点の `result.md` に記す。
   **ただし**、画像を並べたページは、人間が絵を見て決めた計測(論点 0041 / 0045 / 0062 / 0063 / 0065 / 0067 の主指標)の材料で、`result.md` には絵は残っていない。
   次に絵を見比べる計測をするときは、その論点で見せ方を決め直す。

## 理由

- 1:同じ窓の見た目を 2 つの書き方で持たない。
- 2:`React.createElement` の入れ子は長く読みにくい。JSX でも出力は同じで、バンドラは要らない。
- 3:人間の判断。報告の HTML は計測のたびに作る使い捨ての物で、決定の記録は `result.md` と論点にある。

## 却下した案

- バンドラ(esbuild など)を入れる — 依存が増える。tsc だけで JSX は変換できる。

## 決まらなかったこと(次の論点へ)
