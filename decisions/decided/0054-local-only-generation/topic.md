# 論点 0054: 生成をローカルだけにし、外部プロバイダーをコードごと削除する

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`・`docs/data-model.md`・`docs/pool-generation.md`・`docs/licenses.md`・`docs/model-weights.md`・`docs/glossary.md`・`docs/overview.md`**(あわせて `.claude/rules/security-rules.md`・`.claude/rules/stack.md`・`.claude/rules/impl-rules.md` のプライバシー方針と不変条件)

## 何を決めるか

人間の指示(2026-11-21):**いったんローカルの生成だけに絞る。プロバイダーは選ばせない。外部プロバイダーは、
同意ダイアログ・API キー・監査ログの仕組みと合わせてコードごと削除する。**

削除すると、決定済みの論点 0008(外部 API プロバイダー)と 0016(プロバイダーの統合)の外部の部分を置き換えることになる。
プライバシー方針(`.claude/rules/security-rules.md`「このプロジェクト固有」・`stack.md`「正」)の
「外部送信はキャラ作成時の明示同意のみ」は「外部送信をしない」になり、方針の文書も直す対象になる。

削除するもの(見込み):

- 外部プロバイダー 6 件(`openai` / `anthropic` / `openai-tts` / `elevenlabs` / `openai-dalle` / `stability-ai`)
- 送信内容を示す同意ダイアログと、同意の状態
- API キーの保存(`safeStorage`)
- 監査ログ `{userData}/audit.log.json`
- 生成画面の「生成に使うプロバイダー」の選択
- 設定の `providers`(テキスト・音声・画像)。ローカルの 3 つに固定する

ローカルだけになっても残すもの:

- テキスト・音声・画像を生成する部分の抽象(`local-ollama` / `local-voicevox` / `local-sdcpp`)。
  テストで偽物に差し替えるのに使う。
- 生成元の記録 `generatedBy`(論点 0022)。値の定義域がローカルの 3 つになる。

## 案

### 1. 保存済みの設定に外部プロバイダーが入っているとき

| | 案A:読み込み時にローカルへ移す | 案B:読み込みでエラーにする |
| --- | --- | --- |
| 利用者から見て | 黙って直る(論点 0028 の移行と同じやり方) | 起動できない、または設定画面でエラーが出る |
| 備考 | 配布前なので、該当する利用者はいまは開発機だけ | — |

### 2. 外部で作ったキャラクター(`generatedBy` が外部の値)

| | 案A:そのまま使える。生成元の値だけ読み込み時に許す | 案B:読み込み時に「作り直しが要る」状態にする |
| --- | --- | --- |
| プール・wav・画像 | 残して使う | 次の生成で作り直す(論点 0038 の作り直し) |

### 3. 前に保存した API キーと監査ログのファイル

| | 案A:起動時に消す | 案B:触らない(読みも書きもしない) |
| --- | --- | --- |
| 備考 | 秘密を残さない | コードが減るぶん単純。ファイルは OS のユーザー領域に残る |

## 人間の判断(2026-11-21)

- 1・2:「今はローカルのデータしかないはず」。外部プロバイダーを選んだ設定・外部で作ったキャラクターは存在しない前提とし、移行の処理を設けない。
- 3:起動時に消す。

## 決定

1. **生成はローカルの 3 つだけで行う。** テキスト `local-ollama`・音声 `local-voicevox`・画像 `local-sdcpp`。
   プロバイダーを選ぶ画面と、設定の `providers`(選択値と同意のフラグ)を持たない。
2. **外部プロバイダー 6 件を、同意ダイアログ・API キーの保存・監査ログと合わせてコードごと削除する。**
   それらを縛っていたシナリオは廃止し、ID は欠番にする(下の「反映先」の一覧)。
3. **プロバイダーの抽象(種別ごとのインターフェース)と、生成元の記録 `generatedBy` は残す。** `generatedBy` の定義域はローカルの 3 つになる。
4. **外部のデータの移行は設けない**(人間の判断 1・2)。
5. **起動時に、前の版が残した API キーのファイル(`{userData}/secrets.json`)と監査ログ(`{userData}/audit.log.json`)を消す**(人間の判断 3)。
   ほかのデータには触らない。
6. プライバシー方針の「外部送信はキャラ作成時の明示同意のみ」は「外部送信をしない」に改める。
   モデルの重みの取得(受け取るだけの通信)の扱いは変えない(論点 0055 で決め直す)。

## 理由

- 人間の方針(2026-11-21):いったんローカルの生成に絞る。外部は UI が未接続のまま(作業 0001 / 0003)で、利用者が外部に到達する経路はアプリに無かった。
- コードを残すと、使われない送信経路と秘密の保存が残り、プライバシー境界の検査(ESLint・テスト)を維持し続ける費用だけがかかる。戻すときは新しい論点で作り直す。
- 抽象を残すのは、テストでプロバイダーを偽物に差し替えるため(S0016_13)。
- API キーは秘密なので、使わなくなったあとも残さない。監査ログは外部送信の記録で、送信が無くなれば意味を持たない。

## 却下した案

- **画面と設定から外すだけでコードを残す** — 人間が「コードごと削除」を選んだ。残すと使われない送信経路が残る。
- **保存済みの外部の設定をローカルへ移す / 読み込みでエラーにする** — 外部のデータが存在しない(人間の判断)ので、処理を書くだけ費用になる。
- **外部で作ったキャラクターを作り直しが要る状態にする** — 同上。
- **前の API キーと監査ログに触らない** — 秘密が OS のユーザー領域に残る。
