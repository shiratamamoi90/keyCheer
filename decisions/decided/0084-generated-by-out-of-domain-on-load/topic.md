# 論点 0084: 読み込んだ生成元に定義域外の値があったときの扱い

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/data-model.md`**

## 何を決めるか

`docs/data-model.md` S0022_10 は「生成元の値はプロバイダー識別子の定義域に従う(定義域外の文字列は不正)」と決めているが、
**設定を読み込んだときに不正な値を見つけたらどうするか**は書いていない。実装は論点 0022 のときの人間の判断で、
「エラーを記録するだけで値は変えない」にしてある(`src/main/store.ts` の `loadCharacters`)。この扱いが docs に無いまま残っていた(CLAUDE.md の宿題)。
起こりうる例:論点 0054 で消した外部プロバイダーの識別子(`openai` など)が、前の版で作ったキャラクターに残っている。

## 案

| | 案A:エラーを記録するだけで値は変えない(今の実装) | 案B:定義域外の種別だけ消して保存し直す | 案C:そのキャラクターを読み込まない |
|---|---|---|---|
| 生成元の用途 | 再生成のときの参照だけ。応援の発動経路は見ない(S0022_08) | 同左 | 同左 |
| 利用者への影響 | なし | なし | キャラクターが一覧から消える |
| 記録が残るか | 残る(何で作ったかの事実は消えない) | 消える | キャラクターごと使えない |
| 実装の変更 | なし | 要る | 要る |

## 現在の考え

案A。シナリオ S0084_01 を足して、今の動きを縛るテストを書く(書いた時点で緑の見込み。見張りとして置く)。

## 決定

**案A。読み込みで定義域外の生成元を見つけたら、エラーを記録するだけで値は変えない**(人間の承認 2026-11-27。論点 0022 のときの人間の判断を docs に写す)。キャラクターは一覧に残る。`docs/data-model.md` S0084_01。

## 理由

- 生成元は再生成のときの参照用で、応援の発動経路は見ない(S0022_08)。不正な値があっても動きは変わらない。
- 消すと「前の版で何を使って作ったか」の事実が失われる。
- 実装の変更が要らない。

## 却下した案

- 案B(定義域外の種別だけ消して保存し直す)— 記録の事実が消える。読み込みで保存し直す副作用も増える。
- 案C(そのキャラクターを読み込まない)— 参照用の値のために、使えるキャラクターが一覧から消える。

## 決まらなかったこと(次の論点へ)

- なし。
