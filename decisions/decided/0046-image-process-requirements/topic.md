# 論点 0046: 画像の作り方の決定(論点 0045)を要件に書き起こす

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`**(S0046_01〜19。あわせて S0036_05・S0036_06・S0040_01 の文言)・**`docs/pool-generation.md`**(S0036_12・S0036_15 の文言)・**`docs/data-model.md`**(画像ファイル)

## 何を決めるか

論点 0045 で、ローカル画像生成の作り方を替えると決めた(白の下地から待機画像を作り、ほかの 2 枚は待機画像を下絵にして描き直す。
背景を抜いて 7 色に減らす)。絵の良し悪しは 0045 が計測で決めたので、ここでは**アプリが満たすべき決定的な振る舞い**を決める。
今の要件(論点 0036)は「3 枚は同じシードで作る」(S0036_06)など、捨てた作り方を前提にしている。
要件を直さないと、テストも実装も今の作り方のまま動かせない。

決めること:

1. **画像タグの出させ方。** 待機画像は見た目(髪・服など)、ほかの 2 枚は表情とポーズだけを出させる。形式の検証と、違反したときの扱い(S0036_05 との関係)。
2. **アプリが足す固定の語**と、人物の語が無いときに足す語。
3. **3 枚の作る順と、待機画像が失敗したときの扱い。** ほかの 2 枚は待機画像が無いと作れない(S0036_09「一部が失敗しても完了」との関係)。
   中断して再開するとき、下絵にする待機画像(後処理の前のもの)を残しておくか。
4. **後処理。** 背景の色の読み方、透明にする範囲、7 色の決め方と当て方。背景が抜けなかった絵・全部抜けた絵をどう扱うか。
5. **減色と縮小の順。** 今は 256x384 に縮小して保存する(S0036_15)。縮小は色を混ぜるので、減色の後に縮小すると 7 色でなくなる
   (0045 の `result.md`「透明になっているかの確認」)。
6. **`local-sdcpp` に渡すもの。** サンプラー・CFG・LoRA・下絵・強さ・ステップ数(今の実装はサンプラーと CFG を渡していない。論点 0041)。
7. **外部の画像プロバイダー(`openai-dalle` / `stability-ai`)の扱い。** 下絵を渡せるかは API ごとに違う。同じ作り方にするか、今のままにするか、
   後処理だけ当てるか。
8. S0036_06 の扱い(置き換えるなら欠番にする。ID は再利用しない)。

## 人間の判断(2026-11-13)

- **5(減色と縮小の順)**:先に 256x384 に縮小し、そのあと背景を抜いて 7 色に減らす。保存される絵は必ず 7 色以下で、半透明の画素を持たない。
- **7(外部の画像プロバイダー)**:今のまま変えない。新しい作り方は `local-sdcpp` だけ。外部は今の要件(3 枚を文字から作る。
  シードを受け付けるものは同じシード)のまま。後処理(背景を抜く・減色)も外部の絵には当てない。

## 決定

上の「人間の判断」2 つと、「案」の表の提案のとおり。シナリオは `docs/integrations.md` の「ローカル画像生成の作り方」(S0046_01〜19)。

- `local-sdcpp` だけを新しい作り方にする。外部の画像プロバイダーは変えない。
- 保存までの順は、縮小 → 背景を透明にする → 7 色以下に減らす。
- 待機画像が作れなければ、画像は 1 枚も保存しない。背景の抜けそこないは失敗にしない。
- 再開のために、縮小前の待機画像を生成が終わるまで残す。
- S0036_06 は ID を変えず、対象を外部(`stability-ai`)に絞った。S0036_05・S0036_12・S0036_15・S0040_01 は文言に参照を足した。

## 理由

- 値と作り方は論点 0045(計測)・0041(ベースモデル)の決定をそのまま要件にした。
- 縮小を先にするのは、縮小が色を混ぜて 7 色の制限を崩すため(0045 の `result.md`「透明になっているかの確認」。7 色が 2549 色になった)。
- 外部を変えないのは、計測がローカルだけで、外部の絵に同じ後処理が通るか分かっていないため。
- 待機画像が無いときに残りを文字から作らないのは、別の人物の絵になり、同じキャラに見えるという狙いを崩すため。
- 縮小前の待機画像を残すのは、保存済みの待機画像(縮小・透明・7 色)を下絵にすると計測と違う絵になるため。
- 抜けそこないを失敗にしないのは、0045 の決定(ひとまず受け入れる)に合わせるため。

## 却下した案

- 原寸で後処理をして、色を混ぜない縮小をする — 7 色は保てるが、線がぎざぎざになりやすい。
- 7 色を厳密に守らない(原寸で減色し、今の縮小のまま)— 保存される絵が 7 色を大きく超える。
- 外部の絵にも後処理を当てる — 外部の絵は背景が 1 色とは限らず、抜けそこないが多くなる見込み(未計測)。
- 待機画像が作れなかったとき、残りの 2 枚を文字から作る — 3 枚が同じキャラに見えなくなる。
- 再開で保存済みの待機画像を下絵にする — 未計測の絵になる。
- 透明の画素が 0% や 100% の絵を失敗にする — 見分けられるのは極端な場合だけで、0045 の「受け入れる」と食い違う。

## 決まらなかったこと(次の論点へ)

- **後処理を縮小の後にしたときの絵は確かめていない。** 実装のあと、実機の絵を見て問題があれば論点を開く。
- 待機画像に不透明の画素が 1 つも無いとき、残りの 2 枚を何色で塗るか(`docs/integrations.md` の `[要確認]`)。
- 外部の画像プロバイダーを新しい作り方に寄せるか(下絵を渡せる API かの調査から)。必要になったら論点を開く。
- 既存のテストのうち S0036_06 は、対象を外部に絞った文言に合わせて見直す(作業単位の中で)。
