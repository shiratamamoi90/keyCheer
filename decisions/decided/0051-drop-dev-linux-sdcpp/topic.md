# 論点 0051: 開発機に Linux 向けの sd.cpp を取る決定(論点 0040 の決定 5)を取り下げる

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: —**(要件 S0040_01〜05 は変わらない。開発機の用意のしかただけの話)

## 何を決めるか

論点 0040 の決定 5 は「同じタグの Linux 向け CPU 版を開発機用に取る。`npm run dev` でも画像の工程を動かせる」とした。
実際には、公式リリースの Linux 向けの配布物は開発機(WSL2)より新しい GLIBC を要求し、そのままでは動かない
(論点 0041・0045 の計測は、専用のコンテナの中で動かした)。決定 5 は満たせていない。どうするかを決める。

## 案

| | 案A:決定 5 を取り下げる | 案B:開発機でもコンテナ経由で動かす | 案C:自分たちで Linux 版をビルドする |
| --- | --- | --- | --- |
| 開発機(Linux)での画像の工程 | 動かない(画像なしで生成が終わる。今までどおり) | 動く | 動く |
| 足すもの | 無し | アプリからコンテナを起動する経路(開発機だけの分岐) | ビルド環境とその保守 |
| 実物の絵の確認 | Windows 実機(`npm run deploy:win`)と、計測ドライバ(コンテナ)で行う | 開発機でできる | 開発機でできる |

## 決定

人間の判断(2026-11-13):**案A。決定 5 を取り下げる。**

同梱するのは Windows 向け CPU 版だけ(`scripts/fetch-sdcpp.sh`)。開発機(Linux)では `local-sdcpp` を組み立てられず、
画像なしで生成が終わる。実物の絵は Windows 実機で確かめる。計測は今までどおり計測用のコンテナで行う(`scripts/fetch-image-eval.sh`)。

## 理由

- 公式の配布物が開発機で動かない。動かすには開発機だけの分岐(案B)かビルド環境(案C)が要り、製品には不要なものが増える。
- 画像の工程の決定的な部分は、偽の子プロセスを使った単体・総合テストで縛れている。開発機で実物が動かなくても、開発は進められる。

## 却下した案

- 案B — 開発機だけの経路が増え、製品と違う動かし方を保守することになる。
- 案C — ビルド環境を持たない方針(論点 0040 の決定 2:公式の配布物を固定する)と合わない。
