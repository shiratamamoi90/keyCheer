# 論点 0026: プロンプトに書式の禁止(Markdown・番号・注記)を指示するか

- **種別: 非決定的**
- **状態: 決定済み**
- **反映先: —**(決めた値は config へ。要件には及ばない)

## 何を決めるか

テキスト生成のプロンプト(`buildSystemPrompt`)に「Markdown の強調・見出し・番号・括弧の注記を
使わず、応援文だけを書く」という指示を足すかどうか。**守られるかはモデル次第で、良し悪しは
混入率でしか測れない**ため、決定的な要件としては書かない(@.claude/rules/experiment-rules.md)。

論点 0024 の人間の方針(2026-10-24)「強調をそもそも生成させない」の **層 2(指示)** に当たる。
層 1(構造化出力)と層 3(強調記号を落とす保険)は決定的なので 0024 が持ち、**本論点はそれを待たない**。

現行のプロンプトは出力形式を何も指示しておらず、さらにバケットキー `{normal_regular_morning}` と
`slow=… / normal=… / fast=…` をそのまま渡している。実測(論点 0024)で返った末尾の `(normal)` は
これを写した可能性が高い。

## 案

| | 案A: directive(指示を足す) | 案B: no_directive(足さない = 現行) |
|---|---|---|
| 強調・注記の混入率 | 下がるはず(仮説) | 現行水準 |
| プロンプト長・レイテンシ | 1〜2 行ぶん伸びる | 現行水準 |
| 文言の質への副作用 | 指示が増えて応援の中身が痩せる可能性 | なし |

## 測り方

- 評価データ: 24 バケット × キャラ 3 種(性格の異なる固定プロフィール)
- モデル: sarashina2.2-3b-instruct(固定。論点 0027 で gemma2:2b から変更、Gemma は使わない方針)、temperature 0.8 固定、seed 42 固定、依存は `package-lock.json` で固定。
  実行環境は論点 0023 の既定(CPU のコンテナ)
- 試行: 各組み合わせ 5 回 = 360 応答
- 指標:
  - **書式混入率**(主指標):**層 3 を通す前**の要素のうち、`**` / `__` / 先頭 `#` / 末尾の括弧注記を含む割合
  - 契約違反率(30 文字超過・空・複数文)
  - 1 バケットあたり生成レイテンシ(ms)
- 比較基準(baseline): 指示を足さない現行プロンプト(`no_directive`)。固定し、改良は別名で追加する。
- **層 1(構造化出力)の有無を揃える。** 0024 が決まる前に測るなら両案とも行分割、決まった後なら
  両案とも構造化出力で測る。混ぜると 2 変数を同時に動かすことになる(1 論点 = 1 変数)。
- 計測コマンド: `npm run eval`

## 中止条件

- 契約違反率が baseline より悪化したら中止し、現行プロンプトに戻す。
- 書式混入率が baseline と有意差なし(指示の効果が無い)なら、層 1・3 に任せて案B を採る。

## 決定

**案B(no_directive)を採る。プロンプトに書式の禁止を指示しない。** `buildSystemPrompt` は現行のまま変えない
(人間が承認 2026-10-31)。書式の混入は論点 0024 の層 1(構造化出力)と層 3(記号の除去)で受ける。

## 理由

- 2026-10-25 の計測(`result.md`)で、指示を足すと書式混入率が 3.7% → 22.9% に悪化した。
  強調 `**` が 0 → 630 要素に増えている。禁止する記号を文言に書いたことで、3B のモデルがその記号を真似たと見られる。
- 30 字超過率(契約違反)も 2.8% → 4.5% に悪化し、中止条件の 2 つに当たった。
  レイテンシも +1.2 秒/バケット増えた。
- 減ったのは末尾の括弧注記(22 → 4)だけで、これは層 3 が既に落としている。

## 却下した案

- 案A: format_directive(指示を足す) — 上の計測で主指標・契約違反率・レイテンシのすべてが悪化した。
- 指示だけで「生成させない」を保証する案 — モデルが守る保証がないため、決定的な線(0024 の層 1・3)の
  代わりにはならない。本論点は**混入率を下げる**ことだけを扱う。

## 決まらなかったこと(次の論点へ)

- 否定の指示ではなく、記号を一切書かない言い回しの指示なら効くか — 必要になったら別の論点として測る(いまは開かない)。
- 論点 0021 の baseline は現行プロンプト(指示なし)のままでよい。

## 現在の考え

**次に測る論点はこれ(0021 より先)。** 計測ドライバ `src/eval/` は論点 0027 で実装済みで、
評価データ(24 バケット × キャラ 3 種 × 5 試行)と主指標(書式混入率 = `hasFormatMarkers`)が
そのまま使える。足りないのは**振る変数をモデル名からプロンプトに切り替える口**だけ。

**案A で足す指示の文言(人間が確定 2026-10-25)**:`buildSystemPrompt` の末尾に 1 行

> 応援の文だけを書き、強調(`**`)・見出し(`#`)・番号・括弧の注記は付けないでください。

- バケットキー `{…}` と `slow=… / normal=… / fast=…` の行は**変えない**(それを変えるのは別の変数。
  末尾の `(normal)` の写しが減るかは、この指示の効果として測る)。
- アプリの `buildSystemPrompt` は**計測中は変えない**。案は eval 側で組み立て、決まってから
  アプリへ反映する(反映は決定後の作業)。

**baseline は同じ実行の中で測り直す。** 論点 0027 の sarashina の値(書式混入 3.7%)は同じ条件だが、
別の実行の値と比べると Ollama の状態差が混ざるため、参考値にとどめる。

**計測済み(2026-10-25、`result.md`)。** 指示を足すと強調 `**` が 0 → 630 要素に増え、
書式混入率は 3.7% → 22.9%、30 字超過率も 2.8% → 4.5% に悪化した。中止条件に当たるので
**案B(指示を足さない = 現行)を推す。**

**決定済み(2026-10-31)。**
