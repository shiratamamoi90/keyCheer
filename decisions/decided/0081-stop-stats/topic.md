# 論点 0081: 統計の記録をやめる(累計カウントだけ残す)

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/key-counter.md`・`docs/data-model.md`・`docs/speed-zone.md`・`docs/popup.md`・`docs/main-window.md`・`docs/glossary.md`・`docs/overview.md`・`README.md`・`DEVELOPMENT.md`・`.claude/rules/impl-rules.md`・`.claude/rules/stack.md`**

## 何を決めるか

人間の判断(2026-11-27):「統計 UI は作らない。そもそも記録をしない」。論点 0080 で応援履歴(`cheerHistory`)の記録をやめたが、
残りの統計も記録をやめる。そのうえで、ほかの機能が統計の何を使っているかを確かめ、残すものと消すものを決める。

| 記録 | 使っているところ | やめたときの影響 |
|---|---|---|
| `stats.totalKeyCount` | **応援の発動判定**。起動のたびにここから累計カウントの続きを数え、通常の応援・節目の応援は累計カウントの倍数で出る(`docs/cheer-trigger.md`)。節目の文の数値もこの累計(S0071_05) | 保存しないと、起動のたびに 0 から数え直す |
| `stats.dailyCounts` | どこからも読んでいない | なし |
| `stats.totalActiveSeconds` / `stats.dailyActiveSeconds` | どこからも読んでいない(S0011_07 で数えて保存するだけ) | なし |
| `getStats()`(IPC `keycheer:get-stats`。S0017_07 の公開 API) | 呼んでいる画面が無い | なし |
| `triggers.activeThresholdSec`(設定画面の「止まったとみなす秒数」。S0070) | **アクティブ秒数を数えるためだけ**に使う(S0011_04〜07)。KPM の窓は 60 秒固定で別(S0011_08) | アクティブ秒数をやめると、**何にも効かない設定**になる |

## 案

### 1. 累計カウント(`totalKeyCount`)

| | 案1A 残す | 案1B 保存しない |
|---|---|---|
| 応援の出方 | 今のまま(再起動をまたいで続きから数える) | 起動のたびに 0 から。節目は「起動してからの回数」になる |
| 保存するもの | 累計カウント 1 つ | 無し |

**人間は 1A を選んだ(2026-11-27)。** 累計カウントは統計ではなく、応援を出すための数として扱う。

### 2. 累計カウントの保存場所

- 2A:今の `stats.totalKeyCount` のまま(移行が要らない。`stats` の中身が累計カウント 1 つになる)。
- 2B:統計ではないので、別の名前の場所(例 `counter.totalKeyCount`)へ移す(起動時に移す処理が要る)。
- 現在の考え:**2A**。名前の据わりは悪いが、データ契約を動かす理由が「名前」だけで、移行の処理とその失敗の扱いが増える。

### 3. 保存済みの統計

- 起動時に `dailyCounts`・`totalActiveSeconds`・`dailyActiveSeconds` を消す(論点 0080 の `cheerHistory` と同じ扱い)。
  累計カウントと設定・キャラクターには触れない。

### 4. アクティブ判定と「止まったとみなす秒数」(`triggers.activeThresholdSec`)

- 4A:**設定ごと消す**。S0011_04〜07(アクティブ判定・アクティブ秒数の累積)を欠番にし、設定画面の欄(S0070)と設定の値・値域の検証を外す。
  保存済みの `triggers.activeThresholdSec` は起動時に消す。
- 4B:設定とアクティブ判定は残す(何にも効かない欄が設定画面に残る)。
- 現在の考え:**4A**。効かない設定を見せると、利用者は変えても何も起きないことに戸惑う。

### 5. `getStats()`

- 消す。S0017_07(preload が公開する API は最小)は、公開する API の一覧が変わる(意味が変わる)ので、
  新しい ID で置き換えて S0017_07 を欠番にする。

### 6. 文書の言葉

- README の「アンインストールで…統計もすべて消える」「打鍵数・速度・統計…は外部に送信しない」、`docs/` の GIVEN に出てくる「統計」は、
  「累計カウント」に直すか外す(ほかのデータに触れない [否定] のシナリオは、累計カウントに置き換えれば意味は変わらない)。

## 決定

人間の決定(2026-11-27):「応援を出すための最低限の記録だけでいい」。

1. **記録するのは累計カウント(`stats.totalKeyCount`)だけ**(案 1A)。応援の発動判定に使い、再起動をまたいで続きから数える。
2. 保存場所は今の `stats.totalKeyCount` のまま(案 2A)。
3. 日ごとの押下数(`dailyCounts`)・アクティブ時間(`totalActiveSeconds` / `dailyActiveSeconds`)は記録しない。保存済みの分は起動時に消す。
4. **止まったとみなす秒数(`triggers.activeThresholdSec`)を設定ごと消す**(案 4A)。アクティブ判定と、設定画面の欄・設定の値・値域の検証を外し、
   保存済みの値は起動時に消す。設定画面の応援の欄は 3 つ(通常の回数・節目の回数・節目を出すか)になる。
5. `getStats()`(IPC `keycheer:get-stats`)を消す。
6. シナリオ:主題が消えるものは欠番(S0011_04〜08・S0012_08)。主題が残るものは ID を保ち、消したものを文言から外す
   (S0015_01・S0017_02・S0017_07・S0017_10・S0070_01・S0070_04・S0071_07・S0071_09・S0071_13・S0071_14・S0080_04)。
   新しいシナリオは `docs/key-counter.md` S0081_01〜02、`docs/data-model.md` S0081_03〜06。用語集から「アクティブ時間」を外した。

## 理由

- 統計 UI は作らず、記録を読む画面も無い。人間の基準は「応援を出すためだけに記録する」で、応援に要るのは累計カウントだけ
  (速度ゾーンの KPM はメモリ上の 60 秒の窓で数え、保存しない)。
- 「止まったとみなす秒数」はアクティブ時間を数えるためだけに使っていた。アクティブ時間をやめると何にも効かない設定になり、
  変えても何も起きない欄を利用者に見せることになる。
- 累計カウントの保存場所を変えると、移行の処理と失敗の扱いが増える。変える理由が名前だけなので見合わない。

## 却下した案

- 案 1B(累計カウントも保存しない)— 起動のたびに 0 から数え直し、節目が「起動してからの回数」に変わる。応援の出方を変える理由が無い。
- 案 2B(累計カウントを `counter.totalKeyCount` などへ移す)— 名前の据わりのためだけに移行の処理が増える。
- 案 4B(秒数の設定とアクティブ判定を残す)— 効かない設定が画面に残る。
- 統計を起動のたびに消す(動いている間だけ記録する)— 読む画面が無いので、記録する理由そのものが無い。
