# 論点 0043: 同梱物・取得物のライセンスと、利用者に示す表記

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/licenses.md`**(S0043_01〜06)・`docs/glossary.md`(用語「クレジット表記」)

## 何を決めるか

論点 0010 は、同梱物のクレジット・規約の同梱を法務の宿題として残した。論点 0034 で VOICEVOX ENGINE を音声モデルごと
同梱する判断になり、論点 0030 / 0040 / 0041 でも同梱物・取得物が増える。手元の開発用ビルドは配布にあたらないが、
**配布インストーラに進む前に**、何をどの条件で配ってよいか、利用者に何を示す必要があるかを決める。

対象(それぞれ、同梱してよいか・再配布の条件・要る表記を確かめる):

| 対象 | 入れ方 | 確かめること |
|---|---|---|
| Ollama の実行ファイル | 同梱(論点 0034) | ライセンスと同梱時の表記 |
| VOICEVOX ENGINE | 同梱(論点 0034) | LGPL v3 と別途ライセンスのどちらで使うか。LGPL の条件を Electron アプリへの同梱で満たす方法 |
| VOICEVOX の音声モデル | ENGINE に同梱(論点 0034)。選べる話者は 四国めたん・春日部つむぎ・雨晴はう・玄野武宏 の 4 つ(論点 0044) | この 4 つの利用規約。クレジット表記(どの画面に・どの文言で)。生成した wav の扱い |
| stable-diffusion.cpp | 同梱(論点 0040) | ライセンスと同梱時の表記 |
| Sarashina(テキストモデル) | 取得(論点 0030。自分たちで量子化した GGUF を Hugging Face に置く) | MIT の LICENSE をどこに置くか。ホストするリポジトリに要る表記 |
| 画像のベースモデル・LCM LoRA | 任意で取得(論点 0041 / 0042) | 候補ごとのライセンス(0041 の計測の前に確かめる) |
| npm の依存(Electron・uiohook-napi ほか) | 同梱 | ライセンス一覧の同梱 |

## 決めるべき細目

1. **表記の置き場。** アプリ内の画面(設定タブなど)に出すか、インストール先にファイルとして置くだけか。
   VOICEVOX の音声のクレジットは、利用者が話者を選ぶ画面や生成物の近くに要るか。
2. **利用者が選んだ話者だけ表記するか、選べる話者 4 つを全部表記するか。**
3. **条件を満たせない対象が出たとき。** 同梱をやめて取得に回すか、対象そのものを外すか(その論点に戻す)。

どの詳細ページにも「アプリに組み込んで再生する利用」を直接定めた条項は無かった。組み込みと再配布を許しているのは

**これはエージェントが規約を読んだ結果で、法的な助言ではない。** 規約は改訂されるので、配布の前に人間が原文を読み直す。

## 決定

人間の指示で決定(2026-11-11)。

1. **VOICEVOX ENGINE は LGPL v3 で使う。別ライセンスは取らない。** ENGINE のコードは改変せず、アプリとは別の実行ファイルとして
   同梱する(アプリに取り込まず、子プロセスとして起動して HTTP で話す。論点 0034)。LGPL v3 の全文と著作権表示を同梱し、
   同梱した版のソースの入手先を示す。利用者が ENGINE を差し替えられる置き方にする(アプリ本体の書庫に入れない)。
   使わない音声モデルを除くこと(論点 0044)は ENGINE のコードの改変にあたらない、と読んでいる。
2. **アプリ内に「ライセンスとクレジット」の表示を置く。** 設定画面から開ける。同梱物・取得物・npm の依存のライセンスと、
   VOICEVOX のクレジット表記を示す。同じ内容のライセンスのファイルをインストール先にも置く。
3. **クレジット表記は、選べる話者 4 つを全部示す**(利用者が選んだ話者だけにしない)。
   「VOICEVOX:四国めたん」「VOICEVOX:春日部つむぎ」「VOICEVOX:雨晴はう」「VOICEVOX:玄野武宏(CV:ガロ)」と、各規約の URL。
4. **話者を選ぶ画面に、その話者のクレジット表記を示す。** 生成した音声をアプリの外で使うときは各話者の規約に従うこと
   (クレジット表記が要ること)を利用者に知らせる。
5. **表示は通信しない。** 規約の URL は文字として示すだけで、アプリが読みに行かない。
6. **MIT のもの(Ollama・stable-diffusion.cpp・Sarashina)は、著作権表示とライセンス文を上の表示とファイルに入れる。**
   Sarashina の GGUF を置く Hugging Face のリポジトリにも LICENSE を置く。
7. **npm の依存のライセンス一覧をビルド時に作って同梱する。**
8. **条件を満たせない対象が出たら、その対象を決めた論点を開き直して外す**(話者なら論点 0044、画像のモデルなら論点 0041)。
9. **配布インストーラを作る前に、人間が各規約の原文を読んで確かめる。** とくに、未読の春日部つむぎの詳細ページと、
   上の 1 の LGPL v3 の満たし方。

## 理由

- 別ライセンスを取らずに済むよう、ENGINE を改変せず別プロセスに保つ。論点 0034 の「子プロセスとして起動する」とそのまま合う。
- 表記をアプリ内に置くのは、四国めたんの規約が「アプリの場合はアプリの紹介画面など」と場所を示しているため。
  インストール先のファイルだけでは利用者の目に触れにくい。
- 4 つ全部を示すのは、4 つとも音声モデルを同梱して配るため。選んだ話者だけにすると、表示の出し分けと
  「話者を変えたのに表記が古い」場面が増える。
- 話者を選ぶ画面にも示すのは、「VOICEVOX 音声モデル 利用規約」が、音声の利用を他者に許諾するときに同じ条件の遵守を
  義務付けるよう求めているため。利用者は生成した wav を手元に持つ。
- 通信しないのは、プライバシー方針(アプリが勝手に外へ繋がない)を保つため。

## 却下した案

- ENGINE の別ライセンスを取得する — LGPL v3 で足りる読みで、費用と交渉が要らない。満たせないと分かったら開き直す。
- 表記をインストール先のファイルだけにする — 四国めたんの規約が示す場所(アプリの紹介画面など)に合わない。
- 利用者が選んだ話者だけを表記する — 同梱しているのは 4 つ全部。出し分けの分だけ誤りが入る。
- 規約の本文をアプリが取得して表示する — 通信が発生する。規約が改訂されても URL は変わりにくい。
