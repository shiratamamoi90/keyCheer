# 論点 0011: キー押下をどう数え、いつセッションを切るか

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/key-counter.md`**

## 何を決めるか

グローバルキーフックから流れてくる生イベントを、応援の発動条件に使える形にどう畳むか。
数え方(何を1カウントとするか)と、「まだ打鍵中か」を切る境界を決めないと、トリガーもKPMも定義できない。
プライバシー方針(キーの種類のみカウント)を破らない範囲で決める。

## 案(採らなかったものは却下理由付きで残す)

| | 案A: 生イベントごとに1カウント | 案B: キーリピートをデバウンスして1カウント |
|---|---|---|
| 実装の単純さ | 単純(uiohook のイベントをそのまま数える) | 押しっぱなしの検出状態を持つ必要がある |
| 体験 | 長押しが多いと数が伸びる | 「打鍵数」の直感に近い |
| 決定性 | 高い(入力列 → 出力が一意) | 閾値の置き方で揺れる |

## 決定

- **生イベントごとに1カウント**とし、キーリピートをデバウンスしない。
- **入力内容・キーシーケンスは保持しない。** 数と時刻だけを持つ。
- **アクティブ判定**:最後の押下から `triggers.activeThresholdSec`(既定 60 秒、値域 5〜600)以内なら
  「入力中」。超えたらセッション終了として当該セッションのカウントを切る(既定値の由来は論点 0006、
  設定可能化は論点 0009)。
- 統計(累計・当日)は別に持ち、セッションの切れ目では消さない。

## 理由

閾値を持つ実装は「どこで切るか」という非決定的な調整を core に持ち込む。
まず一意に決まる数え方で固定し、体験上の不足が出たら別の論点として開く方が、
決定的コアの不変条件(同じ入力 → 同じ出力)を保てる。

## 却下した案

- キーリピートのデバウンス — 閾値が体験由来で決まらず、核の決定性を弱めるため見送り。
  必要になったら新しい論点を開く。
- 除外キー設定(修飾キーを数えない等) — 契約としてスキーマにだけ残し、判定は先送り。

## 決まらなかったこと(次の論点へ)

- 除外キー設定の具体的な判定規則(スキーマのみ確定、挙動は未着手)。
