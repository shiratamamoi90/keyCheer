# 論点 0038: 画面から生成したとき、再開と作り直しをどう分けるか

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/pool-generation.md`・`docs/main-window.md`**
  (S0038_01〜09。確定事項の表の「既にプールがある状態で再生成」の行に、どちらになるかの参照を足した)

## 何を決めるか

`docs/pool-generation.md` には、互いに違うことを求める決めごとが 2 つある。

- 確定事項の表:「既にプールがある状態で再生成 → 全バケットを作り直し、古い wav は削除する」。
  S0036_13 も、画像まで作り直すとしている。
- S0020_06 / S0016_15 / S0036_12:中断した後に再開すると、`complete` のバケットと保存済みの画像は作り直さない。

**どちらの動作を選ぶかを、利用者の操作や保存されている状態からどう決めるかは、docs のどこにも書かれていない。**
生成画面にある操作は「生成」ボタン 1 つだけ。

今の実装は、プールがあれば必ず再開として扱う(論点 0036 の実装で見つかった。CLAUDE.md の「制限」に記載)。
その結果、全部揃ったキャラクターで「生成」を押すとこうなる。

| 工程 | 今の動作 | docs の「再生成」 |
|---|---|---|
| テキスト | 全バケットが `complete` なので 1 文も作り直さない | 全バケットを作り直す |
| 音声 | 毎回消して作り直す(今のプールの文を読み直す) | 作り直す |
| 画像 | 保存済みの画像は作り直さない | 作り直し、前の画像を残さない |

困るのは、**プロフィールを変えた後**(S0032_22 で「生成後に変えた」と判定される状態)。
名前や性格を直して「生成」を押しても、セリフも画像も前のプロフィールのまま残る。
変わるのは話者だけで、それも古いセリフを新しい声で読み直すだけになる。

単体テストは、`resumeFrom` を渡せば再開・渡さなければ作り直し、という形で S0036_12 / 13 を守っている。
緑なのはそのため。画面から呼ぶ経路(IPC がいつ `resumeFrom` を渡すか)を縛るシナリオが無い。

## 案

| | 案A 状態で決める(ボタン 1 つ) | 案B 操作を分ける(ボタン 2 つ) | 案C 画面からは常に作り直す |
|---|---|---|---|
| 決め方 | プールの `completion` に `pending` / `failed` が残っていれば再開する。全部 `complete` なら最初から作り直す | 未完了があるときは「続きから」と「最初から作り直す」の 2 つを出す。全部 `complete` なら「作り直す」だけを出す | 「生成」は常に最初から。再開は無くす |
| 中断後の再開(S0020_06) | 守れる | 守れる | **守れない**。S0020_06 / S0016_15 / S0036_12 を変える新しい論点が要る |
| プロフィールを変えた後 | 全部揃っていれば作り直す。中断した後に直した場合は、古いプロフィールで作った前半が残る | 利用者が「作り直す」を選べる | 作り直す |
| 画面の変更 | 無い(文言だけ。「途中から再開します」はそのまま正しい) | ボタンを 1 つ足し、出し分ける | 中断時の文言「途中から再開します」を直す |
| 誤操作の危険 | 揃ったプールを 1 回押すだけで消す | 「作り直す」を押さない限り消さない | 揃ったプールを 1 回押すだけで消す |
| 書くシナリオ | 少ない(判定 1 本と否定 1 本くらい) | 多い(出し分けと各ボタンの動作) | 少ないが、既存シナリオの書き換えを伴う |

案A・案B のどちらでも、**全部揃ったときは作り直す**点は同じ。違うのは、未完了のときに作り直しを選べるかどうか。

## 現在の考え

案A を推す。

- docs の 2 つの決めごとを両方守れて、どちらに振り分けるかが状態で一意に決まる。
- 画面の変更が要らない。
- 未完了のまま直したい場面は、確認を挟む(下の 1)か、別の論点で手当てできる。

案B のほうが利用者の意図をそのまま取れる。ただし、出し分けのシナリオと UI が増える。

**人間に確認したこと**(下の「決定」の 1〜3 で解消した)

1. 全部揃ったプールを作り直す前に、確認を出すか。48 文・48 本の wav・画像 3 枚を消すので、押し間違いを防げる。
   出すなら main-window にシナリオが要る。
2. 案A では、未完了の判定にテキストの `completion` しか使わない。
   画像だけが欠けた(画像プロバイダーが使えなかった、など)キャラクターで「生成」を押すと、テキストも音声も作り直す。
   これを受け入れるか。受け入れないなら、「欠けた画像だけ作る」を別の論点として切り出す(下)。
3. 中断した後にプロフィールを変えてから再開したら、どうするか。
   前半のバケットは古いプロフィールで作られている。S0032_22 の「変えた」判定が立っていれば作り直しに倒す、という手もある。
   ただし判定の材料(`generatedProfile`)は、部分結果を保存したときの値。

## 決定

**案A**(2026-11-09 人間が承認)。人間に確認した 1〜3 は推奨どおりにする。

- 生成を始めたときに、保存されている状態から再開か作り直しかを決める。生成画面のボタンは 1 つのまま。
  - プールの `completion` に `pending` / `failed` が残っていれば再開する。
  - 全部 `complete` なら、最初から作り直す。
  - プールが無い、または `completion` を読めなければ、最初から作る。
- 1:作り直しになり、しかも読み込めるプールがあるときは、生成を始める前に確認を出す。
  - 取りやめたら何も変えない。
  - 再開のときは確認を出さない。
- 2:画像だけが欠けたキャラクターも、テキストが全部 `complete` なら作り直す。
  - 再開の判定には、テキストの `completion` だけを使う。
  - 「欠けた画像だけ作る」は論点 0039 へ切り出した。
- 3:未完了でも、「生成後にプロフィールを変えた」(S0032_22)と判定されれば作り直す。
  - 比べる元(`generatedProfile`)が無ければ「変えた」と判定しない(S0032_23)ので、再開する。

## 理由

- docs の 2 つの決めごと(「再生成は全部作り直す」と「中断後の再開は終わった分を作り直さない」)を、どちらも書き換えずに守れる。
  どちらになるかが保存されている状態から一意に決まり、シナリオに落とせる。
- 画面にボタンを足さずに済む。中断したときの文言「もう一度実行すると途中から再開します」も、
  プロフィールを変えない限りそのまま正しい。
- 確認(1):揃ったプールは 48 文・48 本の wav・画像 3 枚で、ローカル生成なら作り直しに数十分かかる。
  押し間違い 1 回で失わないようにする。確認を作り直しのときだけに絞るのは、再開では何も消えないため。
- 画像だけの欠け(2):判定にテキスト以外の欠けまで使うと、「全部揃っている」の意味が工程ごとに分かれ、
  シナリオが増える。欠けた画像だけ補う操作は需要が見えてから別に決める。
- プロフィールの変更(3):古いプロフィールで作った前半を残して後半を新しいプロフィールで作ると、
  1 キャラのセリフが 2 人分混ざる。S0036_13 の「前のプロフィールの絵を混ぜない」と同じ理由。

## 却下した案

- 案B(ボタンを 2 つに分ける):利用者の意図をそのまま取れる。ただし、出し分けのシナリオと UI が増える。
  未完了のまま作り直したい主な場面(プロフィールを変えた)は、3 の判定で拾える。
- 案C(画面からは常に作り直す):S0020_06 / S0016_15 / S0036_12 の再開を捨てることになる。
  ローカル生成で途中まで進んだ数十分を、中断のたびに失う。
- 確認を出さない:揃ったプールを 1 回の押し間違いで失う。
- 再開の判定に音声・画像の欠けも使う:上の理由 2 のとおり。

## 決まらなかったこと(次の論点へ)

- 欠けた画像(と wav)だけを補う操作 → 論点 0039(`decisions/undecided/0039-fill-missing-images/`)。
