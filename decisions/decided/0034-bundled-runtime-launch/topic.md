# 論点 0034: Ollama / VOICEVOX ENGINE をビルドに同梱して、アプリから起動する

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/integrations.md`**(「同梱ランタイムの起動と停止」S0034_01〜13)・`docs/glossary.md`(用語「同梱ランタイム」)。
  同梱物の版と出所は本論点に残す

## 何を決めるか

論点 0010 で「ランタイム実行ファイルは同梱、モデル重みは初回セットアップで取得、キャラ作成時のみ子プロセスで
起動して終わったら落とす」と決めたが、**同梱も起動も未実装**。いまの Windows ビルド(論点 0025)は
WSL2 のコンテナ(論点 0023)に `127.0.0.1` で繋いでいる。

人間の方針(2026-10-31):**実行ファイルだけ同梱し、重みは後で**(初回セットアップは論点 0030 で別に進める)。
重みが無い間は、開発機で用意したものを置き場へコピーして確かめる。

ここで決めるのは、同梱するもの・置き場・起動と停止の契機・失敗時の振る舞い。sd.cpp(画像)は対象外で、
論点 0040 で決める(常駐せず画像 1 枚ごとに起動して終わる CLI なので、起動と停止の契機・ポートの衝突が当てはまらない。
画像生成そのものは論点 0036 で実装済み)。細目 2 の「ビルドへの入れ方」は 0040 も同じものに従う。

## 決めるべき細目

1. **同梱する版と出所(依存の審査。@.claude/rules/security-rules.md「依存・サプライチェーン」)。**
   Ollama の Windows 版と VOICEVOX ENGINE の Windows 版を、どの版・どこから取り、どう照合するか
   (論点 0029 と同じく版を固定し sha256 を照合する)。CPU 版か GPU 版か(製品ターゲットは iGPU / CPU)。
2. **ビルドへの入れ方。** electron-builder の `extraResources` に置くか。取得はビルド時のスクリプトで行い、
   リポジトリには入れない(サイズ。`.gitignore` 済みの置き場に落とす)。
3. **起動と停止の契機。** 0010 は「キャラ作成時のみ」だが、保存画面の話者一覧(S0019_05)は VOICEVOX を
   要する。保存画面・生成画面を開いている間だけ起動するか、生成のときだけ起動するか。
   **応援発動経路からは起動しない**(外部依存ゼロの不変条件)。
4. **既に動いているものがあるときの扱い。** 開発機では WSL2 のコンテナが :11434 / :50021 を使っている。
   同じポートに応答があれば起動せずそれを使うか、同梱版を別ポートで起動するか。
5. **起動失敗・途中で落ちたとき。** 今の「未起動ならクラッシュせずフォールバック」(S0019_06 / S0020_03〜04)を
   そのまま使えるか。起動待ちの時間上限。
6. **重みの置き場。** Ollama のモデルディレクトリ(`OLLAMA_MODELS`)をどこにするか(`{userData}` 配下か)。
   開発機の `sarashina2.2-3b-instruct` をそこへコピーする手順。
7. **子プロセスの起動方法。** sd.cpp と同じく引数配列でシェルを経由しない(不変条件)。アプリ終了時に必ず落とす。

## 確認した点(議論の時点では要確認だったもの)

- **VOICEVOX ENGINE の配布物に入っている音声モデルの扱い。** → 初回取得にはせず同梱する(下の決定 8)。
  どこまで同梱するかは論点 0044。
- **VOICEVOX ENGINE のライセンス**(LGPL v3 / 別途ライセンス。0010 の法務の宿題)。→ 論点 0043 に切り出した。
  手元の開発用ビルドは配布にあたらないので、本論点はそこまでを対象にする。
- **サイズ。** Ollama の Windows 版は大きく、配置(`deploy:win`)のたびのコピー時間が延びる。→ 受け入れる(下の理由)。

## 決定

人間が承認(2026-11-11)。

1. **版と出所。** 開発機の compose(論点 0023)と同じ版 — Ollama 0.32.13 / VOICEVOX ENGINE 0.25.2 — の
   Windows 向け **CPU 版**を同梱する。公式の配布物を取り、sha256 を照合する(一致しなければ同梱しない)。
   版を上げるときは compose と同梱物を同時に上げる。
2. **入れ方。** electron-builder の `extraResources` に置く。取得はビルド時のスクリプトで行い、リポジトリには入れない。
3. **起動と停止。** メインウィンドウを表示している間だけ起動する。隠したら止める。
   生成中は、隠しても生成が終わるまで止めない。応援の発動からは起動しない。
4. **既存の応答。** :11434 / :50021 に既に応答があれば、同梱ランタイムを起動せずそれを使う。
   アプリが起動していないものは止めない。
5. **失敗。** 起動の失敗・途中で落ちたときは、今の失敗の扱い(S0019_06 / S0016_18 / S0020_03〜04)に乗せる。
   自動では再起動しない。次にメインウィンドウを表示したとき・生成を始めたときに改めて起動を試みる。
   起動待ちには時間上限を置く。**値は要件に書かず**、実装時に CPU で応答し始めるまでを実測して内部定数にする。
6. **重みの置き場。** Ollama のモデルの置き場は `{userData}` 配下。消す手段は論点 0042。
7. **起動方法。** 引数配列で起動し、シェルを経由しない。127.0.0.1 だけで待ち受ける。アプリ終了時に必ず止める。
8. **VOICEVOX の音声モデル。** 初回取得にはせず、ENGINE と一緒に同梱する
   (論点 0010 の「音声ライブラリは初回取得」を置き換える)。同梱する範囲は論点 0044。
9. **同梱ランタイムが無いとき**(`npm run dev` での開発起動)は起動を試みず、既存の接続先に繋ぐだけにする。
10. 用語「**同梱ランタイム**」を `docs/glossary.md` に登録する。

## 理由

- **版を開発機と揃える**:確かめた版と利用者の版が同じになる。計測(論点 0021 / 0026 / 0027 / 0035)もこの版で取っている。
  CPU 版にしたのは製品ターゲット(iGPU / CPU)と、開発機の既定(CPU)に合わせるため。
- **メインウィンドウの表示中だけ**:保存タブの話者一覧(S0019_05)がすぐ出せ、論点 0010 の「常駐させない」も守れる。
  起動と停止の組み合わせが「表示 / 非表示 / 生成中」の 3 つで済む。
- **既存の応答を使う**:開発機は今のまま WSL2 のコンテナを使え、利用者の機械では同梱ランタイムが起動する。
  接続先のポートを固定のままにできる(`docs/integrations.md` の契約 :11434 / :50021 を変えない)。
- **自動で再起動しない**:再起動の回数・間隔・生成中に落ちたときの続け方を決めずに済み、今の失敗の扱いをそのまま使える。
  生成物は残るので、利用者が生成をやり直せば続きから再開できる(論点 0020 / 0038)。
- **重みを `{userData}` に置く**:アプリを更新しても残り、再取得が要らない。インストール先は書き込めない場合がある。
- **音声モデルを同梱する**:配布物を初回取得用に分けてホストする手間が無くなり、初回セットアップの取得物が減る。
- **サイズとコピー時間は受け入れる**:手元の開発用ビルドの配置が遅くなるだけで、振る舞いには影響しない。

## 却下した案

- 必要になったときだけ起動する(話者一覧の取得時・生成の開始時)— 起動待ちが操作のたびに入り、起動と停止の組み合わせが増える。
- アプリ起動中ずっと動かす — 論点 0010 の「常駐させない」を覆し、常時メモリを使う。
- 同梱ランタイムを常に別ポートで起動する — 開発機にも同梱物が要り、接続先を起動時に決める仕組みが要る。
- 落ちたら自動で再起動する — 決めることとシナリオが増える。今の失敗の扱いで足りる。
- 重みをインストール先に置く — 更新で消えうる。書き込み権限が無い場合がある。
- GPU 対応版を同梱する — 配布物が大きくなり、開発機(CPU 既定)で確かめていない経路が増える。
- 着手時点の最新版を同梱する — これまでの計測と版が変わる。
- 音声モデルを ENGINE から全部抜いて初回取得にする(論点 0010 の当初案)— 配布物の加工とホスト先が要る。
- ライセンスの確認を本論点の中で解く — 0034 と、それを待つ 0040 / 0042 が止まる。論点 0043 に切り出した。

## 決まらなかったこと(次の論点へ)

- 同梱物・取得物のライセンスと表記 → 論点 0043(配布インストーラに進む前に解く)。
- 選べる声を 5 種類に絞り、同梱する音声モデルを減らす → 論点 0044。
- sd.cpp の同梱と起動 → 論点 0040。
- 重みを消す手段、必須 / 任意の取得 → 論点 0042。
- 同梱物の sha256 の値は、取得スクリプトを書く段で公式の配布物から取り、スクリプトに固定する(論点 0029 と同じ)。

## 現在の考え(決定前の記録)

細目 4 は「既に応答があればそれを使う」が開発機と利用者の機械の両方で素直(開発機は今のまま WSL のコンテナを使い、
同梱版は利用者の機械で起動する)。細目 3 は保存・生成画面を開いている間だけ起動するのが 0010 の
「常駐させない」と話者一覧の両方を満たす。
