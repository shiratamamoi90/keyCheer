# 論点 0073: テキストモデルを、インストール中に同梱の Ollama へ取り込む

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/model-weights.md`**(S0073_01〜05)

## 何を決めるか

GGUF(論点 0059)を置いただけでは Ollama から使えない。取り込み(論点 0030 決定 4:Ollama の HTTP API)をいつ行うか(論点 0048 の宿題)。

## 案

| | 案A:生成を始めるとき | 案B:インストール中 |
| --- | --- | --- |
| 最初の生成 | 取り込みの分だけ遅い | 遅くならない |
| インストール | 早い | 取り込みの分だけ長い |

## 決定

人間が選んだ(2026-11-25):**案B**。1 は人間の選択、2〜5 はエージェントが補い、人間が承認した(2026-11-25)。

1. インストール中、重みを置いた後に、補助モード(論点 0072)がテキストモデルを Ollama に取り込む。
2. 取り込み先は同梱の Ollama(論点 0034 と同じ待ち受け先・モデルの置き場 `{userData}/ollama-models`)。:11434 に既に応答があればそれに取り込む(アプリが使う Ollama と同じにするため。論点 0034 決定 4)。
   補助モードが起動した Ollama は、取り込みが終わったら止める。
3. 取り込むのは置き場の GGUF(照合を通ったもの)と、開発機の取り込み(論点 0029)と同じチャットテンプレートと stop。Ollama 上の名前は `sarashina2.2-3b-instruct`。
4. 既に同じ名前で同じ層(GGUF の sha256)のモデルがあれば取り込み直さない(更新のインストール。S0055_06 と同じ考え)。
5. 取り込みに失敗したらインストールを完了しない(重みが揃わないときと同じ扱い。論点 0055 決定 5)。

## 理由

- 案B:最初の生成で待たせない(人間の選択)。
- 2:アプリは既にある Ollama を使うので、取り込みも同じ所にしないとモデルが見つからない。
- 5:取り込めていないと生成が始められない(S0055_08 と同じく入れ直しが要る)。

## 却下した案

- 案A — 最初の生成が取り込みの分だけ遅れる。

## 決まらなかったこと(次の論点へ)

- なし。
