# 論点 0017: 応援ポップアップの表示契約

- **種別: 決定的**
- **状態: 決定済み**
- **反映先: `docs/popup.md`**

## 何を決めるか

応援が発動したときに何を、どれだけの時間、どう出すか。作業の邪魔をしないための制約も含む。

## 決定

- 表示は**キャラ画像 + メッセージ**。音声があれば同時に再生し、無ければ表示のみ。
- 表示時間は一定時間で自動的に閉じる。**表示中に次が発動したら上書きする**(積み上げない)。
- ポップアップは**入力の邪魔をしない**(フォーカスを奪わない・クリックを透過する)。
- renderer は core の内部実装・`providers`・agent の生成系を import しない。型は `core/shared` から取る。

## 理由

常時動くアプリなので、応援そのものが作業を中断させたら本末転倒になる。
また表示経路に生成系が混じると、発動経路の外部依存ゼロ(論点 0007)が import レベルで崩れる。

## 却下した案

- 発動を待ち行列に積む — 打鍵が速いほど遅延して表示がずれるため却下(常に最新を出す)。

## 決まらなかったこと(次の論点へ)

- ウィンドウ生成オプション(クリック透過など)そのものは Electron の I/O グルーで、
  自動テストでは縛れない。実機確認に依存している。
